### 記事本文の導線（2026-08-25 追加）

**節ごとの作品ポスターが Amazon のビデオ内検索へのリンクになっている。**
それまで記事本文の Amazon 導線は末尾の1本だけで、
最後まで読まれないと1回も現れなかった。いまは節の数だけ現れる
（実測: 記事1本あたり4〜8節）。

| | |
|---|---|
| 生成 | `site/scripts/posters.mjs` の `posterLink()` |
| 出力 | `[![作品名（年）](/sections/posters/….webp)](https://www.amazon.co.jp/s?k=…&i=instant-video)` |
| ID付与 | ビルド時に `plugins/rehype-affiliate.ts`（記事には焼き込まない） |

**なぜ Amazon 固定なのか。** 対象4社のうち提携できるのが Amazon だけだから
（Netflix は提携先が無い、Disney+ はクローズド、Apple TV+ は招待制）。
サービスを問わず全作品に出せる。

> **2026-08-28: ポスターが無い作品も導線になった。**
> U-NEXT 由来の作品には画像が付いてこないため、それまで U-NEXT の記事は
> 全節が「文字だけのカード」で、**節の画像が1つもリンクになっていなかった**。
> いまは**生成ポスター**（自前で描く絵）が同じ形で入るので、
> 記事1本あたり4〜8節すべてが Amazon への導線になる。
> 実装は `site/scripts/make-sections.mjs`、方針は
> [APPEARANCE.md 10・14節](./APPEARANCE.md#10-本文中のセクション画像)。

> **U-NEXT の提携が通ったら**、`posterLink()` の戻り値を
> `https://video.unext.jp/freeword?query=…` に替えるだけでよい。
> LinkSwitch がブラウザ側で自動変換するので、記事にIDを埋める必要は無い。
> 記事の再生成（`npm run sections -- --write`）だけは要る。
> **どちらを出すかは単価と成約率で決めること。** 両方を並べるのは避ける
> （選択肢を増やすと読者が選べなくなる。5節の方針と同じ）。

### 表の作品リンク（2026-08-25 追加）

**記事と常設ページの表で、作品名がそのままリンクになっている。**
それまで表は文字だけで、記事に載せた作品のうち読者がクリックできるのは
17%（391作品中65本）しかなかった。いまはサイト全体で 1,249本になっている。

| | |
|---|---|
| 送り先の決定 | `site/src/lib/work-links.ts` の `resolveUrl()`（**方針はここ1か所**） |
| 記事側 | `site/plugins/rehype-work-links.ts` がビルド時に表のセルを `<a>` で包む |
| 常設ページ側 | `site/src/components/WorkTable.astro` |
| ID付与 | 記事は `rehype-affiliate`、常設ページは `WorkTable` が直接 |

**送り先は検索結果ではなく「作品ページ」を第一候補にする。**
収集データの `work.link` に、そのサービス上の作品ページURLが入っている
（実測 1,849件中1,671件・90%。U-NEXT は723件すべて）。
検索へ渡すより1クリック短い。

| 直リンクの形 | 扱い | 理由 |
|---|---|---|
| `www.amazon.co.jp/gp/video/detail/…` | **そのまま使う** | `tag=` が乗る。直行と成果を両立できる唯一の形 |
| `app.primevideo.com/detail?gti=…` | **Amazon検索に落とす** | 作品ページではあるが **`tag=` が乗らない＝成果が出ない** |
| `www.netflix.com` / `www.disneyplus.com` / `tv.apple.com` | そのまま使う | 提携先が無いので収益にはならないが、読者には最短 |
| `video.unext.jp/title/…` | そのまま使う | LinkSwitch が変換する（**U-NEXT と未提携なので現時点では0円**。3-3） |
| 直リンクが無い / 配信終了済み(`removed`) | Amazon検索に落とす | 終了した作品の作品ページへ送ると読者の期待とずれる |

> **リンクを増やしすぎない。** Amazonアソシエイトは「サイトの主目的が
> アフィリエイトリンク」だと審査で落ちる。**地の文の比率は変えないこと。**
> リンクを足してよいのは表とポスターまで、と決めてある。

> **トラッキングIDは枠ごとに分けられる（2026-09-03 実装）。** 下の 1-2。

### 1-2. 枠別のトラッキングID（2026-09-03 追加）

**サイト内のAmazon導線は6種類ある。IDが1本だと、アソシエイトのレポートは
その合計しか返さない。** どの導線が効いているのか分からないまま
導線を増やすか減らすかを決めることになる。**出し分けの前に、まず分けて測る。**

| 枠 | 環境変数 | どこに出るか | 実測本数 |
|---|---|---|---|
| `poster` | `PUBLIC_AMAZON_TAG_POSTER` | 記事本文の節ごとの作品ポスター | 157 |
| `table` | `PUBLIC_AMAZON_TAG_TABLE` | 表の作品リンク（記事・常設ページ共通） | 1,102 |
| `cta` | `PUBLIC_AMAZON_TAG_CTA` | 記事末尾・常設ページのCTA（`AmazonCta`） | 687 |
| `rail` | `PUBLIC_AMAZON_TAG_RAIL` | 右の追従枠のPR（**1200px以上のみ**） | 711 |
| `bar` | `PUBLIC_AMAZON_TAG_BAR` | 画面下の追従枠（**1200px未満のみ**） | 687 |
| `work` | `PUBLIC_AMAZON_TAG_WORK` | 作品ページ `/works/<ID>` の各リンク | 482 |
| `body` | `PUBLIC_AMAZON_TAG_BODY` | 本文のその他のリンク | **0** |

> 本数は 2026-09-03 の全711ページ実測（`bar` だけ 2026-09-05 の全721ページ実測）。
> `body` が0本なのは、**記事本文のAmazonリンクがすべてポスターか表から出ている**ため。
> 地の文に直接Amazonリンクを書いていない、という設計がそのまま出ている。

> ★ **`rail` と `bar` は同時には出ない。** 同じページの同じ主題を、
>   画面幅で出し分けたもの（1200px 以上なら右、未満なら下）。
>   分けてあるので「PCとスマホのどちらで押されているか」が読める。下の 6節 Phase D-2。

**未設定の枠は既定ID（`PUBLIC_AMAZON_TAG`）に落ちる。**
だから1つ作って1つ足す、という進め方でよい。

> ★ **アソシエイト・セントラルで実際に作成したIDだけを書くこと。**
> 未登録のトラッキングIDで発生した紹介料は計上されない。
> ここは「作ったIDを書き写す場所」であって、命名を先に決める場所ではない。

| | |
|---|---|
| 枠の種類 | `site/src/lib/affiliate.ts` の `AMAZON_SLOTS` / `tagFor()` |
| .astro 側の解決 | `site/src/config.ts` の `AMAZON_TAGS` / `amazonTagFor()` |
| 記事本文側の解決 | `site/plugins/rehype-affiliate.ts` の `slotOf()` |
| 環境変数の読み込み | **2か所**（`config.ts` と `astro.config.mjs`）。**片方だけ直さないこと** |

**記事本文の枠は、HTMLの形から判定している**（`slotOf()`）。

- `class="work-link"` → `table`（付けているのは `rehype-work-links.ts`）
- 中身が `/sections/…` の画像 → `poster`（作っているのは `posters.mjs`）
- それ以外 → `body`

目印のクラス名や画像の置き場を変えたら、**`slotOf()` も必ず追うこと。**
間違えてもリンクは壊れないが、レポートが混ざって分離の意味が消える。

### 1-3. ページ別の検索語（2026-09-03 追加）

**CTA（`AmazonCta`）と右の追従枠（`FollowRail`）は、
ページに関係なく Prime Video の売り場トップへ送っていた。**
節ポスターも表も作品名を渡しているのに、**画面上いちばん長く見えている追従枠**が
「とりあえずAmazonへ」で、読者から見れば中身の無い入口だった。

いまは、そのページの主題が分かれば**主題で検索させる**。
判断は `site/src/lib/page-intent.ts` の1か所。

| 優先 | 根拠 | 適用範囲 |
|---|---|---|
| 1 | **Search Console の実測クエリ** | `data/search-queries.json` があるページ |
| 2 | シリーズ記事の主題（タイトルの「」の中） | シリーズ記事 4本 |
| 3 | 決めない → 従来どおり売り場トップ | 残り |

> **2 をシリーズ記事に限っているのは意図的。**
> 月次の一覧記事は主題が80個あり、最初の1本を主題として選ぶ根拠が無い。
> 実際に本文の先頭に来るのは「終了日がいちばん早い作品」で、
> 記事の見どころ（タイトルの `｜` の後ろ）とは別物だった（実測）。
> 一覧記事は 1 が付くのを待つ。

> ★ **1 を無条件には使わない。** 検索語は「u-next 配信終了 9月」のような
> 意図語の並びであることが多く、そのまま Amazon 検索へ渡すと0件になる。
> **当サイトの台帳に実在する作品名を含む検索語だけ**を採用する
> （`workTitleIn()`）。ここが緩いと、読者を空の検索結果に送ることになる。

**検索語の取り込みは `npm run queries`**（`pipeline/cli/queries.ts`）。

```bash
npm run queries                # 直近28日ぶん → data/search-queries.json
npm run queries -- --dry-run   # 取得して表示するだけ
```

`.env` に2つ要る。**未設定なら何もしない**（サイトは 2→3 に落ちるだけ）。

```bash
GSC_SITE_URL=sc-domain:mihoudairader.com
GSC_SERVICE_ACCOUNT=./secrets/gsc.json
```

> ★ **サービスアカウントを作っただけでは読めない。**
> Search Console の**設定 → ユーザーと権限**で、そのサービスアカウントの
> メールアドレス（`…@….iam.gserviceaccount.com`）を追加すること。
> 忘れると 403 になる。手順は `pipeline/cli/queries.ts` の冒頭。

> ★ **公開直後は必ず0件になる。** Search Console は反映に2〜3日かかる。
> 0件のときは既存のファイルを上書きしないので、走らせて損はない。

#### なぜ「訪問者ごと」ではないのか

**検索エンジンは検索語をリファラに渡さない。**
Google も Yahoo! も HTTPS 化以降、ブラウザが渡すのは
`https://www.google.com/` という**オリジンだけ**で、
「いま来たこの人が何で検索したか」は原理的に取れない。
取れるのは **URL単位の統計**だけなので、出し分けはビルド時にページ単位で
焼き込む形にしかならない。

> ★ **リファラを見てサーバ側で中身を変えないこと（クローキングになる）。**
> 全員に同じHTMLを配る。ここはビルド時に1つ決めるだけなので、その心配がない。

## 2. 有効化の手順（人手）

`site/.env` に書くだけ。コードは触らない。

```bash
# Amazonアソシエイト
PUBLIC_AMAZON_TAG=xxxxx-22

# バリューコマース LinkSwitch（VC管理画面 → LinkSwitch → コードを選択 の vc_pid）
PUBLIC_VC_LINKSWITCH_PID=000000000
```

> **2026-09-02 に両方とも設定済み**（`jetbike-22` / `892690936`）。
> ローカルの `site/.env` にだけ入っている。

**Cloudflare Pages の環境変数にも同じものを入れること。**
`.env` はリポジトリに入らない（`site/.gitignore`）ので、
**これを忘れると本番だけタグが出ない**。ビルドは通り、ローカルでは動いているので気づきにくい。
`Workers & Pages → brog-ez1 → Settings → Environment variables` で
**Production / Preview の両方**に入れる。

> **Preview に入れても事故らない。** `*.pages.dev` では LinkSwitch が
> 自分で無効化する（下の 5-6）。Preview にも入れておくと、
> 本番と同じHTMLがプレビューで確認できる。

反映されたかは本番のHTMLで確かめる。

```bash
curl -s https://mihoudairader.com/ | grep -c vcdal.js       # 1 なら出ている
curl -s https://mihoudairader.com/ | grep -o 'pid = "[0-9]*"'  # 892690936
```

### Amazon のトラッキングIDの調べ方

アソシエイト・セントラル → 右上のアカウント名 → **トラッキングIDの管理**。
`xxxxx-22` の形。複数作れるので、このサイト専用のIDを1つ作ると成果を分離して見られる。

### LinkSwitch のブロック設定（2026-09-03 に前提が変わった）

**VCに確認したところ、ブロック設定（LinkSwitch対象外設定）は2種類あった。**

| 種類 | 中身 |
|---|---|
| **既定で提携済みの広告主** | 登録した時点で提携状態になっているもの。**申請していなくても変換される** |
| **自分で提携申請した広告主** | 申請が通ったもの。任意でブロックできる |

**LinkSwitch が変換するのは、この2つのどちらかに入っている広告主だけ。**
裏返すと、**自分から提携申請していない広告主のリンクは変換されない。**

| | サイト内の本数 | 状態 |
|---|---|---|
| **Amazon** | 3,140本 | ✅ **VCで提携申請していない → 変換されない。二重計上は起きない** |
| **U-NEXT** | 1,695本 | ✅ 同上。そもそもVCの広告主一覧に無い（3-3） |
| **DMM** | 1,139本 | ⬜ **既定の提携先に入っていないか確認すること。** 入っていれば変換され、AdSense審査のリスクになる（5-3） |

> 🔺 **「PIDを本番に入れる前に必ずブロック設定」は取り消した。**
> ここには以前「サイト内で最多の Amazon が真っ先に変換され、
> アソシエイトのタグと二重計上になる」と書いてあったが、
> **提携していない広告主はそもそも変換対象にならない**ので、その心配は無かった。
>
> ★ **ただし条件付きで復活する。** VCで Amazon を提携申請したら、
> **その瞬間から**二重計上が始まる（デプロイも設定変更も挟まらない）。
> **VCで新しく広告主に提携申請するときは、必ずこの表に戻ること。**
> これは afb 側で同じ広告主と提携する場合も同じ（11-8）。

> コード側にも `src/lib/affiliate.ts` の `EXCLUDED_HOSTS` があるが、
> **LinkSwitch の変換はVC側で走るので、管理画面の設定が本体**。
> コード側の除外は `rel` の付け方を変えるだけで、変換自体は止められない。

## 3. 提携できるもの・できないもの（2026-08-23 調査）

**対象4社のうち3社は現在提携できない。** これが収益設計の前提。

| サービス | 可否 | ASP | 単価 |
|---|---|---|---|
| **Amazon Prime Video** | ✅ | Amazonアソシエイト（直） | ビデオ購入/レンタルの紹介料 ＋ Prime無料体験 500円/件 |
| Netflix | ❌ **公式プログラムが存在しない** | — | — |

## 5. 落とし穴（同じ穴に落ちないために）

### 5-1. `rel="noreferrer"` を付けてはいけない

ASP と Amazon は**リファラで成果を判定する**。
`noreferrer` を付けると成果が計上されない。`noopener` だけならリファラは送られる。
`src/lib/affiliate.ts` の `relFor()` がこれを分けている。外部リンク一律で
`noopener noreferrer` にしないこと。

### 5-2. LinkSwitch の `vc_pid` は `window` に直接代入する

Astro の `define:vars` はスクリプトを IIFE で包む。
`var vc_pid = ...` と書くと関数スコープに閉じ込められ、
グローバルを読む `vcdal.js` から見えなくなる。
**タグの読み込みだけは成功するので、「入れたのに成果が出ない」という気づきにくい壊れ方をする。**
`LinkSwitch.astro` は `window.vc_pid = pid` と書いてある。変えないこと。

### 5-3. DMM TV は意図的にアフィリエイト対象外

DMM は FANZA と同一基盤のため、**AdSense審査へのリスク**が残る
（[DESIGN.md 3.7](../DESIGN.md) に既出）。単価は最高（afb 1,691円）だが、
AdSense を通すまでアフィリエイト化しない、と 2026-08-23 に判断した。

読者向けの検索リンクとしては有用なので**リンク自体は残している**。
解禁するときは `src/lib/affiliate.ts` の `EXCLUDED_HOSTS` から `tv.dmm.com` を消し、
`AFFILIATE_HOSTS` に移し、VC管理画面のブロック設定も外す。

### 5-4. `markdown.rehypePlugins` は Astro 7 で非推奨

動作はするが、将来のメジャーで削除される予定。移行先は
`markdown.processor` に `@astrojs/markdown-remark` の `unified({ rehypePlugins })` を渡す形。
**Astro を上げてビルドが落ちたらここを疑う。**

> なお、この機能を使うために `@astrojs/markdown-remark` を導入している。
> Astro 7 の既定プロセッサ（Sätteri）は unified ベースではないため、
> プラグインを使うにはこの追加が必須だった。
> **導入前後で出力HTMLを全記事比較し、差分は `&amp;` → `&#x26;`（同じ文字の別表記）
> 1箇所のみであることを確認済み**（2026-08-23）。表示・意味に影響はない。

### 5-5. 広告表記は「冒頭」に置く

景品表示法（2023-10-01施行のステマ規制）は、
**一般消費者が分かりやすい位置**への明記を要求する。
本文を読み進めた先ではなく記事冒頭に置くこと。`AffiliateNotice` は
`posts/[...slug].astro` でタイトル直下に配置してある。下に動かさない。

### 5-6. LinkSwitch は本番ドメイン以外では動かさない（2026-09-02）

バリューコマースに登録してあるのは `mihoudairader.com` **だけ**。
**登録していないドメインにタグを貼るのは規約違反**にあたるし、
`npm run dev` で開いた自分のリンクを踏めば自己クリックにもなる。

`LinkSwitch.astro` は、次のホストでは `vc_pid` を立てない。
`vcdal.js` は `vc_pid` が無ければ何もしないので、読み込みは残してある。

| ホスト | 何が動くか |
|---|---|
| `localhost` / `127.0.0.1` / `[::1]` | ❌ 変換しない（`npm run dev`, `astro preview`） |
| `*.pages.dev` | ❌ 変換しない（Cloudflare Pages のプレビュー配信） |
| それ以外 | ✅ 変換する |

**★ 除外リスト方式にしてある（「本番だけ有効」とは書いていない）。**
ドメインを増やしたときに黙って止まるのが**収益側**になるため。
GAの除外（`BaseLayout.astro`）と同じ形にそろえてあるが、
**倒れる向きを逆にしている**のはこの理由。

### Phase D — 記事の右の追従枠 ✅ 器は実装済み（2026-08-23）

**当初は「表レイアウトの改修とセット」と考えていたが、それは不要だった。**

[競合の実装](https://www.noiat.co.jp/internet/vod_comparison/) を調べたところ、
追従枠は**本文カラムを削らず、余白に浮かせている**（`position:fixed; width:289px`）。
当サイトも本文 `46rem`（736px）中央寄せなので、1200px 画面でも片側 232px の余白があり、
**本文の幅を1mmも変えずに枠を置ける**。表が狭くなる問題は起きない。

実装は `FollowRail.astro` ＋ `global.css` の `.layout`。

```
1200px 未満  → .layout { display: block }   ＝ 枠が消えて1カラム
1200px 以上  → minmax(0,1fr) | 46rem | minmax(0,1fr) の3カラム
                   └ 左の枠（常設ページ一覧）        └ 右の枠（新着記事＋PR）
```

> **2026-08-24 の変更。** 常設ページ一覧を左の枠（`LeftRail.astro`）へ分けた。
> 右の枠は「新着記事＋PR」になり、**PR枠が画面の上のほうに来る**（以前は
> 一覧の下に埋もれていた）。広告面としてはこちらのほうが強い。

- **追従にJSを使わない**。競合はJSで追従させているが、それは本文末で
  フェードアウトさせるため。`position: sticky` なら親グリッド行の高さが
  自然な上限になるので、JSが要らない
- `minmax(0, 1fr)` にしているのは、`1fr` だと枠の min-content 幅で左右の列が広がり
  本文が中央からずれるため
- 中身はいま **Amazon 1枠**。提携できているのがそれだけのため。
  Phase B で U-NEXT が通ったら `FollowRail.astro` の `OFFER` を差し替える。
  **複数を並べない**（競合も1広告主だけ。選択肢を増やすと読者が選べなくなる）

**残っている検討事項**

- 効果測定。記事6本・流入ほぼゼロでは良し悪しが判断できない。記事を増やしてから
- **追従枠に AdSense を入れないこと。** 本文に重ならない配置なら通常は問題ないが、
  追従広告は誤クリック誘発とみなされうる領域。審査を控えている間は
  **追従枠はアフィリエイト専用**にする
- スクロール追従の実挙動は**ブラウザで目視確認していない**（headless Edge が
  スクロール後の描画を撮影できなかった）。1200px 以上で開いて確認すること

### Phase D-2 — 画面下の追従枠（スマホ）✅ 実装済み（2026-09-05）

#### 中身


## 9. 設置の検証（2026-09-02 実測）

**「クリックが1円になるか」ではなく、「24時間クッキーが正しく乗るか」を確かめる。**
Amazonアソシエイトはクリックでは1円も出ない。効くのは
**タグ付きURLで着地させ、そこから24時間以内に買われたとき**。
つまり検証すべきことは1つだけ ——
**読者のブラウザが `tag=jetbike-22` を付けたままAmazonに着地するか**。

### 9-1. 静的な検査（ビルド成果物の全数）

`site/dist` の全711ページ、Amazonリンク3,140本を機械的に数えた結果。

| 見たもの | 結果 |
|---|---|
| `tag=jetbike-22` が付いている | **3,139 / 3,140** |
| 別のIDが混ざっている・二重に付いている | **0** |
| `http://`（平文）になっている | **0** |
| `rel` に `noreferrer` が入っている | **1**（後述。これは正しい） |
| `app.primevideo.com`（タグが乗らない形）の漏れ | **0** |

**唯一の例外は `/privacy` から Amazon のプライバシー規約へ張ったリンク。**
`rel="noopener noreferrer"`・タグ無しで、**アフィリエイトリンクではない**。
規約ページへの参照にタグを付けるほうが誤りなので、この1本はこのままでよい。

残り3,139本はすべて `rel="sponsored noopener"`。
**`noreferrer` が入っていない**のが要点（5-1）。

リンクの内訳は 検索 `/s` が2,393本、`/gp/video/storefront` が736本、作品ページが10本。
検索URLでもタグは有効で、クッキーは同じように乗る。

### 9-2. 実ブラウザでの検査（本番サイト）

静的な検査では**JSがリンクを書き換える可能性**を潰せない。
とくに LinkSwitch を入れた後は、**VCがAmazonリンクを横取りしていないか**が焦点になる。
Edge を実際に起動して本番を開き、クリックまで再現した。

| 見たもの | 結果 |
|---|---|
| `window.vc_pid` | `892690936`（立っている） |
| JS実行後の `href` | `…&i=instant-video&tag=jetbike-22`（**書き換えられていない**） |
| クリックで要求されたURL | `https://www.amazon.co.jp/s?…&tag=jetbike-22` |
| VC経由（`valuecommerce.com`）に化けたか | **いいえ** |
| `onclick` の差し込み | 無し |

## 11. afb での設置（2026-09-03 調査）

**afb の審査が通り、U-NEXT / Hulu / Disney+ と提携できる状態になった。**
3-1 と 3-3 で「全ASPでクローズド」「VCの一覧に無い」と書いた状況は、
**afb 側では解消している**（管理画面の実測。情報源より管理画面が正しい、の再確認）。

ここは「では実際にどう貼るか」を調べた結果。

### 11-1. APIキーではリンクを作れない（最初に潰しておく誤解）

**afb が発行するAPIキーで読めるのは成果データだけ。**
仕様書のエンドポイントは `GET /partners/{partner_id}/conversion` の**1本しかない**。
リンクを生成するAPIは afb に存在しない。

| | |
|---|---|
| APIキーでできること | 成果（発生・承認・却下）と報酬額を**読む** |
| APIキーでできないこと | リンクを作る・提携する・広告素材を取る |
| リンクの入手経路 | **管理画面から人手でコピーする**（11-2） |

つまりAPIキーは「収益を測る」側の道具で、「設置」とは別の話。
測る側は `npm run afb` として実装済み（11-9）。

### 11-2. リンクの取り方（管理画面の手順）

1. **提携申請** … ナビの検索窓にサービス名を入れる、または「広告・提携管理」から
   カテゴリで探し、プロモーションの「提携申請」を押す
2. **提携完了を待つ** … 即時提携と審査ありがある
3. **広告原稿取得** … 「広告・提携管理」→「広告原稿取得」→ プロモーションを選ぶ →
   素材を選ぶ → **「広告原稿（リンクコード）取得」**
4. 出てきたコードをコピーする

素材は4種類ある。**リンク先を自分で決められるのは「商品リンク」だけ。**

| 素材 | リンク先 |
|---|---|
| バナー原稿 | 広告主が指定したLP固定 |
| テキスト原稿 | 同上 |
| メール原稿 | 同上（メルマガ用） |
| **商品リンク** | **自分で指定できる。ただし該当プロモーションのドメイン内のみ** |

リンクコードの形はこれ。

```html
<a href="https://t.afi-b.com/visit.php?guid=ON&a=XXXX-XXX&p=XXX" rel="nofollow">
```

> ★ `a` と `p` は afb が発行する値。**手で組み立てないこと。**
> ★ **成果データAPIの `partner_id` はこれとは別物**（ログインに使うパートナーID）。
>   リンクコードの `p=` はパートナーサイトIDで、役割が違う。

### 11-3. リンクコードは勝手に改変できない（当サイトに直接効く）

afb が明示的に認めている改変は**3つだけ**。

- `target="_blank"` を外す
- `rel="noopener"` を足す
- `rel="nofollow"` を `rel="sponsored"` に替える

当サイトの `plugins/rehype-affiliate.ts` は rel を**上書きし**、`target="_blank"` を付ける。
afb のリンクに対して出るのは `rel="sponsored noopener"` `target="_blank"` なので、
**認められている範囲に収まる**（意図せず外れていたわけではないが、
rel の方針を変えるときはここが制約になる）。

> 🔴 **`t.afi-b.com` を `AFFILIATE_HOSTS` に入れないと `noreferrer` が付く。**
> `relFor()` は知らない外部ホストに `noopener noreferrer` を返す。
> afb はリンク元ページをリファラで見ているので、noreferrer が付くと
> **どのページから成果が出たか分からなくなる**（成果は立つが `ref` が死ぬ）。
> **2026-09-03 に `src/lib/affiliate.ts` へ追加済み。**

### 11-4. 枠ごとに測る（`id1`）

Amazon の枠別トラッキングID（1-2）と同じことが afb でもできる。
**リンクコードの末尾にパラメータを足すだけ。**

```
https://t.afi-b.com/visit.php?guid=ON&a=XXXX-XXX&p=XXX&id1=cta
```

| | |
|---|---|
| 使えるキー | `id1` 〜 `id5`（5つまで。全部使う必要はない） |
| 使える文字 | 半角英数字・`.`・`-`・`_`・`*` のみ。**日本語や `=` `&` `/` は不可** |
| どこに返るか | 成果データの **`keyword` 欄**（管理画面の「キーワード」列） |

**枠名は Amazon 側と揃えること**（`poster` / `table` / `cta` / `rail` / `work` / `body`）。
揃っていれば「同じ枠で Amazon と afb のどちらが効いたか」を並べて読める。
`npm run afb` は `keyword` で集計して出す。

### 11-5. リンク元ページを取る（`vref.js`）

成果データの `ref`（リンク元ページ）は、**何もしないとオリジンだけ**になる。
ブラウザの既定 `strict-origin-when-cross-origin` は
`https://mihoudairader.com/` しか送らないので、711ページのどこで
成果が出たのかが永久に分からない。

afb は2つの方法を案内しているが、**実際にページ単位で取れるのは前者だけ**。

```html
<!-- <head> に置く -->
<script src="https://t.afi-b.com/jslib/vref.js" async></script>
```

中身を読んだ（2026-09-03）。ページ内の `t.afi-b.com` / `track.affiliate-b.com` 宛の
`<a>` を探して、**`v_ref=<現在のページURL>` を付け足す**だけのスクリプト。
リファラに頼らないので Referrer-Policy の影響を受けない。

> ★ afb がもう一つ案内している `<meta name="referrer" content="origin-when-cross-origin">`
>   は**これ単体では足りない**。`origin-when-cross-origin` もクロスオリジンには
>   オリジンしか送らないので、パスは付かない。ページ単位で見たいなら `vref.js`。

> ★ 入れるのは **afb のリンクを実際に置いてから**。
>   リンクが1本も無いページで外部スクリプトを1本増やすだけになる。

### 12-1. 改訂で変わった2つの前提

| | 何が変わったか | どこに効くか |
|---|---|---|
| **掲載NG権利元・作品** | TBS作品・TBSオンデマンド / 日テレ作品 / FOD / HBO・HBO Max、および名指しの37作品を**アフィリエイト広告で扱うこと**が禁止された | **当サイトの構造に直撃する。** 記事は自動生成で、国内ドラマは毎月入ってくる |
| **LP限定** | 「下記で紹介しているLP以外での成果は却下」（【5】） | **11-6 の分岐が決着した。** 作品別リンクは成果にならない |

#### 掲載NGが当サイトに効く理由

当サイトの U-NEXT 記事は、収集した作品をそのまま終了日順に並べる。
**人が1本ずつ権利元を照合することはできない**（1記事80本・毎月）。
そして違反の代償は重い。

> 提携解除・提携拒否の措置を取らせていただきます。
> また、発生した成果は過去成果も含め**全却下対象**となります。

だから**機械で止める**。止め方は「広告を出さない」であって、
記事から作品を消すことではない。禁じられているのは
**アフィリエイト広告で扱うこと**で、配信終了の事実を書くことではない。

```
掲載NGの作品が載っているページ  →  U-NEXT の広告だけ消える（Amazon の枠は残る）
それ以外のページ                →  今までどおり
```

#### LP限定が 11-6 を決着させた

11-6 は「商品リンクで検索URLを指定できるか」を**最大の分岐**としていた。
通れば U-NEXT / Hulu の検索リンク2,837本が一斉に成果対象になる、と。

**その道は塞がっている。** 管理画面で商品リンクが作れるかどうかに関係なく、
**LP以外で発生した成果は却下される**（【5】）。
`video.unext.jp/freeword?query=…` はLPではない。

| | 11-6 の想定 | 改訂後の結論 |
|---|---|---|
| 作品別の検索リンク | 一斉にアフィリエイト化できるかもしれない | ❌ **できない。成果にならない** |
| 置き場所 | 商品リンク次第 | ✅ **CTAと追従枠・作品ページに絞る**（LPへ送る） |

**これは悪い知らせではない。** 2,837本のリンクを転送ドメイン経由に変える案は、
「1クリックで確認できる」という当サイトの線を薄くする副作用があった（11-6 の★）。
その心配ごと消えた。**読者向けの検索リンクは素のまま残し、
広告は広告として別に置く。** 役割が混ざらない形に落ち着いた。

| 読み切れなかったとき | **同じく書き込まずに落ちる**（`--pages` の指示が出る）。欠けた一覧は「NGなし」と誤判定するので、黙って書かせない |
| 手書きの部分 | 名指しの37作品と権利元の呼び方。**ガイドライン改訂時はここも見る** |

#### 照合は3通りある。**同じ規則で当ててはいけない**

2026-09-04 に2つとも実際に踏んだ失敗で、どちらも「安全側に倒したつもりが逆だった」もの。

| 対象 | 当て方 | なぜ |
|---|---|---|
| 権利元の略称（`TBS` `FOD` `HBO`） | **語の区切り＋大文字小文字を区別** | 記号を落として部分一致にすると、出演者「Răzvan **Fod**or」が FOD 作品として当たった |
| 集めてきた題名（1,748件） | **題名として書かれているときだけ**（かぎ括弧の中 / 表のセル / 行そのもの） | TBSオンデマンドには「秘密」「卒業」「サキ」「C」のような**ふつうの語と同じ題名**が並ぶ。部分一致にすると「この作品の**秘密**は…」に当たり、**記事20本中10本が巻き添え**になった |
| ガイドライン名指しの37作品・権利元の日本語表記 | 記号を落として部分一致（広め） | 数が少なく、どれも紛れにくい語。ここは広く取るのが安全側 |

> **止め過ぎは安全ではない。** 全ページから広告が消えれば、提携が通っても1円も生まれない。
> 「取りこぼすより広く止める」は**紛れにくい語にだけ**通用する考え方だった。

#### 実測: どの記事が止まるか（2026-09-04）

テスト用のリンクコードを入れてビルドし、全711ページで確かめた結果。

|---|---|---|
| 作品ページ | **492** | 517 |

掲載NGに当たって止まったのは36ページ（枠の無い一覧ページ・サイトマップを含む）。

🔴 **止まった記事に `2026-09-leaving-u-next` が入っている。**
9月の U-NEXT 見放題終了記事＝**いま最も検索流入が伸びている記事**で、
原因は表に並んだ **「Ｔシャツが乾くまで ナビ」「君の好きは無敵 ナビ」の2本**（TBSの番宣番組）。
80本のうち2本のために、そのページ全体で広告が出ない。

**これは実装の不具合ではなく、解釈の結果。** 対処は3つある。

**2026-09-04、afb 経由で U-NEXT に解釈を問い合わせた（回答待ち）。**
回答ごとの分岐（このまま止める／緩める／記事の素材から外す）と、
回答を書き残す場所は **12-0** にある。

> 「配信終了の一覧に事実として並べること」が**扱うに当たるか**は書かれていない。
> 当サイトは**当たると解釈して止めている**（安全側）。
> 回答の記録場所と、回答ごとに何を触るかは **12-0**。

### 12-5. 文言の決まり

**U-NEXT は表現そのものを縛る広告主。** だから文言を散らさない。
`site/src/lib/unext-ad.ts` の `COPY` と `TRIAL` と `noticeFor()` が全部で、
コンポーネントにも記事にも書かない。

| ガイドライン | 実装 |
|---|---|
| 【4】「無料で見放題」「全て見放題」「◯万本見放題」 | 文言に持たない。`ad-policy.ts` が記事も公開物も検査する |
| 【4】「期間限定」「今なら」（定常キャンペーンのため） | 同上。**煽り文句をコードに持たない** |
