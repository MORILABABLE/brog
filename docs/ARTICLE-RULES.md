# 記事の軸とタイトルの決まり

作成: 2026-08-27 ／ **同日に実装済み**（タイトルの形と特報は同日中に追補）

**これから作る記事の指針**。既存の記事は作り直さない（4節に棚卸表がある）。

> **記事を書くときに読むのはここではない。**
> 実際の決まりは [`theme-packs/streaming-jp/templates/naming.md`](../theme-packs/streaming-jp/templates/naming.md)
> にあり、記事生成時にプロンプトへそのまま入る。**このファイルはその決まりの根拠。**

- 1節 … 決めたこと（指針そのもの）
- 2節 … その指針を実データに当てて確かめた結果（吟味）
- 3節 … どこに落としたか（テンプレート・コード）
- 4節 … 既存記事は指針に照らすとどうなるか

## 1. 決めたこと

| # | 決めごと |
| --- | --- |
| **A** | 記事は必ず**軸を1本だけ**名乗る。軸は「サービス1社」「ジャンル1つ」「主題1つ（特報）」のどれか |
| **B** | サービス軸の記事に**他社を混ぜない**（配信開始・終了予定・終了済みのすべて） |
| **C** | 横断してよいのは**ジャンル軸と主題軸だけ**。**配信終了はサービス軸だけ**にする（ジャンル別の終了記事は作らない） |
| **D** | U-NEXT は**横断してよい軸の記事以外では他社と混ぜない** |
| **E** | タイトルは `【{年}年{月}月】` で始める。**軸の無いタイトルを作らない**。更新版でも**先頭は変えない** |
| **F** | 同じ月・同じ軸の記事は新しく作らず、**既存の記事を書き直す**（更新版。更新日は本数の直後） |
| **G** | 特報（そのつど人が決めて出す記事）も、**構成・文体・品質ゲートは月次記事と同じ**仕組みに載せる |

### 軸の割り当て

| 記事タイプ | 軸 | 横断 | 更新版 | 状態 |
| --- | --- | --- | --- | --- |
| `arrivals-service` 配信開始 | サービス | ✕ | あり | 実装済 |
| `leaving` 配信終了予定 | サービス | ✕ | あり | 実装済（更新版は 2026-08-27 追加） |
| `ended` 配信終了済み | サービス | ✕ | あり | 実装済（軸と更新版は 2026-08-27 追加） |
| `arrivals` 配信開始 | ジャンル | ○ | あり | 実装済 |
| `special` 特報 | 主題 | ○ | あり | 実装済（2026-08-27 追加。3-5） |
| ~~`leaving-genre`~~ | ジャンル | — | — | **作らないと決めた**（2-2 の追記） |

### この決まりが及ばないもの

- **常設ページ**（`/leaving/netflix` `/arrivals/netflix` `/stats`）。記事ではないので対象外。
  `/stats` はサービス横断だが、これは「定点観測の数字」であって配信情報のまとめではない。
- **記事末尾の「他のサービスで探す」節**。軸は1社のままで、行き先を他社の検索に出しているだけ。
  ★ この節を「横断だから」と削らないこと。**`ended` ではこの節が記事の中心**（`ended.ts` 冒頭）。

## 2. 吟味 — 指針を実データに当てて確かめた

計測はすべて 2026-08-27 時点・収集済み1,849件。
記事タイプが実際に使う絞り込み（`publishable` ／ 対象月 ／ 未終了のみ ／ U-NEXTのポイント専用除外）を
通したうえで数えているので、`npm run write -- --list` の件数と同じ土俵の数字。

> **この節は「直す前に何が見えていたか」の記録。** 2-4〜2-6 で挙げた問題は
> すべて同日に直してある（3節）。**残したのは、同じ穴をもう一度掘らないため。**

### 2-1 「サービス軸が主・ジャンル軸が従」という順序は正しい

ジャンル判定は原語が分からない作品を落とす。**落ちた作品はジャンル記事に一生載らない。**

| 素材 | 総数 | 判定不能 | 割合 |
| --- | --- | --- | --- |
| 配信終了予定 2026-08 | 219 | 34 | 16% |
| 配信終了予定 2026-09 | 81 | 22 | 27% |
| 配信開始 2026-08 | 465 | 101 | 22% |

サービスは100%確実に分かる。**網羅を担えるのはサービス軸だけ**なので、
ジャンル軸に横断を許しても、サービス軸の記事が主であることは動かない。指針Aの並びは実態と合っている。

検索需要の側も同じ向きを向いている。Googleサジェストの実測では
「配信終了予定␣」の候補10件が10件ともサービス名で、ジャンル名は出てこない（`leaving.ts` 冒頭）。

### 2-2 ジャンル軸に横断を許すのは、そうしないと1本も成立しないから

配信終了予定をジャンルでまとめた場合の件数（サービスの内訳つき）。

**2026-08（8/27時点・未終了のみ 219件）**

| ジャンル | 件数 | 内訳 |
| --- | --- | --- |
| アニメ | 55 | Netflix 36 ／ U-NEXT 19 |
| 洋画・海外ドラマ | 72 | U-NEXT 51 ／ Netflix 21 |
| 邦画・国内ドラマ | 58 | **U-NEXT 52** ／ Netflix 6 |

**2026-09（81件）**

| ジャンル | 件数 | 内訳 |
| --- | --- | --- |
| アニメ | 6 | Netflix 6 |
| 洋画・海外ドラマ | 50 | Prime Video 30 ／ Netflix 18 ／ U-NEXT 2 |
| 邦画・国内ドラマ | 3 | Netflix 3 |

読み取れること。

1. **横断しなければ成立しない。** 8月のアニメ55件は、Netflix単独36件・U-NEXT単独19件で、
   片方は記事にならない。9月のアニメ6件・邦画3件は1社に閉じるとさらに割れる。
2. **月によって作れるジャンルが変わる。** 8月は3ジャンルとも成立、9月は洋画だけ。
3. `leaving.ts` に「ジャンル別は成立しなかった（9月 合計65件 → アニメ6/洋画47/邦画3）」と書いてあるが、
   **これは U-NEXT を足す前（2026-08-23）の計測**。U-NEXT が入った今、8月は3ジャンルとも成立している。

> **決定（2026-08-27）: それでもジャンル別の終了記事は作らない。**
> 件数が足りるかどうかとは別の理由による。**読者は「Netflixで何が終わるのか」を探しに来ており**
> （2-1 のサジェスト実測）、ジャンルで束ねた終了記事は、どのサービスの話なのかを
> 読者側で分解できない。配信終了はサービス軸だけにする。
> 上の数字は「作れるかどうか」ではなく「**作らないと決めた対象がどれくらいあったか**」の記録。
>
> 一方**配信開始のジャンル別（`arrivals`）は続ける。** 開始記事の読者は
> 「アニメで何か観たい」という探し方をしており、そこでは横断が読者の利益になる。

### 2-3 U-NEXTの但し書きは、いちばん効かせたい場所では効かない

指針Dの理由は「画像自動付与がシステム化していない」。これは事実として裏が取れる。

- U-NEXT の作品は `posterUrl` を**1件も持たない**（実測 723件すべて）
- 仮に持っていても付けてはいけない。ポスターの再ホスト許諾は配信APIのカタログに対するもので、
  U-NEXT は自前収集なので範囲外（`site/src/lib/work-links.ts` の `NO_POSTER_SERVICES`）
- したがって U-NEXT の行は**必ずジャンル別の汎用画像**になる

問題は、**その汎用画像がいちばん多く出るのが、指針Dが例外として許したジャンル記事**だということ。

| 記事 | U-NEXTの割合 |
| --- | --- |
| 邦画・国内ドラマ の終了記事（2026-08） | 52 / 58 = **90%** |
| 洋画・海外ドラマ の終了記事（2026-08） | 51 / 72 = 71% |

つまり「邦画の終了まとめ」を作ると、表のほぼ全行が汎用画像になる。
**指針として矛盾はしていない**（Dは「他社と混ぜない」を要求しているだけで、画像を揃えろとは言っていない）が、
出来上がる記事の見た目には効くので、次のどちらかを明示的に選んでおく必要がある。

- **(推奨) 汎用画像のまま出す。** そのかわり **「画像が揃わないからAPI側のポスターを流用する」を明確に禁じる**。
  これは許諾の範囲外で、`work-links.ts` が二重に止めている事故（2026-08-27 修正）と同じ穴。
- U-NEXTの比率が高いジャンルは記事にしない。ただし**邦画はほぼ作れなくなる**（8月で90%）。

推奨を採る理由は、汎用画像は見栄えの問題で済むが、ポスターの流用は許諾の問題になるため。
**推奨側を採用し、`naming.md` に「それでよい／ポスターを流用しない」と明記した。**

### 2-4 いま「横断記事が作れてしまう」穴が3つある

指針B/Cを決めても、コードが穴を残していると来月また横断記事が生まれる。

| # | 場所 | 何が起きるか |
| --- | --- | --- |
| 1 | `ended.ts` に `variants` が無い | **軸を名乗っていない。** いまDisney+の1社記事に見えるのは `TARGET_SERVICES = ['disney-plus']` が1社だからで、Apple TV+ を足した瞬間に横断記事になる。スラッグも `2026-08-ended` で軸を含まない |
| 2 | `leaving.ts` の `slug()` に `?? 'all'` が残っている | 総合1本だった頃の名残。`variant` 無しで呼べば `2026-10-leaving-all` が作れる |
| 3 | `arrivals` と `arrivals-service` が**同じスラッグの形**を使っている | どちらも `{月}-arrivals-{キー}`。いまはジャンルキーとサービスキーが被っていないので衝突しないが、名前空間を共有している。`leaving-genre` を足すと `leaving` が同じ状況になる |

### 2-5 更新版を持っていない記事タイプが2つある

指針Fの「同じ月なら書き直す」は、**スラッグが同じなら同じファイルを上書きする**という形ですでに構造的に成立している
（`existingTitles()` も自分自身のスラッグを重複判定から外している）。

ただし「更新版として**書き分ける**」仕組みを持っているのは `arrivals` と `arrivals-service` だけ。

| 記事タイプ | `previousAsOf()` を見ているか | 更新回の固定文言 | 更新回のタイトル規則 |
| --- | --- | --- | --- |
| `arrivals` | ○ | `arrivals-update-lead-first-sentence` | ○ |
| `arrivals-service` | ○ | `arrivals-service-update-lead-first-sentence` | ○ |
| `leaving` | **✕** | **無い** | **無い** |
| `ended` | **✕** | **無い** | **無い** |

いま `leaving` を同じ月に2回書くと、**初回と同じ体裁のまま中身だけ差し替わる**。
読者から見ると「前と同じ記事の本数だけ変わった」状態になり、更新したことが伝わらない。
指針Fを全記事に適用するなら、ここを揃える必要がある。

### 2-6 タイトルは、いま誰も検査していない

`verifyArticle()` がタイトルについて見ているのは**長さだけ**（10字未満でNG・70字超で警告）。
記事タイプ側の `verify()` は `parsed.body` しか受け取っておらず、タイトルを見られない。

実際、既存11本のタイトルの言い回しは揃っていない。

- 「見放題配信が始まった」／「見放題配信開始の」
- 「見放題配信が終了予定の」／「見放題終了する」／「配信終了する」
- 【2026年8月】が付くものと、付かないもの（`2026-08-arrivals-anime` は年月が無い）
- 更新版は【8月26日更新】だけになり、**どの月の記事なのかがタイトルから消える**

指針Eを「守れているか分からない努力目標」で終わらせないために、**機械で検査できる形**に落とす（3-4）。

## 3. どこに落としたか

### 3-1 決まりの本体: `templates/naming.md`（新設）

軸とタイトルは全記事タイプに共通なので、各テンプレートに同じ文を4回書かない。
**1枚にまとめ、記事生成時に4つのプロンプトすべてへそのまま入る**
（`shared.ts` の `namingRules()` が読み、各記事タイプの system プロンプトに差し込む）。

タイトルは**初回も更新版も先頭が同じ**。更新の日付は本数の直後に置く。

    【{年}年{月}月】{軸句}{動詞句}{本数}本{更新}｜{見どころ}

    初回　 【2026年9月】Netflixで見放題配信が終了予定の作品36本｜007シリーズ5作と五等分の花嫁
    更新版 【2026年9月】Netflixで見放題配信が終了予定の作品42本【9月12日更新】｜追加は踊る大捜査線

動詞句は記事タイプごとに固定（`見放題配信が始まった` / `見放題配信が終了予定の` /
`見放題配信が終了した` / 特報は `見放題配信開始`・`見放題配信終了予定`・`見放題配信終了`）。

> **なぜ先頭を固定するか（2026-08-27 に見直した）。**
> 最初は更新版を `【9月12日更新】2026年9月にNetflixで…` の形にしていた。
> しかしそれだと**検索結果の一覧で、どのカテゴリ・どの月の記事なのかが頭から消える。**
> 読者が最初に見るのは先頭の数文字で、更新したかどうかはその次。
> 先頭は版によらず `【{年}年{月}月】` に固定し、更新日は本数の直後・`｜` より前に置く。

### 3-2 各テンプレートに足した節

各テンプレートの冒頭に「## 軸とタイトル」を置き、**自分の軸と動詞句だけ**を書いて
`naming.md` を指すようにした。あわせて、散らばっていたタイトル規則の行を消して寄せた。

| テンプレート | 軸 | 動詞句 |
| --- | --- | --- |
| `arrivals-service.md` | サービス1社 | `見放題配信が始まった` |
| `arrivals.md` | ジャンル1つ（**サービス横断可**） | `見放題配信が始まった` |
| `leaving.md` | サービス1社 | `見放題配信が終了予定の` |
| `ended.md` | サービス1社 | `見放題配信が終了した` |
| `special.md`（新設） | 主題1つ（**サービス横断可**） | `--kind` で3種 |

`leaving.md` と `ended.md` には「## 版（初回と更新版）」を新設した（2-5）。

### 3-3 `fixed-phrases.md`

| 追加したキー | 中身 |
| --- | --- |
| `leaving-update-lead-first-sentence` | 「今回新たに{追加本数}本の終了予定が判明し…」 |
| `ended-update-lead-first-sentence` | 「今回新たに{追加本数}本の終了を確認し…」 |
| `special-new-lead-first-sentence` | 特報（配信開始）のリード1文目 |
| `special-leaving-lead-first-sentence` | 特報（終了予定）のリード1文目 |
| `special-ended-lead-first-sentence` | 特報（終了済み）のリード1文目 |

`{追加本数}` の説明を「サービス別記事の更新回だけ」から「更新版だけ」に広げ、
`{サービス}` に「サービス軸では1社・ジャンル軸では複数」を明記し、`{主題}` を足した。

★ 特報の**リードの締め**は新設していない。`arrivals-lead-closer` /
`leaving-lead-closer` / `ended-lead-closer` を `--kind` で使い分ける。
締めの役割は月次記事とまったく同じで、文言を増やすと**片方だけ直されてずれる**。

### 3-4 コードの直し

| # | ファイル | やったこと |
| --- | --- | --- |
| 1 | `pipeline/core/article.ts` | `ArticleType` に **必須の `axis: 'service' \| 'genre' \| 'topic'`** を追加。軸を名乗らない記事タイプは型が通らない |
| 2 | `article-types/shared.ts` | `titleIssues()` を追加。期間・軸・他社名・略称・動詞句を error、本数・字数・煽りを warn。`namingRules()` / `variantKey()` / `foundSince()` も同ファイル |
| 3 | `pipeline/cli/write.ts` | `type.verifyTitle?.()` を品質ゲートに追加。**これを入れるまでタイトルは長さしか見られていなかった** |
| 4 | `article-types/ended.ts` | サービス別バリアントへ（`--service disney-plus`）。スラッグは `{月}-ended-{キー}`。更新版に対応 |
| 5 | `article-types/leaving.ts` | `slug()` の `?? 'all'` を削除。更新版に対応。ジャンル別の計測コメントを2-2の数字で更新 |
| 6 | `pipeline/cli/write.ts` | `assertUniqueSlugs()` を起動時に実行。スラッグが衝突したらその場で落ちる |
| 7 | `leaving.ts` / `ended.ts` | `previousAsOf()` で初回／更新版を書き分け。今回判明した分は**収集日だけ**で決める（`foundSince`。終了日で判定すると全件が今回分になる） |
| 8 | 新設 `article-types/special.ts` | 特報。3-5 に別記 |
| 9 | ~~`article-types/leaving-genre.ts`~~ | **作らない**（2-2 の決定）。配信終了はサービス軸だけ |

`npm run write -- --list` の見え方の変化:

    （前）ended                        76  作成済   2026-08-ended
    （後）ended --service disney-plus  76  未作成   2026-08-ended-disney-plus

### 3-5 特報（`special`）

**「ユーザーが明示的に作りたい時期・内容」を、テンプレ通りに作れるようにしたもの。**
月次記事が決まった軸で毎月出るのに対して、特報はそのつど人が主題と時期を決めて出す。

    npm run write -- --type special --kind expiring       --topic "「007」シリーズ" --slug 007-netflix --match "007" --month 2026-09 --emit

`/article` に「9月にNetflixで終わる007シリーズの特報」のように渡せば、
コマンド側がこのフラグに翻訳する（`.claude/commands/article.md` の「2b. 特報を書く」）。

| 決めたこと | 理由 |
| --- | --- |
| 軸は**主題**（`axis: 'topic'`）。サービス横断可 | 読者は「あの作品がどこで観られるか」を探して来る。ジャンル軸と同じ理屈 |
| 主題軸は**タイトルにサービス名を出してよい** | 「Netflixで『007』が終了」は主題の記事であって横断まとめではない |
| `--kind` を**必須**にした | 「これから終わる」と「もう終わった」を取り違えた記事は読者を直接裏切る。人に選ばせ、選んだ結果で検査を切り替える |
| カテゴリは `--kind` から決まる（`categoryOf()`） | 同じ記事タイプで開始の特報も終了の特報も書くので、`category` を1つに固定できない |
| `--slug` を**必須**にした | 日本語の主題からURLは作れない。ここだけは人が決める |
| **更新版専用の固定文言は作らなかった** | 特報は「前回から何が増えたか」を追う記事ではない。基準日が入れ替わればいつ時点かは伝わる |
| 危険な言い回しの表を `shared.ts` に移した | 終了済みの月次記事と終了済みの特報は**同じ嘘をつきうる**。写すと片方だけ直される |

CLI 側には**特報という概念を入れていない。** 記事タイプが必要なフラグを
`ArticleType.flags` で宣言し、`write.ts` は名前も必須かどうかも宣言だけを見て渡す
（`variants` と同じ考え方）。値は `--apply` のために下書きへ保存される。
`--list` では「要指示」と出る。

    special                            —  要指示  --kind --topic --slug

## 4. 既存記事は指針に照らすとどうなるか

**作り直さない。** 次に同じ月・同じ軸の記事を書くときに、更新版として自然に直る。

| 記事 | 指針との差 |
| --- | --- |
