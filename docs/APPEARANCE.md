> **全ページの一番上に出していたヘッダーバナーは 2026-08-24 に外した。**

> （`site/src/assets/header-banner.png`）は**残してある**。

**背景（点と地色）は画像ファイルではなく CSS で描いている。** 理由は3つ。

1. サイトはライト/ダーク両対応。画像だと明暗2枚とメディアクエリが必要になる
2. 背景は全ページに乗る。画像だと表示速度（LCP）に直撃し、広告収入にも響く
3. CSS なら数百バイトで済み、`--accent` などの既存の色変数と揃えられる

> **ライトモードでも地は暗い。** 文字は必ず白いカードの中に置くこと。
> カードの外に直接テキストを置くと、`--text`（ほぼ黒）のままで読めなくなる。
> フッターだけは地の上に載るので、専用の明るい色（`--footer-text`）を持たせてある。

## 1. 背景の色と濃さを変える

`site/src/styles/global.css` の先頭にツマミがある。

```css
:root {
  --bg-tint: #1b3a6e;                      /* 地の色 */
  --dot-color: rgba(174, 208, 255, 0.13);  /* 点の色 */
  --dot-gap: 22px;                         /* 点の間隔 */

  --footer-bg: #16305c;                    /* フッターの地。--bg-tint より少し沈める */
  --footer-text: #bccbe4;                  /* フッターの文字 */
  --footer-link: #9dc4ff;                  /* フッターのリンク */
  --footer-border: rgba(255, 255, 255, 0.12);
}
```

**ライトとダークの2箇所にある。必ず両方直すこと。**
片方だけ変えると、もう一方の配色で背景が浮いたり沈んだりする。

| やりたいこと | 直す値 |
|---|---|
| 地をもっと濃くしたい | `--bg-tint` を `#142c55` などに下げる。`--footer-bg` も一段暗い値に合わせる |
| 地を明るくしたい | `--bg-tint` を `#28518f` などに上げる |
| 青みを落として黒に寄せたい | `--bg-tint` を `#1a2430` などに寄せる |
| 淡いブルーに戻したい | `--bg-tint: #eef4fd` ＋ `--dot-color: rgba(31,111,235,0.22)`。**その場合はフッターの色も明るく戻すこと**（[下記](#フッターだけ元の明るい色に戻す)） |
| 点を目立たせたい | `--dot-color` の末尾 `0.13` を `0.20` などに上げる |
| 点をまばらにしたい | `--dot-gap` を `28px` `32px` と広げる |

ダーク側の既定値はこちら。

```css
--bg-tint: #0b1d3a;
--dot-color: rgba(110, 168, 254, 0.14);
--footer-bg: #091728;
```

> **地が暗いので、点は「明るい色」で置いている。** 暗い地に暗い点を置くと何も見えない。
> 地を淡い色に戻すときは、点も暗い色に戻す必要がある。

### フッターだけ元の明るい色に戻す

`site/src/components/Footer.astro` の `footer { }` を戻す。

```css
footer {
  border-top: 1px solid var(--border);
  background: var(--bg-subtle);
  color: var(--text-muted);
}
```

同じファイルの `footer a { color: var(--footer-link); }` を消し、
`nav a { color: var(--footer-text); }` を `var(--text-muted)` に戻す。

## 2. 背景の柄を変える

点を描いているのは `body` のこの1行。

```css
background-image: radial-gradient(var(--dot-color) 1px, transparent 1.3px);
```

差し替え例。`--dot-gap` が `background-size` に効いているので、間隔はそのまま使える。

**細い格子（方眼紙）**

```css
background-image:
  linear-gradient(var(--dot-color) 1px, transparent 1px),
  linear-gradient(90deg, var(--dot-color) 1px, transparent 1px);
```

**斜めのストライプ**

```css
background-image: repeating-linear-gradient(
  45deg,
  var(--dot-color) 0 1px,
  transparent 1px 12px
);
```

もっと凝った柄が欲しいときは **Hero Patterns**（heropatterns.com・CC0）で
色と濃さを決めて CSS をコピーし、この行と差し替える。
`background-size` の指定も一緒に付いてくるので、その場合は `--dot-gap` の行を消す。

## 3. 背景をやめる

`site/src/styles/global.css` の `body` を元に戻す。

```css
body {
  margin: 0;
  background: var(--bg);   /* ← background-color / -image / -size の3行と差し替え */
  color: var(--text);
  font-size: 16px;
  overflow-x: hidden;
}
```

このとき[本文カードもやめる](#4-本文カードを調整するやめる)と、改修前の見た目に完全に戻る。

## 4. 本文カードを調整する／やめる

```css
.content-card {
  margin: 1.6rem auto 0;              /* ヘッダーとの間隔 */
  padding: 0.6rem 1.9rem 2.2rem;      /* カード内側の余白 */
  border-radius: 14px;                /* 角の丸み */
}
```

**狭い画面（47rem 以下）ではカードを全幅に戻している。**
スマホで本文の横幅を削るほうが、背景が見えることより損だという判断。
そのぶん**スマホでは背景の紺がほとんど見えない**（フッター手前の余白だけ）。
この挙動は同じファイルの `@media (max-width: 47rem)` で変えられる。

**カードをやめる**なら `site/src/layouts/BaseLayout.astro` の1行を戻す。

```astro
<main id="main" class="wrap">        <!-- content-card → wrap -->
```

### 左右の枠（1200px 以上だけ）

本文カードの左右の余白に枠を出している。見た目に関わるのは
`global.css` の `.layout` だけ。

```css
.layout { display: block; }          /* 既定。1200px 未満は枠が消えて1カラム */

@media (min-width: 75rem) {
  .layout {
    display: grid;
    grid-template-columns: minmax(0, 1fr) min(var(--max-width), 100%) minmax(0, 1fr);
  }
}
```

**本文の幅（`--max-width`）は枠があってもなくても変わらない。**
左右とも同じ列幅なので本文は中央のままで、余白に枠が載るだけ。
記事は配信終了作品の**表**が主体で横幅を食うため、本文を削るサイドバー方式は採っていない。

#### 左の枠（`LeftRail.astro`）

```
┌──────────────────────┐
│ 最新の配信終了・配信開始一覧 │ ← 見出し（背景の紺の上に直接載る）
│ 自由にタイトルを検索できます  │ ← 補足（.block-note。リンク先の検索窓の案内）
│ [絵] 配信終了予定 Netflix  │
│ [絵] 配信終了予定 Prime… │   常設ページ1つにつき1枚
│ [絵] 新着配信 Netflix     │
│ ⋯                     │
└──────────────────────┘
```

追従しない。本文と一緒に流れる。

> **もとは右の枠の1ブロック目だった**（2026-08-24 に左へ移動）。
> サービスが増えるほど一覧が縦に伸び、その下の新着記事とPR枠が
> 画面外へ押し出されていた。**右に戻さないこと。**

#### 右の枠（`FollowRail.astro`／中身と運用は [AFFILIATE.md](./AFFILIATE.md)）

```
┌──────────────────────┐
│ 新着記事                │ ← カテゴリ横断の最新記事（既定3本）
│ [バッジ] 記事タイトル…     │
├──────────────────────┤
│ PR                    │ ← 広告カード。アフィリエイト有効時のみ。**ここだけ追従**
│ Amazon …              │
└──────────────────────┘
```

**広告とそれ以外を混ぜてはいけない。** まとめて `aria-label="広告"` にすると
新着記事まで広告と称することになり、逆にPR表記を外すと
景品表示法（ステマ規制）に触れる。

カードのバッジは記事カードと同じ `.badge[data-category]` を使っている。

> **並びは全ページで固定。** 以前は「いま見ているページのカードを消す」実装に
> していたが、**移動のたびに一覧の中身と順番が変わり読者が混乱した**
> （2026-08-23 に修正）。いまは常に同じ順で全件出し、現在地だけリンクを外して
> `aria-current="page"` を付けている。**出し分ける実装に戻さないこと。**

> **ブロック見出しはカードの外＝紺の地に直接載る。**
> `--text-muted`（本文用の暗いグレー）だと沈んで読めないので、
> 地の上の文字用の明るい色（`--footer-text`）を使っている。
> この文書の冒頭に書いた「文字は白いカードの中にしか置かない」の例外なので、
> 色を変えるときはコントラストを必ず確認する。

> **追従するのは PR枠だけ。** 左の枠と新着記事はページと一緒に流れる。
>
> 枠全体を `sticky` にすると、枠が画面より高いときに上端で貼り付き
> **下端のPR枠に永久に手が届かなくなる**。枠の中をスクロールさせれば届くが、
> **読者がスクロールを2回する**ことになる。
> 新着記事を流し、PR枠（約230px＝どんな画面にも収まる）だけを追従させるのが、
> 「スクロールバーはページの1本だけ」と「広告が付いてくる」を両立する唯一の形
> （2026-08-23 の判断）。
>
> ★ **PR枠をラッパー要素でくくらないこと。** `sticky` が効く範囲は
> 直近のブロックコンテナ＝ `.follow-rail`（グリッドの列）で、
> これは記事の高さいっぱいに伸びている。`<div>` で囲むとその高さまでしか
> 追従しなくなる。だから `.follow-rail` の直下に置いてある。

#### サムネイルを置く（左の枠）

`src/assets/services/<キー>.png` を置くだけで、そのカードに48×48pxの絵が出る。
キーはサービスキー（`netflix` / `prime-video` / `disney-plus`）。
**置いていないキーはサービス名の頭文字**（`N` `A` `D`）になり、レイアウトは崩れない。
詳細と注意（各社ロゴの商標リスクを含む）は
[src/assets/services/README.md](../site/src/assets/services/README.md)。

> **枠では短い名前を使っている。** 1200px のとき文字に使える幅は約158pxしかなく、
> 「Amazon Prime Video」は2行に折り返して**そのカードだけ背が高くなる**（実際に踏んだ）。
> `evergreen.ts` の `SHORT_LABELS` で「Prime Video」に置き換えて1行に収めている。
> 名前の長いサービスを足すときは、ここに短縮形を1行足すこと。
> 併せて `.rail-card { min-height: 64px }` を入れてあるので、
> 万一折り返しても高さは下回らない。

> **カテゴリページのカード（`EvergreenCard.astro`）には画像を付けていない。**
> 周りの記事カードに画像が無いため、そこだけ絵を置くと浮く。
> 画像は左の枠の役割にしてある。

| 変えたいこと | 直す場所 |
|---|---|
| 枠を出す画面幅の下限 | `global.css` の `.layout` のメディアクエリ `75rem`（下げすぎ注意・下記） |
| 枠の幅 | 各コンポーネントの `.block { max-width }`（左右とも 17rem） |
| PR枠が張り付く位置 | `FollowRail.astro` の `.rail-ad { top }` |
| 枠に出す常設ページ | `src/lib/evergreen.ts` の `EVERGREEN_PAGES` |
| 枠での短い表示名 | 同ファイルの `SHORT_LABELS`（下記） |
| 対象サービスそのものの増減 | `src/lib/events-data.ts` の `LEAVING_SERVICES` / `ARRIVALS_SERVICES` |
| 広告カードの文面 | `FollowRail.astro` の `.rail-ad` ブロック |
| サムネイル | `src/assets/services/` にファイルを置く／消す |
| 新着記事の本数 | `FollowRail.astro` の `RECENT_POSTS`（既定3） |
| 追従の対象 | `FollowRail.astro` の `.rail-ad { position: sticky }` |
| ブロックの見出し文言 | 各コンポーネントの `.block-title` を持つ `<p>` |
| 左の枠の補足文（「自由にタイトルを検索できます」） | `LeftRail.astro` の `.block-note` を持つ `<p>` |
| **左の枠を消す** | `BaseLayout.astro` から `<LeftRail />` を外す |
| **右の枠を消す** | `BaseLayout.astro` から `<FollowRail />` を外す |

> **狭い画面（1200px未満）では左右とも枠ごと消える。**
> 常設ページへの入口がスマホで無くなるので、カテゴリページ側にも導線を置いてある
> （`src/pages/category/[category].astro`）。片方だけ消さないこと。

> `.rail-ad` の `position: sticky` は、`html` に `overflow` が無く
> `body` の `overflow-x: hidden` がビューポートに伝播することで成立している。
> **`html` 側に `overflow` を足すと追従が壊れる。**

## 5. ロゴ（ファビコン）を差し替える

いま入っているのは**仮のマーク**（青い角丸に再生三角）。自作ロゴができたら差し替える。

置いてあるファイルは3つ。

| ファイル | 用途 |
|---|---|
| `site/public/favicon.svg` | 本体。モダンブラウザはこれを使う |
| `site/public/favicon-32.png` | SVG非対応の古いブラウザ向け |
| `site/public/apple-touch-icon.png` | iOS のホーム画面追加用（180×180） |

### ターミナルが使える場合

`favicon.svg` を上書きしてから、PNG を焼き直す。

```powershell
cd C:\Users\grate\brog\site
node scripts/make-icons.mjs
```

### ブラウザだけで完結させたい場合

**RealFaviconGenerator**（realfavicongenerator.net）にロゴ画像を入れ、
出てきたファイルから上の3つと同じ名前のものを `site/public/` にアップロードする。

> **アップロードは github.dev ではなく github.com から。**
> リポジトリのページで `site/public` を開き、
> **Add file → Upload files**（1ファイル25MBまで）。

### ロゴをヘッダーにも出す

`site/src/components/Header.astro` を編集する。ロゴが SVG なら
**そのままコンポーネントとして読める**（画像タグではなくインライン展開される）。

```astro
---
import { SITE, CATEGORIES } from '../config'
import Logo from '../assets/logo.svg'
---

<a class="brand" href="/">
  <Logo width={26} height={26} aria-hidden="true" />
  <span>{SITE.name}</span>
</a>
```

```css
.brand {
  display: flex;
  align-items: center;
  gap: 0.45rem;
}
```

> **SVG のロゴは `fill="currentColor"` / `stroke="currentColor"` で作ると得。**
> ダークモードで文字色に自動追従するので、明暗2枚を用意せずに済む。

## 6. ヘッダーバナー（いまは表示していない）

`site/src/assets/header-banner.png`（1200 × 463・2.59:1）。
以前は `BaseLayout.astro` から全ページの一番上に出していたが、
**2026-08-24 に表示をやめた**（画面の上をヘッダーと本文だけにするため）。

> **ファイルは消さないこと。** OG画像（7節）の元になっており、
> `site/scripts/make-og.mjs` がこのパスを直接読んでいる。
> 消すと `node scripts/make-og.mjs` が「元画像が無い」で止まる。

差し替えたい場合は、同じファイル名（`header-banner.png`・幅1200px以上）で
上書きしてから 7節の `node scripts/make-og.mjs` を実行する。

### また画面に出したくなったら

`site/src/layouts/BaseLayout.astro` の `<Header />` の直後に戻す。

```astro
---
import { Image } from 'astro:assets'
import banner from '../assets/header-banner.png'
---
<Image
  class="site-banner"
  src={banner}
  alt={OG_IMAGE.alt}
  widths={[736, 1200]}          {/* 元画像の幅を超える数値は指定できない */}
  sizes="(max-width: 47rem) 100vw, 736px"
  loading="eager"
  fetchpriority="high"
/>
```

`site/src/styles/global.css` に見た目も戻す（削除済み）。

```css
.site-banner {
  display: block;
  width: 100%;
  max-width: var(--max-width);
  height: auto;
  margin: 1.6rem auto 0;
  border-radius: 14px;
}
@media (max-width: 47rem) {
  /* 狭い画面ではヘッダーに密着させて全幅にする */
  .site-banner { margin-top: 0; border-radius: 0; }
}
```

- **`public/` ではなく `src/assets/` に置くこと。** `src/assets/` の画像だけが
  ビルド時に WebP へ変換され、`srcset` と `width`/`height` が自動で付く
  （605KB の PNG → 配信時 15〜27KB の WebP）
- **`loading="eager"` と `fetchpriority="high"` は外さない。**
  画面の一番上に出る画像を遅延読み込みにすると表示速度の評価が落ちる
- **`alt` は画像の中身を書く。** キャッチコピーが画像として入っているなら
  その文言をそのまま書く（`OG_IMAGE.alt` を共有している）
- 高さは縦横比で決まる。2.59:1 ならデスクトップで 736 × 284px。
  詰めたいなら `aspect-ratio` + `object-fit: cover` を足すか、その比率で描き直す

## 7. OG画像（SNS共有画像）を差し替える

X や Slack にURLを貼ったときに出る画像。
いまは**ヘッダーバナーから機械的に作っている**（`site/public/og-default.jpg`・61KB）。

> バナーは 2.59:1 だが、OGPの推奨は **1.91:1**。
> そのまま出すと SNS 側で左右を切られてキャッチコピーが欠けるので、
> 上下に「バナー自身を拡大してぼかしたもの」を継ぎ足して 1200 × 628 にしている。
> 単色で埋めると継ぎ目が帯として見えるため。

### バナーを差し替えたら作り直す

```powershell
cd C:\Users\grate\brog\site
node scripts/make-og.mjs
```

バナーの幅が 1200px でない場合や、バナーが 628px より高い場合は
スクリプトが理由を出して止まる。その場合は手で作る。

### 別の絵を使いたい場合

**1.** 画像編集ソフトで **1200 × 630** で作る。

**2.** `site/public/og-default.jpg` に**同じファイル名で**上書きする
（以降 `make-og.mjs` を流すと上書きされるので、使うのをやめること）。
ファイル名や寸法を変える場合は `site/src/config.ts` も直す。

```ts
export const OG_IMAGE = {
  path: '/og-default.jpg',
  width: 1200,
  height: 628,
  alt: '見放題レーダー｜主要動画サービスの配信終了と新着をまとめて追う',
} as const
```

**3.** `alt` も実際の画像の内容に合わせて直す。

> **写真は JPEG にする。** PNG のままだと1MB近くになる。
> `public/` の画像はビルドで最適化されないので、ここだけは手で軽くする必要がある。
> バナー元画像（`src/assets/`）は PNG のままでよい（ビルドが WebP にする）。

### 注意

- **文字は中央寄りに置く。** SNSによって上下左右が切られる
- **文字は大きく。** タイムラインでは実寸の半分以下で表示される
- **反映は遅い。** 各SNSがキャッシュを持つため、差し替え後も古い画像が出続けることがある。
  X なら Card Validator、Facebook なら Sharing Debugger でキャッシュを更新できる

## 8. カテゴリバッジの色を変える

記事一覧と記事冒頭に出る「配信終了予定」「新着配信」などのタグ。
**読者が文字を読む前に、観られるのか観られないのかを判別できるようにするための色分け**です。

| バッジ | 色 | 意味 |
|---|---|---|
| 配信終了予定 | アンバー | まだ観られる。急ぐ意味がある |
| 配信終了済み | グレー | もう観られない。急かす対象ではない |
| 新着配信 | ブルー | 新しく入った |
| ランキング | パープル | — |

色は `site/src/styles/global.css` の `:root` にまとまっています。

```css
--cat-leaving-bg: #fbeedb;   /* 背景 */
--cat-leaving-fg: #8a4d08;   /* 文字 */
--cat-ended-bg: #e9ecf0;
--cat-ended-fg: #55606d;
--cat-arrivals-bg: #e8f0fe;
--cat-arrivals-fg: #1a5fd0;
--cat-ranking-bg: #efe8fc;
--cat-ranking-fg: #6535bb;
```

**ライトとダークの2箇所にあります。必ず両方直してください。**
ダーク側は地が暗いので、文字を明るく・背景を沈める方向で組んであります。

### 変えるときに守ること

- **文字と背景のコントラスト比を 4.5:1 以上に保つ。**
  現在の8組はすべて 5:1 以上を実測で確認済みです。淡い色同士にすると読めなくなります
- **色だけに意味を持たせない。** バッジには必ずラベル文字を併記します。
  色覚特性のある読者や、印刷・モノクロ表示では色が届きません

### カテゴリを増やしたとき

`:root` に1組（`--cat-<スラッグ>-bg` / `-fg`）を足し、同じファイルの下のほうにある
バッジの定義にも1ブロック足します。

```css
.badge[data-category='新しいスラッグ'] {
  background: var(--cat-新しいスラッグ-bg);
  color: var(--cat-新しいスラッグ-fg);
}
```

**足し忘れても壊れません。** 指定の無いカテゴリは既定のアクセント色で表示されます。

## 9. 記事ごとのカード画像

記事をSNSに貼ったときに出る画像を、**記事1本ごとに自動生成**している。
以前はサイト共通のバナー1枚だったので、どの記事を貼っても同じ絵が出ていた。

出力先は `site/public/cards/<スラッグ>.jpg`（1200 × 630）。
記事タイトル・カテゴリ・サービス名を、サイトの配色でカードに起こしたもの。

### なぜ作品の場面写真を使わないのか

**使えないため。** 理由は3つ。

1. 作品の場面写真（作中キャプチャ）は著作権があり、広告のある当サイトでは
   「引用」の要件（引用の必要性・主従関係）を満たさない
2. 配信APIが返す画像は**ポスターとキーアートだけ**で、本編の画像は含まれない
3. Wikidata / Wikimedia Commons にも無い（実測：Wikidataに項目のある17作品中、画像は0件）

生成カードなら**第三者の権利が一切絡まない。** URLの失効も帯域制限も無い。

> **本文中のセクション画像には作品ポスターを載せている**（2026-08-25〜）。
> 配信APIが返すポスターを、提供元の許諾を得たうえで使っている。
> ここ（記事カード＝SNS共有画像）に載せていないのは、
> 契約が切れたら差し替えが要る画像をOGPに置きたくないため。
> 経緯と運用は [11節](#11-作品ポスターの取り扱い許諾取り直し契約終了)。

### 何もしなくてよい（ビルド時に自動生成される）

`npm run build` の前に自動で走る（`package.json` の `prebuild`）。
記事を書いたら、**ただコミットしてプッシュすればカードもできる。**
画像は `.gitignore` 済みで、コミットする必要も無い。

手元で絵だけ確認したいときは次で単体実行できる。

```powershell
cd C:\Users\grate\brog\site
npm run cards
```

### なぜ環境に左右されないのか

SVG の `<text>` で文字を描くと、**描画するマシンにインストールされたフォント**が使われる。
Cloudflare のビルド環境（Linux）には日本語フォントが無いので、
素直に書くと本番のカードだけ**日本語が豆腐（□□□）になる。**

実測で確認した事実：

| 試したこと | 結果 |
|---|---|
| SVG に `@font-face`（data URI）でフォントを埋め込む | **無視される。** システムフォントに代替された |
| `FONTCONFIG_FILE` でフォント探索先を指定する | **効かない**（Windows では fontconfig を見ない） |

そこで **opentype.js で文字をすべてパス（`<path>`）に変換**している。
出来上がる SVG にフォントの概念が残らないので、Windows でも Linux でも
Cloudflare でも同じ絵になる。

フォントは `site/scripts/fonts/` に同梱（Zen Kaku Gothic New・SIL Open Font License 1.1）。
**差し替えるときは `OFL.txt` も一緒に入れ替えること。**

### 見た目を変える

`site/scripts/make-cards.mjs` の `buildSvg()` を編集する。

| 変えたいもの | 場所 |
|---|---|
| カテゴリごとの色 | `CATEGORY`（**`global.css` の `--cat-*` と同じ値にすること**） |
| 出すサービス名 | `SERVICES`（theme.yaml の catalogs に合わせる） |
| 文字サイズ | `buildSvg()` の `titleSize` ほか、`textPath()` に渡すサイズ |
| 折り返しの行数 | `wrap('bold', title, titleSize, innerW, 3)` の末尾の `3` |
| フォント | `FONTS`（**同梱ファイルとライセンスも入れ替えること**） |
| 画像の寸法 | 先頭の `W` / `H`（**`site/src/config.ts` の `CARD_IMAGE` も同時に直す**） |

### カードを一覧のサムネイルにも出すか

**出していない。** カードには記事タイトルがそのまま描かれているので、
記事一覧に並べるとタイトルが隣に二重に出るだけで、読者が得る情報が増えないため。
必要なら `site/src/components/PostCard.astro` に `<img>` を1つ足せば出せる。

## 10. 本文中のセクション画像

記事の小段落ごとに、**小見出しの直後**へ画像を挟んでいる。

```
## 8月3日：Netflixで京都アニメーション作品が一斉に見放題配信開始

[![Free!（2013年）](/sections/posters/….webp)](…) [![らき☆すた（2007年）](…)](…)   ← ここ

| 配信開始日 | 作品 | 評価 | サービス |
| 8月3日 | Free! | 62/100 | Netflix |
    …

「Free!」「らき☆すた」「日常」は、いずれも京都アニメーション制作の…
```

### どこに入るか

**小見出しの直後**（見出し → 画像 → 表 → 地の文）。
読者が節に入った瞬間に絵が目に入り、そのまま表へ進む。

> 2026-08-25 に「表の直後」から移した。
> 旧位置に残っている画像は `npm run sections -- --write` が消してから入れ直す。

### 版が2つある（重要）

| | 中身 |
|---|---|
| **ポスターが揃った節** | **作品ポスター2枚だけ。** 枠も日付も見出しも文字も描かない |
| **揃わなかった節** | 日付バッジ＋取り上げた作品名・公開年の**枠つきカード** |

**絵の側に文字を描かないのは、すぐ上の小見出しと重複するから。**
日付も主題も作品名も見出しに書いてある。画像にも入れると同じ文字が2回出る。
文字情報は**代替テキスト（alt）とすぐ下の表**に残っているので、
読者にも検索エンジンにも伝わる情報は減らない。

同じ理由で、**文字だけの版からも見出しを外してある。**
描くのは日付と「取り上げた作品」だけ（見出しに必ずしも書かれていない情報）。

### 何が選ばれるか

**その段落の地の文が実際に取り上げた作品を、先頭から2本。**
節の全作品を並べるとすぐ上の表と同じものが二度出て過密になるため、
**2本だけ**にしている。本数は `MAX_HIGHLIGHT` で変えられる。

選び方は「地の文に最初に出てくる順」。読者が読む直前の文章と画像の中身が一致する。
地の文がどの作品にも触れていない段落は、評価の高い順で代替する。

### ポスターが無くても崩れない

ポスターは**その節の2本ぶんが揃ったときだけ**使う。
1枚だけ欠けた状態で並べると、片方だけ絵という中途半端な見た目になるため。

ポスターが付かないのは次の場合（実測：37節中7節が文字だけの版）。

- **U-NEXT 由来の作品**（スクレイピングで集めているので画像が無い）
- **APIがポスターを持っていない作品**（題名を書いただけのSVGが返る。使わない）
- URLが失効している／取得に失敗した（下の11節）

> **文字だけの版は必ず保守すること。** 提供元との契約を終えたら、
> サイトはこの版だけで成立する必要がある。
> コードは `make-sections.mjs` の `buildSvg()`。

### ポスターはアフィリエイトの導線を兼ねる

ポスターは **Amazonのビデオ内検索（レンタル・購入）へのリンク**で包んである。

```markdown
[![Free!（2013年）](/sections/posters/…-1.webp)](https://www.amazon.co.jp/s?k=Free%21&i=instant-video)
```

- トラッキングIDは**記事に焼き込まない。** ビルド時に
  `plugins/rehype-affiliate.ts` が `tag=` と `rel="sponsored"` を付ける
- リンク先を変えるのは `site/scripts/posters.mjs` の `posterLink()` 1か所
- **U-NEXT の提携が通ったら**、リンク先を U-NEXT の検索URLに替えるだけでよい。
  LinkSwitch がブラウザ側で自動変換するのでIDは要らない（[AFFILIATE.md](./AFFILIATE.md)）

なぜ Amazon かというと、対象4社のうち**アフィリエイトが成立するのが Amazon だけ**
だから（Netflix は提携先が無い、Disney+ はクローズド、Apple TV+ は招待制）。
サービスを問わず全作品に出せるので、ポスターが出る節すべてが導線になる。

### 対象になる段落

**日付の `##` 見出しの配下にある表**が対象。`###` の小見出しで分かれている場合は
小見出しごとに1枚できる。「全終了作品リスト」「まとめ」には入らない。

表の列構成は記事タイプによって違う（4列と3列）が、
**見出し行から「作品」列を探す**ので、どちらでも動く。

### 記事を書いたら1度だけ実行する

画像そのものはビルド時に自動生成されるが、**記事への `![…]()` の挿し込みだけは
明示的に実行する**。ビルドが記事ファイルを書き換えるのは避けたいため。

```powershell
cd C:\Users\grate\brog\site
npm run sections -- --write
```

何度実行しても同じ結果になる（既にある行を書き換えるだけ）。

> 画像のファイル名は**見出しのハッシュ**にしてある。
> 節を並べ替えても参照が壊れない。

### 手元で確認するときのフラグ

```powershell
npm run sections -- --refresh     # キャッシュを無視してポスターを取り直す
npm run sections -- --no-posters  # ポスターを使わず文字だけの版を作る
```

`--no-posters` は「契約を終えたらどう見えるか」を確認するのに使う。

## 11. 作品ポスターの取り扱い（許諾・取り直し・契約終了）

セクション画像に載せている作品ポスターは、配信API（Movie of the Night）が
返す画像を**ビルド時に取得して、自分のドメインから配信**している。

### 許諾は取ってある（2026-08-25）

規約には再ホストの明示が無く、「データを再配布してはならない」という条項が
あったため、実装前に提供元へ照会した。**回答は "Yes, you can."**
併せて「**画像は最低でも6ヶ月ごとに取り直すこと**」を推奨された。

> 契約終了後は画像を使えない条項について「規約は更新された」との回答があった。
> **更新後の規約は未確認。** 変更点は
> https://developers.movieofthenight.com/terms-and-conditions で確認すること。
> このリポジトリは「契約終了時には消す」という**厳しい側の前提**で組んである
> （下の「契約を終えるとき」）。

### なぜホットリンクにしないのか

APIが返す画像URLは**署名付きで、6〜12ヶ月で失効する**。
読者のブラウザに直接読ませると、期限が切れた時点で**過去記事の画像が一斉に壊れる。**
読者のアクセスがそのまま提供元のCDN帯域（無料枠 1GB/月）を食うという問題もある。

ビルド時に1回取得する方式なら、消費は**1回のビルドあたり約3.3MB**（実測・58枚）。
読者が何人来ても増えない。

### 取得したものは git に入れない

| 置き場所 | 中身 | git |
|---|---|---|
| `site/.image-cache/` | 取得した元画像 | **入れない**（`.gitignore` 済み） |
| `site/public/sections/posters/` | 記事に出すポスター（WebP） | **入れない**（毎ビルド再生成） |
| `site/public/sections/` | 文字だけの版のカード画像 | **入れない**（毎ビルド再生成） |
| `data/image-manifest.json` | 使っている作品のURLの台帳 | **入れる** |

**コミットすると git の履歴から消せなくなる。**
提供元には「ビルドごとに取得する」と説明して許諾を得ており、
契約終了後は画像を使えない。ここは変えないこと。

Cloudflare のビルド環境は毎回まっさらなので、キャッシュは効かない（毎回取得する）。
`.image-cache/` は手元で同じ画像を何度も落とさないためだけのもので、消しても動く。

### 6ヶ月ごとに取り直す

```powershell
cd C:\Users\grate\brog
npm run refresh:images            # 期限が90日以内に迫ったものだけ
npm run refresh:images -- --dry-run   # APIを叩かず対象だけ見る
```

**1作品につきAPIリクエストを1消費する**（無料枠 500回/月）。
そのため対象は**サイトが実際に使っている作品だけ**に絞ってある。
その一覧は `npm run sections` が `data/image-manifest.json` に書き出す
（2026-08-25 時点で58件）。

`npm run sections` は期限が60日を切ると警告を出す。**警告が出たら実行する。**

```
! 画像URLの期限が近い作品が 12件。最短 2026-12-21
  → npm run refresh:images で取り直してください
```

> **失効しても記事は壊れない。** その節が文字だけの版に戻るだけ。
> 気づかないまま放置すると絵が減っていく、という壊れ方をする。

### 契約を終えるとき

```powershell
cd C:\Users\grate\brog\site
npm run posters:purge   # キャッシュとセクション画像を消す
npm run sections        # 文字だけの版を作り直す
```

そのうえで `data/image-manifest.json` を削除し、コミットする。

## 12. 記事のヘッダー画像（frontmatter の `heroImage`）

記事1本に1枚。**2か所に同時に出る。**

| 出る場所 | 大きさ |
|---|---|
| 記事一覧・追従枠のカードの左サムネイル | 72×72（正方形で切り抜き） |
| 記事ページの見出し（h1）の直上 | 高さ320pxまで。**切り抜かない** |

未設定なら、カードは**カテゴリ色のタイル**、見出し上は**何も描かない**。
レイアウトは崩れないので、揃わない記事があっても問題ない。

### 自動で選ばれる（記事を書いたら勝手に入る）

`npm run sections -- --write` が frontmatter に書き込む。優先順は2つ。

1. **記事タイトルと一致する作品**のポスター
2. 取れなければ、**記事に最初に出てくる作品**のポスター

一致は前方一致で見る。記事タイトルが「…クレヨンしんちゃん劇場版」で
作品名が「クレヨンしんちゃん オラたちの恐竜日記」でも拾えるようにするため。
**4文字以上**一致したものだけを候補にする（`HERO_MATCH_MIN`）。
「日常」のような短い題名は誤爆するので候補にしない。その記事は2番目の規則に落ちる。

> ポスターが1枚も取れない記事（U-NEXTだけの記事など）は**未設定のまま**になる。
> カードはカテゴリ色のタイルに戻るだけで、記事は崩れない。

### 気に入らない絵は手で差し替えてよい

**frontmatter に書いてある値が最優先。** 自動処理は
`heroImage` が空のとき、または自分が入れた `/heroes/<スラッグ>.webp` のときしか触らない。
**別のパスを書いた瞬間、その記事は自動処理の対象から外れる。**

```yaml
heroImage: '/my-hero.jpg'   # site/public/my-hero.jpg を置く
```

好きな画像を `site/public/` に置いて、そのパスを書けばよい。
`site/public/` はビルドで最適化されないので、**置く前に自分で軽くしておくこと**。

> 別の作品のポスターにしたいだけなら、`/heroes/…` ではなく
> `/sections/posters/…`（その記事の節に出ているポスター）を指してもよい。
> ファイル名は記事の本文に書いてある。

## 画像ファイルの置き場所

| 置き場所 | 最適化 | 使うもの |
|---|---|---|
| `site/src/assets/` | **される**（WebP変換・srcset自動） | 記事やページに `<Image>` で載せる画像 |
| `site/public/` | されない（そのまま配信） | favicon、OG画像、CSSの `url()` から参照する素材 |

**判断基準はひとつ。`<Image>` で読むなら `src/assets/`、
URLで直接指す必要があるなら `public/`。**

### 環境について（確認済み）

- 画像最適化（sharp）はインストール済み。Cloudflare のビルド環境（Linux）でも動く
- `.gitattributes` で画像はバイナリ指定済み。改行変換で壊れることはない
- `/_astro/` 配下（最適化後の画像）には `site/public/_headers` で永久キャッシュを設定済み

## 素材のライセンス（重要）

**このサイトは広告を載せる＝商用サイト。** 素材は必ず商用利用可のものを使う。

### 使ってはいけないもの

| | 理由 |
|---|---|
| 映画・ドラマのポスター、場面写真、キービジュアル**を自分で拾ってきて使う** | 著作権。配信ブログで最も起きやすい事故 |
| ライセンスを確認していない写真素材 | **現在のヘッダーバナーの映画館写真も、出所と商用可否を確認しておくこと** |
| Netflix / Disney+ / Prime Video / Apple TV+ のロゴ | 商標＋各社ブランドガイドライン。サービス名は**テキストのまま**が安全 |
| Canva の無料素材を「ロゴ・商標として単独で」使う | Canva のライセンス上禁止（デザインの一部ならOK） |

> **唯一の例外が、配信APIが返す作品ポスター。**
> 提供元（Movie of the Night）に照会して再ホストの許諾を得ており、
> 帰属表示もサイトと各記事に出している。**API経由で取得したものだけ**が対象で、
> 検索で拾ってきたポスターは対象外。運用は [11節](#11-作品ポスターの取り扱い許諾取り直し契約終了)。

### 使える無料素材

| サイト | 内容 | ライセンス |
|---|---|---|
| unDraw（undraw.co） | イラスト。色を `--accent` に合わせて書き出せる | 帰属不要・商用可 |
| Hero Patterns（heropatterns.com） | 背景パターンSVG | CC0 |
| Unsplash / Pexels | 写真 | 帰属不要・商用可 |

> Webフォントの読み込みがゼロになる。

## 確認方法

github.dev にはプレビュー機能が無い。**デザインを変えたときはローカルで確認すること。**

```powershell
cd C:\Users\grate\brog\site
npm run dev
```

→ http://localhost:4321/ 。ファイル保存で即座に反映。Ctrl+C で停止。

| 見るべき点 | どうやって |
|---|---|
| ダークモード | OSの設定を切り替える（またはブラウザの開発者ツールで強制） |


## 困ったとき

### 画像を差し替えたのに古いまま表示される

**`npm run dev` でだけ起きる。** 開発サーバーの画像URL（`/_image?href=...`）は
ファイルを差し替えても変わらないので、ブラウザが古い画像を持ち続ける。

1. ブラウザで**ハードリロード**（Windows: `Ctrl` + `Shift` + `R`）
2. それでも直らなければ dev を止めてキャッシュを消し、開き直す

```powershell
cd C:\Users\grate\brog\site
# dev サーバーを Ctrl+C で止めてから実行する
Remove-Item -Recurse -Force node_modules\.vite, .astro -ErrorAction SilentlyContinue
npm run dev
```

> **本番では起きない。** ビルド後のファイル名には内容のハッシュが入る
> （`header-banner.BuN91i8f_276sbD.webp`）ので、中身が変われば URL も変わる。
> ただし `public/` に置いたもの（`og-default.jpg`・favicon）はファイル名が
> 固定なので、本番でもブラウザやSNSのキャッシュが残ることがある。

### `Could not resolve '../assets/xxx.png'` でビルドが落ちる

`site/src/assets/` のファイル名が `import` 側と**完全一致していない。**
よくあるのは**拡張子の前の半角スペース**（`header-banner .png`）で、
見た目では気づけない。ファイル一覧で名前を確認して直す。

### `widths` に元画像より大きい数値を指定してビルドが落ちる

`<Image>` の `widths` は**元画像の幅を超えられない。**
1200px 未満で書き出した画像なら、この数値を下げる。

### 作品検索を打っても何も起きない

常設ページ（`/leaving/…` `/arrivals/…`）の検索窓は
**JavaScript が動かないと出ない**（出ても押せない窓を見せないため）。
出ているのに当たらない場合は、`site/src/lib/normalize.ts` の
ならし方だけを直す。**ビルド時と実行時が同じ関数を使っている**ので、
片方だけ変えると全件外れる。
