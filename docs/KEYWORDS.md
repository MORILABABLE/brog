# 検索語の空き地と、新しい記事ジャンル（考察）

作成: 2026-08-30 ／ 最終更新: 2026-08-30

**このうち案1（記事タイプ『シリーズ』）は同日に実装済み**（6節）。残る案2〜4は考察のみ。

出発点は「サイト名の『見放題』を取れれば見返りが大きいが、競合が強い」という見立て。
**実測すると、この見立ての前半が成立していない。** 何を取りに行くべきかを測り直し、
そのうえで新しい記事ジャンルを設計する。

## 0. 結論（先に4つ）

1. **「見放題」は動画配信の語ではない。** 単体のサジェスト10件のうち、
   動画配信を指すのは3件だけ。残りは音楽サーキットフェス「見放題」（大阪・名古屋・東京）。
   **この語で1位を取っても、フェスの客が混ざる。** 見返りは想定より小さい。
2. **読者は「見放題」を単独で打たない。** 「見放題 いつまで」「見放題 いつから」の
   サジェスト計19件のうち、**17件が作品名かサービス名との複合**だった。
   当てるべきは語そのものではなく、**「見放題」の隣に立つ語**。
3. 空いている的は3つ。**「なぜ」「カレンダー」「シリーズ」**。
   このうち**記事ジャンルの新設が要るのは「シリーズ」だけ**で、
   残り2つはページの形式と、素材が貯まるまで待つ話になる。
4. **人物軸は空き地ではなく荒地。** 「トム・クルーズ 配信」「ジャッキー・チェン 見放題」
   「出演作 配信」はいずれもサジェスト**0件**。S-3 で作った人物ページ144枚は
   **内部リンクの資産**として正しいが、**検索の的としては期待しないほうがよい**。

## 1. 前提の訂正 —「見放題」は動画の語ではない

サジェスト実測（2026-08-30）。**太字が動画配信の語。**

| 入力 | 候補10件 |
|---|---|
| `見放題` | **見放題** / 見放題東京 / 見放題大阪2026 / 見放題名古屋2026 / 見放題大阪 / 見放題名古屋 / **見放題チャンネル** / 見放題2026 / **見放題配信とは** / **見放題独占配信** |
| `見放題␣` | 見放題 大阪 / 見放題 名古屋 / 見放題 2026 / 見放題 名古屋 2026 / 見放題 チケット / **見放題 おすすめ** / 見放題 フェス / 見放題 タイムテーブル / 見放題 英語 / 見放題 東京 2026 |

「見放題」は**大阪・名古屋・東京で開催される音楽サーキットフェスの名前**で、
サジェストの多数派をそちらが占めている。「チケット」「タイムテーブル」「フェス」が
候補に並ぶのはそのため。

**サイト名としては良い名前だが、検索の的としては見返りが薄い。**
仮に上位を取れても、流入の相当部分がフェスを探している人になる。
指名検索（「見放題レーダー」）で1位を取れている現状で、この語に追加投資する理由は無い。

> ★ **サイト名を変える話ではない。** タグライン「消える前に、気づける。」と
> 動詞句「見放題配信が終了予定の」は、**購入・レンタルと区別する語**として機能している
> （[naming.md](../theme-packs/streaming-jp/templates/naming.md)）。
> 変えるべきは「この語で戦う」という**投資判断のほう**。

## 3. 空いている的

### 3-1.「なぜ」— 理由の検索（**いま最も競合が薄い**）

サジェスト実測。

| 入力 | 候補 |
|---|---|
| `配信終了 なぜ` | netflix ワンピース／netflix コナン／netflix／ネットフリックス ナルト／フルハウス netflix／ハリーポッター netflix／プリズンブレイク／有田と週刊プロレスと／アドベンチャータイム |

beaconlink.jp・media-panorama.com）。中身を確認したところ、答えはどれも
**「ライセンス契約が満了したため」という一般論**で、そこから
「VPNで見る方法」「代替サービスはこちら」へ誘導する形になっている。

**ここは当サイトが事実で殴れる的。**
一般論ではなく、観測した数字で答えられる（すべて追加収集ゼロ）。

| 言えること | 実測 |
|---|---|
| 終了は**月末に集中する** | 8月の終了予定542件のうち **291件（54%）が8月31日**。次点は9月1日の37件 |
| 未来の終了予定を持っている | **437件**（Netflix 103 ／ Prime Video 34 ／ U-NEXT 300） |
| 出入りを2種類以上観測した作品 | **88件** |
| 消えたあとに戻った作品 | **4件**（トランスフォーマー/最後の騎士王・ブラックベリー・ピンクパンサー1&2） |

> ★ **「なぜ」の答えそのものは他所と同じ**（契約の満了）。
> 差が出るのは「**いつ・どれくらいの規模で・どの周期で**」の部分だけ。
> つまり**数字が薄いうちは書けない**。いま観測は1か月ぶんしかない
> （[STOCK.md](./STOCK.md) S-5 が「素材待ち」としているのと同じ理由）。

### 3-2.「カレンダー」— 形式の空き

競合は実在する。**[GROWTH.md](./GROWTH.md) 1節の記述に訂正が要る。**

> GROWTH.md 1節: 「『その作品がいつ見られなくなるか』に日本語で答えられるサイトはほぼ存在しない」

**Netflix についてはこれは誤り。** 実在する:

| サイト | 中身 |
|---|---|
| `net-frx.com`（Get Freax） | **Netflix特化**。終了予定をカレンダーと一覧の両方で出し、**作品ごとの個別ページも持つ** |
| `mouhai.net`（もうすぐ配信終了だ） | 「Netflix 配信終了予定タイトル一覧」。日付つき（bot拒否のため中身は未確認） |
| `animephilia.net` | 月別の新着・配信予定カレンダー |

**それでも残っている差は「横断」。** 上記はいずれも1サービス（主に Netflix）に閉じている。
当サイトは Netflix / Prime Video / U-NEXT の終了日を**同じ日付軸で並べられる**。

未来の終了予定を日付で束ねた実測（JST・2026-08-30 時点）:

```
2026-08-31  計291  Netflix 61 / U-NEXT 230
2026-09-01  計 37  Prime Video 33 / Netflix 2 / U-NEXT 2
2026-09-02  計 11  U-NEXT 10 / Netflix 1
2026-09-09  計  8  Netflix 8
2026-09-14  計 10  Netflix 8 / U-NEXT 2
（終了日が付いている日は全27日）
```

> ★ **U-NEXT のカレンダーは作れない。** [UNEXT.md](./UNEXT.md) 2-3 で
> 常設ページを作らないと決めている。上の表で U-NEXT が最大勢力なのに、
> **常設のカレンダーに出せるのは Netflix と Prime Video だけ**になる。
> サジェストに `u-next 配信終了 カレンダー` があっても、そこは取りに行かない。
> **この制約は守る。**

## 5. 表記の衝突 —「アマプラ」問題

**読者は略称で検索している。** 実測でサジェストに出た略称:

> アマプラ 見放題終了 ／ アマプラ 終了カレンダー ／ アマプラ 終了間近 ／ アマプラ 終了予定 ／
> アマプラ 配信終了 一覧 ／ ネトフリ 見放題終了 ／ ネトフリ 終了予定 ／ ネトフリ 終了作品 ／
> ネトフリ 配信終了 なぜ ／ ディズニープラス 配信終了 カレンダー

いっぽう [naming.md](../theme-packs/streaming-jp/templates/naming.md) は
**略称の使用を禁止**しており、`titleIssues()` が **error** で止める
（[ARTICLE-RULES.md](./ARTICLE-RULES.md) 3-4）。

**この規則は変えないほうがよい。** タイトルの表記が揺れると、
記事一覧・パンくず・タグとの一致が崩れる（`SERVICE_HUBS` の `tag` は完全一致で記事を拾っている）。

**代わりに、本文の中で1回だけ読者の言葉を使う。**

- リードの1文目で `Amazon Prime Video（アマプラ）` のように**正式表記に添える形**で1回
- `<title>` と h1 は現行のまま（正式表記）
- meta description は本文から作られるので、そこに略称が入る

> ★ **表記ゆれの解禁ではない。** 添えてよいのは
> **1記事1回・正式表記の直後・括弧の中**だけ、という形に閉じ込める。
> 実装するなら `fixed-phrases.md` に固定文言として置き、
> 記事ごとにLLMが判断する形にしない（判断させると必ず揺れる）。

## 6. 記事ジャンルの案（採否つき）

**4案。上から着手順。** 各案を「狙う語 → 素材 → 既存の決まりとの整合 → 弱点」で見る。

### 案1 ★ 記事タイプ『シリーズ』 — **✅ 実装済み（2026-08-30）**

**「〇〇シリーズは、いつまで見放題で観られるのか」に1本で答える記事。**

> **実装したもの**
>
> | 何 | どこ |
> |---|---|
> | 記事タイプ | `theme-packs/streaming-jp/article-types/series.ts`（`index.ts` に登録） |
> | 構成・文体 | `theme-packs/streaming-jp/templates/series.md` |
> | 固定文言 | 同 `fixed-phrases.md` の `series-` で始まる3キー |
> | タイトルの決まり | 同 `naming.md`「シリーズ記事だけ期間を名乗らない」 |
> | 右の枠 | `site/src/components/SeriesRail.astro` ／ 拾い方は `site/src/lib/series-posts.ts` |
>
> **素材の実測（`--dry-run` で確認）**
>
>     npm run write -- --type series --topic "「名探偵コナン」劇場版シリーズ" \
>       --slug conan-movies --match "名探偵コナン" --dry-run
>     → 2,227件中 61件を選択（U-NEXT 34 / Netflix 27・全件が終了予定）
>
> **設計を2か所変えた。** どちらも「同じURLを書き直し続ける」ことから来ている。
>
> - **`--kind` を持たせなかった。** 特報は人が「終了予定／終了済み」を選ぶが、
>   シリーズ記事は同じURLを何か月も書き直すので、**人が選んだ値だけが古くなる**。
>   状態は素材から決める（`stanceOf()`）。動詞句・カテゴリ・リードの固定文言が
>   まとめて切り替わり、全作が終われば同じURLのまま「終了した」の記事になる。
> - **`categoryOf()` に素材を渡すようにした**（`pipeline/core/article.ts`）。
>   カテゴリも素材から決まるため。`ctx` だけを見る特報は今までどおり動く。
>
> **表の列を5列にした**（終了日 / 作品 / **状態** / 評価 / サービス）。
> 終了予定と終了済みが1本の記事に混ざるので、状態列が無いと読者が
> 1行ずつの可否を判断できない（混在時は品質ゲートが列の有無を見ている）。
> `rehype-work-links` は列の位置ではなく中身で判定しているので、
> 列を1つ増やしても作品ページへの内部リンクは今までどおり付く。

| | |
|---|---|

## 9. 実測のやり方（再現用）

**サジェスト。** 依存なし・APIキー不要。`$CLAUDE_JOB_DIR/tmp` などに置いて実行する。

```js
// suggest.mjs — node suggest.mjs "見放題 いつまで" "配信終了 なぜ"
const seeds = process.argv.slice(2)
for (const s of seeds) {
  const url = `https://suggestqueries.google.com/complete/search?client=firefox&hl=ja&gl=jp&q=${encodeURIComponent(s)}`
  const res = await fetch(url, { headers: { 'User-Agent': 'Mozilla/5.0' } })
  const txt = new TextDecoder('utf-8').decode(new Uint8Array(await res.arrayBuffer()))
  console.log(`【${s}】 ` + (JSON.parse(txt)[1] || []).join(' / '))
  await new Promise((r) => setTimeout(r, 400))
}
```

> ★ **UTF-8 で明示的にデコードすること。** 既定のコードページのまま出すと文字化けする。
> ★ 400ms 空けている。**まとめて叩かない。**

**シリーズ候補の洗い出し**（邦題の先頭6文字で束ねる。粗い候補出し用）。

```js
// series.mjs — node series.mjs
import fs from 'node:fs'
const ev = fs.readFileSync('data/events/2026-08.jsonl', 'utf8').trim().split('\n').map((l) => JSON.parse(l))
const works = new Map()
for (const e of ev) {
  if (!works.has(e.work.id)) works.set(e.work.id, { w: e.work, ev: [] })
  works.get(e.work.id).ev.push(e)
}
const buckets = new Map()
for (const [, v] of works) {
  const t = (v.w.localizedTitle || v.w.title || '').trim()
  if (t.length < 4) continue
  const k = t.slice(0, 6)
  if (!buckets.has(k)) buckets.set(k, [])
  buckets.get(k).push(v)
}
const now = new Date()
for (const [k, v] of [...buckets].filter(([, v]) => v.length >= 3).sort((a, b) => b[1].length - a[1].length)) {
  const fut = v.filter((x) => x.ev.some((e) => e.kind === 'expiring' && e.at && new Date(e.at) > now)).length
  console.log(`${k}… ${v.length}件（未来の終了予定 ${fut}）`)
}
```

**終了日の集中**（月末に寄っているか）。

```js
// month-end.mjs — node month-end.mjs
import fs from 'node:fs'
const ev = fs.readFileSync('data/events/2026-08.jsonl', 'utf8').trim().split('\n').map((l) => JSON.parse(l))
const byDay = {}
for (const e of ev.filter((e) => e.kind === 'expiring' && e.at)) {
  const jst = new Date(new Date(e.at).getTime() + 9 * 3600e3)
  byDay[jst.getUTCDate()] = (byDay[jst.getUTCDate()] || 0) + 1
}
console.log(Object.entries(byDay).sort((a, b) => b[1] - a[1]).slice(0, 5))
```
