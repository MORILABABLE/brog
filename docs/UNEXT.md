# U-NEXT の収集

最終更新: 2026-08-25

U-NEXT だけは Streaming Availability API の外側にあるので、自前で取りに行く。
**なぜそうするのか・法務上の整理**は [SOURCES-UNEXT-HULU.md](./SOURCES-UNEXT-HULU.md)。
このファイルは**何が動いていて、データがどう並んでいるか**を書く。

> **Hulu は同じことをしない。** 利用規約 第3条(3) が自動化手段でのアクセスを
> 明示的に禁止している。Hulu は検索リンクのまま据え置く。

## 1. コマンド

| コマンド | 内容 |
|---|---|
| `npm run unext:menu` | ジャンルとカテゴリのIDを調べる（`theme.yaml` に貼る形で出る） |
| `npm run collect:unext` | 新着・配信終了予定を収集して記録する |
| `npm run unext:refresh` | 作品台帳の情報を取り直す（**終了日の変更を見つける**） |

```bash
npm run collect:unext                                    # 新着と終了予定
npm run collect:unext -- --kinds expiring                # 終了予定だけ
npm run collect:unext -- --genres anime,youga --pages 1  # 試し打ち
npm run collect:unext -- --dry-run                       # 何も書かずに結果だけ見る
npm run unext:refresh -- --dry-run                       # 取り直す対象を数えるだけ
```

**API キーは要らない。無料枠という概念も無い。** かわりに**時間**が制約になる
（実ブラウザなので1ページ2.5秒）。`collect` とコマンドを分けているのはこのため。
API の枠だけ見ているつもりで数十分ブラウザを回す事故を避ける。

### `unext:refresh` は何を取り直すか

| 理由 | 再取得の下限 |
|---|---|
| 作品ページを一度も開いていない | **かからない**（情報が無いので必ず取る） |
| 話数を持っていない（種別が推定のまま・6-1） | **かからない** |
| 終了日が60日以内に迫っている | 最後の確認から12時間 |
| 最後の確認から14日以上たっている | 同上 |

**12時間の下限があるのは、無駄な負荷をかけないため。**
「終了日が近い」作品は毎回そこそこの数になる（実測153件）ので、
下限が無いと同じ日に2回流しただけで同じ150件を開き直すことになる。

1件の取得に失敗しても全体は止めない（`429` / `503` を受けたときだけ止める）。
**数百件直したあとの1件で全部を道連れにしない**ため。失敗した件数は最後に出る。

## 2. どうやって取っているか

U-NEXT は**検索エンジンのUAにだけ**サーバー側で中身を描画する。
Chrome も curl も自称ボットも、返るのは空の器だけ（実測）。

**Googlebot を名乗る手は採らない。** 検索エンジンだと偽ることになる。
かわりに **実ブラウザ（Playwright + Edge / Chromium）で普通に開く。**

さらに、HTMLを解析するのではなく **ページ自身が投げた GraphQL の応答を横で受け取る**
（`pipeline/sources/browser.ts`）。画面の作りが変わっても壊れず、型のついたデータが手に入る。

> GraphQL を直接叩く道は塞がれている。自前で組み立てた問い合わせは
> `403 QUERY_NOT_IN_SAFELIST` で弾かれる（persisted query safelist）。
> ブラウザに正規の問い合わせを投げさせるのが唯一の道。

### 何を読んでいるか

| 種別 | 読む場所 | 並び順 |
|---|---|---|
| `new` | 各ジャンルの「新規入荷作品」カテゴリ | `public_start_desc`（配信開始日の新しい順） |
| `expiring` | 各ジャンルの「すべての作品」 | `public_end_asc`（**配信終了日の近い順**） |

`removed`（配信終了済み）は**取らない**。全カタログの棚卸しが要って重すぎる一方、
`expiring` が取れるので事後まとめを書く理由がない。

### 期間指定が無い

U-NEXT に「いつ何が変わったか」を返す仕組みは無い。毎回いまの一覧を読み、
**台帳（`data/ledger.json`）との差分**を「前回以降の変化」とみなす。
`collect` の `--days` に相当するものは無く、**実行頻度が期間を決める**。

## 3. データの形

**2層ある。役割が違うので混ぜない。**

```
data/events/{YYYY-MM}.jsonl   変化のログ。追記のみ。過去は書き換えない
                              ＝「8月31日に見放題終了する」という出来事
                              → 記事の素材

data/unext-titles.json        作品のいまの姿。上書きする
                              ＝「この作品は現在こうなっている」
                              → 常設ページの素材／次回収集の当たり判定
```

### 3.1 変化のログ（既存の形をそのまま使う）

`ChangeEvent` は Streaming Availability API のものと同じ型。
**`service` が `u-next` になるだけ**で、通知（`digest.ts`）も記事の仕組みも無改修で通る。

```jsonc
{
  "collectedAt": "2026-08-24T14:52:49.576Z",
  "service": "u-next",
  "kind": "expiring",              // new | expiring
  "at": "2026-08-28T14:59:00.000Z", // 終了（new なら配信開始）日時
  "work": {
    "id": "SID0039534",
    "title": "太王四神記",          // 最初から邦題
    "localizedTitle": "太王四神記",
    "type": "series",
    "year": 2007,
    "overview": "",                 // ★ 意図的に空。4節
    "rating": 90,                   // U-NEXT の 0-50 を 0-100 に正規化
    "genres": ["韓流・アジア"],
    "link": "https://video.unext.jp/title/SID0039534",
    "meta": {
      "source": "u-next",
      "genreKey": "asia-drama",
      "genreLabel": "韓流・アジア",
      "lineup": "svod",             // svod | point | both | unknown
      "isNew": true,
      "isOriginal": false,
      "exclusive": false,           // U-NEXT独占か
      "episodeCount": 24,
      "seriesName": "太王四神記",
      "country": "韓国",
      "publicStartDate": "2021-10-14T03:00:00.000Z",
      "publicEndText": "2026年8月28日 23:59まで配信",
      "typeSource": "detail",       // detail | heuristic（6-1）
      "detailFetched": true
    }
  }
}
```

### 3.2 作品台帳（`data/unext-titles.json`）

```jsonc
{
  "version": 1,
  "titles": {
    "SID0039534": {
      "id": "SID0039534",
      "title": "太王四神記",
      "type": "series",
      "episodeCount": 24,
      "genreKey": "asia-drama",
      "genreLabel": "韓流・アジア",
      "lineup": "svod",
      "year": 2007,
      "seriesName": "太王四神記",
      "country": "韓国",
      "publicStartDate": "2021-10-14T03:00:00.000Z",
      "publicEndDate": "2026-08-28T14:59:00.000Z",
      "publicEndText": "2026年8月28日 23:59まで配信",
      "firstSeenAt": "2026-08-24T14:52:49.576Z",
      "lastSeenAt": "2026-08-24T14:52:49.576Z",
      "detailCheckedAt": "2026-08-24T14:52:49.576Z"
    }
  }
}
```

**なぜ要るか。** 配信終了日は一覧に出てこない。作品ページを1件ずつ開かないと取れず、
1件2.5秒かかる。毎回全件を開き直すと数十分かかるうえ、その大半は
「前回と同じ答え」を相手のサーバーから貰い直すだけの無駄になる。

既知の作品は、台帳に記録した終了日で**「まだ期限の内側か」の判定だけ**を行い、
ページを開かない。

> **台帳の日付を記事に出さないこと。** 終了日は変わる。
> 古い日付で記事を書くのが最悪の事故なので、**記事の素材になる作品（＝台帳に無い新しいもの）
> は必ず取り直す**。台帳の値は「どこまで読み進めるか」の判断にしか使わない。
> 実装は `unext.ts` の `#collectExpiring`。

### 3.3 値の意味

| フィールド | 意味 | 注意 |
|---|---|---|
| `lineup` | `svod`＝見放題 / `point`＝ポイント（レンタル・購入） | **「見放題終了」と「配信終了」は違う。** ポイント作品として残るものがある |
| `episodeCount` | 本編の話数。映画は 1 | `type` の根拠。無い記録の `type` は推定（6-1） |
| `exclusive` | U-NEXT独占か | 記事の目玉になる |
| `rating` | 0-100 に正規化（U-NEXT は 0-50） | 0以下は「評価なし」で `undefined` |
| `publicEndText` | 終了日の元表記 | 書式が変わったときに気づくために残している |

## 4. 取らないもの（法務由来の設計）

**事実だけを取り、表現は取らない。**

| | 例 | 扱い |
|---|---|---|
| 事実 | 作品名 / SID / 配信開始日 / 配信終了日 / 見放題かポイントか / 公式ジャンル / 製作年 / 話数 | **取る** |
| 表現 | `catchphrase`（キャッチコピー）/ `story`（あらすじ）/ `attractions` / サムネイル画像 | **取らない** |

API の応答にはキャッチコピーもあらすじも入っているが、**`unext.ts` の入口で捨てている。**
後段が触れる場所に置かない。

> **「収集しただけ・非公開」はこのリポジトリでは成立しない。**
> collect ワークフローは `git add data/` して push する設計で、
> リポジトリは **public**。拾ったものはそのまま GitHub 上で公開される。
> だから「記事にしなければ大丈夫」という整理は使えず、**取らないことが唯一の対策**になる。

`overview` が空文字なのはこのため（`Work.overview` が必須なので `undefined` にできない）。

**記事の質は落ちない。** `templates/leaving.md` を読むと分かるとおり、
配信終了記事が使っているのは作品名・終了日・シリーズ名・評価であって、あらすじではない。

## 5. 相手のサーバーへの負荷

利用規約 第25条(7)「当社のサーバーに過度の負担を及ぼす行為」は、
**こちらで制御できる唯一の項目**なので、既定を安全側に倒してある。

| | 設定 | 場所 |
|---|---|---|
| 遷移の最小間隔 | **2500ms** | `theme.yaml` の `unext.min_interval_ms` |
| 画像・動画・フォント | **読み込まない** | `browser.ts`（相手の転送量が桁で減る） |
| 1回の作品ページ上限 | 300 | `unext.max_detail_views` / `--max-detail` |
| 1回のページ数上限 | 実行時に計算 | 暴走したときの保険 |
| 429 / 503 | **その場で全体を止める** | `BackoffError`。粘らない |

**速くしたくなっても `min_interval_ms` を下げないこと。**
岡崎市立図書館事件（2010）は規約違反ではなく負荷で刑事事件になった実例で、
止め方を決めておくことが対策の本体になる。

### 実測（2026-08-24〜25／2.5秒間隔・各ジャンル1ページ）

| | 収集 | 開いたページ | うち作品ページ | 所要 |
|---|---|---|---|---|
| 終了予定・1回目（4ジャンルで予算切れ） | 115件 | 156 | 150 | 約6.5分 |
| 終了予定・2回目（残り7ジャンル） | 95件 | 183 | 172 | 約7.5分 |
| 新着・全11ジャンル×3ページ | 513件 | 147 | 120 | 約6分 |
| 台帳の取り直し（話数を埋める） | 274件 | 274 | 274 | 約18分 |

**終了予定の2回目は、既知の作品158件について作品ページを開いていない。**
作品台帳が効いている証拠で、回を追うごとに速くなる。

#### 集まったもの（2026-08-25 時点）

| | 件数 |
|---|---|
| **配信終了予定** | **210件**（見放題166 / ポイント33 / 両方8 / 不明3） |
| ┗ うち8月中に見放題終了 | **151件**（映画102 / シリーズ49） |
| **新着** | **513件**（見放題372 / ポイント139） |
| 作品台帳 | **776件**（終了日あり210 / 開始日あり394 / 話数あり394） |

終了予定は**各ジャンル1ページだけ**読んでこの数。`expiring_pages` を上げれば増える。
新着で配信開始日を持つのが120件どまりなのは作品ページの予算を使い切ったためで、
**残りは次回以降の `unext:refresh` が埋める。**

## 6. 落とし穴

### 6-1. `type`（映画かシリーズか）は作品ページを開かないと当てにならない

U-NEXT は種別を明示しない。一覧から分かるのは「更新曜日」と「最新話」だけで、
これは**放送中の作品にしか効かない**。完結済みのシリーズは更新曜日を持たないので、
一覧だけ見ると映画と区別がつかない。

> 実測: 全24話の「太王四神記」が `movie` と判定された。

作品ページの `publicMainEpisodeCount`（本編の話数）が確実な根拠になる。
どちらで決めたかは `meta.typeSource` と台帳の `episodeCount` に残す。
**`episodeCount` を持たない記録の `type` は信用しないこと。**
`npm run unext:refresh` が埋めに行く。

> 実測: 一覧だけで判定すると 274件中 series は **1件**しかなかった。
> 作品ページで話数を取り直したら **105件**（映画169件）になった。
> 「Theかぼちゃワイン」95話、「ザ☆ウルトラマン」50話、「太王四神記」24話が
> すべて映画に化けていた。**放置していたら記事で「映画」として紹介していた。**

### 6-2. 同じ作品が複数のジャンルに出る

「洋画」と「アニメ」の両方に出る作品がある。台帳の重複除外は
`service:kind:作品ID` で効くので二重に記録されることはないが、
**`genreLabel` は先に見つけたほうが残る。** ジャンル別記事を作るときは、
ジャンルごとに一覧を引き直すこと。イベントの `genreLabel` で振り分けない。

### 6-3. `displayPublicEndDate` は表示用の文字列

`"2026年8月28日 23:59まで配信"` という形。ISO ではない。
書式が変われば静かに壊れるので、**パースできなかったものは記事に出さない**
（`parseEndDate` が `undefined` を返し、イベントを作らない）。
元の文字列は `publicEndText` に残してあるので、壊れたときに気づける。

### 6-4. カテゴリIDはジャンルごとに呼び方が違う

「新規入荷作品」はキッズでは「あたらしい」、音楽では「新規入荷の音楽作品」。
**名前では拾えない**ので構造で拾っている（一覧の先頭＝全作品、
既定の並びが `PUBLIC_START_DESC` の最初＝新規入荷）。
`unext-menu.ts` の `pickAll` / `pickArrivals`。

**IDがずれると収集が静かに空振りする。** 取得数が急に減ったらまずここを疑い、
`npm run unext:menu` で調べ直す。

### 6-5. 終了日は動く

延びることも前倒しになることもある。**すでに記事にした作品の日付が変われば、
その記事は間違ったまま公開され続ける。**
`npm run unext:refresh` が変更を検出して一覧で出すので、定期的に回すこと。

## 7. これで何が書けるか（提案・未実装）

素材は揃った。記事タイプはまだ作っていない。

### A. U-NEXT 今月見放題が終了する作品 ✅ 実装済み（2026-08-25）

```bash
npm run write -- --type leaving --service u-next --dry-run
```

**記事タイプは増やしていない。** `leaving` の variant に `u-next` を1行足しただけで、
Netflix / Prime Video とまったく同じ構成・同じテンプレート・同じ検査を通る。
違いは「構成」ではなく「素材に何が入っているか」だけだったので、
差分は `leaving.ts` の `SOURCE_TRAITS` という表1つに寄せてある。

| | Netflix / Prime Video | U-NEXT |
|---|---|---|
| タイトル | 英語。Wikidata で邦題を引く（解決率73%） | **最初から邦題**。原題を併記しない |
| あらすじ | 英語で持っている | **持っていない**（4節）。創作を明示的に禁じる指示に差し替え |
| 見放題／ポイント | 区別が無い | **区別がある**。書き分けを強制（下記） |
| 出典表記 | Streaming Availability API | **U-NEXT の作品ページ＋基準日**（`attribution-unext`） |

**素材は `kind: expiring` かつ当月かつ `lineup` が `svod` / `both` のもの。**
ポイント専用作品を落としているのは、**そもそも見放題ではなかった作品を
「見放題が終わる」と書くことになる**から。

- **現行の `leaving` は Netflix と Prime Video の2社しか書けない**（他社が終了予定を返さない）。
  U-NEXT は単独で成立する。2026-08 の実測で `--service u-next` は素材80件
  （Prime Video は2件で「素材不足」だった月）
- 「今月で消える」は読者の行動を促す最強の文脈で、しかも**全行が U-NEXT への導線**になる

#### 「観られなくなる」と書かせない仕組み

**「見放題終了」であって「配信終了」ではない。** U-NEXT はポイント（レンタル・購入）が
同居するので、見放題が終わっても残る作品がある。ここを取り違えると読者を直接裏切るため、
3か所で止めている。

1. **素材の段階** — ポイント専用作品を `select()` で落とす
2. **指示の段階** — 「観られなくなります」「配信が終了します」を明示的に禁止し、
   ポイントで残る作品には `★見放題は終了するが、ポイントでの取り扱いは続く` を素材に付ける
3. **検査の段階** — `UNAVAILABLE_CLAIM` に当たる表現があれば **error にして公開を止める**
   （`shared.ts` の `MISLEADING_AFTER_END` と同じ考え方）

> この検査は `hasLineup` のサービスにだけ効かせている。
> Netflix / Prime Video の見放題終了はサービスからの退出そのものなので、
> 同じ言い回しでも誤りにならない。一律にすると正しい記述まで止まる。

#### 「他のサービスで探す」から自分自身を外す

U-NEXT の配信終了記事に U-NEXT の検索リンクを並べても意味がないので、
**記事自身のサービスは `search_links` から除外**する。
U-NEXT の記事では Hulu と DMM TV だけが並ぶ。

「◯◯で配信中」と断定していないかの検査も、対象は**記事のサービス以外**にした。
U-NEXT の記事で「U-NEXTで配信中」と書くのは事実なので、一律に禁じてはいけない。

### B. U-NEXT 今月の新規入荷（ジャンル別）🔶 素材待ち

現行の `arrivals` の U-NEXT 版。洋画 / 邦画 / 海外ドラマ / 韓流・アジア / 国内ドラマ / アニメ。

- 現行はジャンルを原語と原題から機械推定していて、**判定できない作品は記事に出していない**。
  U-NEXT は公式ジャンルが付いてくるので、捨てる作品が出ない
- 実測: 新着513件（洋画90・邦画84・音楽83・韓流55・TV45・アニメ43 …）

**まだ作れない。** `arrivals` は配信開始日順に書く記事だが、
U-NEXT の新着513件のうち**配信開始日を持つのは120件だけ**（作品ページの予算切れ）。
`unext:refresh` を数回まわして日付が揃ってから着手すること。
日付の無い作品を並べると、記事の軸そのものが成立しない。

### C. 常設ページ ⚠️ 作る前に形を決めること

既存の `/leaving/…` `/arrivals/…` と同じ作りにすれば、作品台帳から直接引けて
ビルドのたびに最新化できる。**が、そのまま同じ形にするのは勧めない。**

**危ないのは「常設かどうか」ではなく「データベースの代わりになっているかどうか」。**
規約で効くのは第25条(23)「本サービスを利用して**第三者に新たなサービスを提供する行為**」で、
記事か常設ページかは条文のどこにも出てこない。問われるのは機能のほうになる。

| 危険side | 安全side |
|---|---|
| カタログを網羅する | **その月に終わる作品だけ**など、範囲を切る |
| 全文検索・絞り込み・並べ替えを持つ | 読み物として並べる。検索機能を付けない |
| 常に同期して最新 | **基準日を明示した断面**にする |
| CSV/JSON で持ち出せる | 出力手段を持たない |
| 解説が無く表だけ | 記事としての文章がある |
| U-NEXT へ戻る導線が無い | 全行から U-NEXT の作品ページへ送る |

左に寄るほど「U-NEXT の代わりに使えるカタログ検索サービス」になり、(23) に近づく。
右に寄るほど「U-NEXT へ送る読み物」になる。

> **事実に著作権が無いことは、この問題の答えにならない。**
> データベースは、素材が事実でも**選択・体系的な構成**に創作性があれば著作物になる
> （著作権法12条の2）。創作性が無い場合でも、**まるごと複製して競合的に使う行為が
> 不法行為（民法709条）にあたる**とした裁判例がある（翼システム事件・東京地裁 2001）。
> 「facts は自由」で通せるのは1件ずつ引用する場合で、丸ごとの写しは別の話になる。

**方針: 作るなら「今月見放題終了（{基準日}時点）」のような期間で切った1枚にとどめる。**
既存ページと同じページ内ジャンプの検索窓は付けてよい（下記のとおり、あれは
ページに出ている以上の情報を提供しない）。付けてはいけないのは
**カタログ全体を積み上げていくこと**と、JSON/CSV での持ち出し口。

作品台帳（`data/unext-titles.json`）は回を追うごとに育つので、
**常設ページがそれをそのまま出すと、意図せずカタログの写しに近づいていく。**
ページに出す範囲は台帳の中身ではなく「その月に終わるもの」で切ること。

#### 既存の `/leaving/netflix` などは問題ない（2026-08-25 再調査）

一度「同じ物差しが当たるので見直す価値がある」と書いたが、**それは行き過ぎだった。**
[TERMS.md](https://github.com/movieofthenight/streaming-availability-api/blob/main/TERMS.md)
の原文を読み直すと、禁じているのは B2B の再配布に限られている。

> The API User shall use the streaming availability data provided by The API Provider
> **only for its application and/or websites' end-users, and consumers.**
> The API User shall not reshare/resell/redistribute the streaming availability data
> provided as part of this API, **to other businesses or platforms** in any way,
> including but not limited to: offering APIs, offering access to databases,
> and offering data exports.

**「自分のサイトの読者に見せること」が、まさに許可されている使い方。**
禁止されているのは他の事業者・プラットフォームへ渡すことで、当サイトはどれもしていない。

検索窓についても実装を確認した。**あれは「検索」ではなく「ページ内ジャンプ」。**
すでにHTMLに描画済みの行を絞り込んで `scrollIntoView` するだけで、
問い合わせも取得も行わず、行を隠しもしない（`WorkSearch.astro`）。
ページに出ている以上の情報を1件も提供していない。
ビルド成果物に JSON も出していない（`dist` にあるのは RSS とサイトマップだけ）。

規模も誤解していた。`/leaving/netflix` は約117行、`/arrivals/netflix` は約218行で、
これは**収集した「変化」のログ**であってカタログの写しではない。

**つまり、危険を分けるのは検索窓ではなく「カタログをどれだけ再現しているか」。**
U-NEXT で常設ページを作る場合も、判断すべきなのは検索窓の有無ではなく、
月ごとに範囲を切った断面にとどめるかどうかになる。
