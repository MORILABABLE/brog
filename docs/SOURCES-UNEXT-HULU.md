# U-NEXT / Hulu の更新作品を自動取得できるか（調査）

調査日: 2026-08-24 ／ すべて実測（推測は「未確認」と明記）

[AFFILIATE.md の Phase F](./AFFILIATE.md#phase-f--u-next--hulu-の更新情報を照会するページ優先度低) の
「完全自動化はできないが更新情報を察知したい」に対する回答。

---

## 0. 結論

| | 自動取得 | 判断 |
|---|---|---|
| **U-NEXT** | **できる。現行パイプラインとほぼ同等のものが作れる** | **進めてよい**（規約の人力確認が前提） |
| **Hulu** | 技術的にはU-NEXTより簡単だが、**利用規約が自動アクセスを明示的に禁止** | **やらない**。検索リンクのまま |

**U-NEXT に寄せるのが唯一の現実解で、しかも都合がいい。**
ASP単価も U-NEXT 1,320円 > Hulu 917円 で、諦める側のほうが安い（[AFFILIATE.md 3節](./AFFILIATE.md)）。

さらに重要な点として、U-NEXT から取れるデータは
**いま Streaming Availability API から取っているものより質が高い**（4節）。
「代替手段」ではなく「格上げ」になる。

## 2. U-NEXT — 取れる

### 2.1 robots.txt（全文・2026-08-24）

```
User-agent: *
Disallow: /realtime/
Disallow: /play/
Disallow: /live/
Allow: /live/browse
Disallow: /book/view/
Disallow: /series/
Disallow: /_internal/
```

**必要な `/browse/` と `/title/` はどちらも許可されている。** 禁止は再生系と内部APIのみ。

### 2.2 「新規入荷作品」は公式カテゴリとして存在する

各ジャンルの配下に **`新規入荷作品`** というカテゴリがあり、
既定のソート順が `PUBLIC_START_DESC`（配信開始日の新しい順）に設定されている。
つまり**「更新作品一覧」を自前で組み立てる必要がない。U-NEXT が最初から用意している。**

```
https://video.unext.jp/browse/genre/{ジャンルID}/{カテゴリID}/{ページ}?order={ソート}
```

| ジャンル | ジャンルID | 新規入荷作品ID | 実測件数 |
|---|---|---|---|
| 洋画 | MNU0000131 | **MNU0000692** | 169件（6ページ） |
| アニメ | MNU0000136 | **MNU0000769** | 62件（3ページ） |

ジャンルは `https://video.unext.jp/search/top` に全件ある（映像は11ジャンル）。

```
洋画 / 邦画 / 海外ドラマ / 韓流・アジア / 国内ドラマ / アニメ / キッズ /
TV番組・エンタメ / 報道・スペシャル / 音楽・ライブ / 舞台・演劇
（ほかにスポーツ7・書籍4）
```

**1ページ30件固定。** 全ジャンルを1周しても 40〜60リクエスト程度で、頻度の制約はない。

### 2.3 ソート順（URLの `order=` パラメータ）

アプリのコードから確定させた対応表。

| `order=` | 意味 |
|---|---|
| `popular` | 人気順（既定） |
| `public_start_desc` | **配信開始日の新しい順 → 新着記事の素材** |
| `public_end_asc` | **配信終了日の近い順 → 配信終了予定記事の素材** |
| `production_year_desc` / `_asc` | 製作年 |
| `alpha_asc` / `alpha_desc` | 五十音 |

**`public_end_asc` が存在するのが大きい。**
現行APIでは配信終了予定が Netflix と Prime Video の2社しか返らない（[README](../README.md)）が、
U-NEXT は自前で終了日を持っていて、それで並べ替えられる。

### 2.4 一覧で取れるフィールド

一覧ページのHTMLに Apollo のキャッシュ状態が埋まっており、そこから取れる。

```json
"Title:SID0285889": {
  "id": "SID0285889",
  "titleName": "転生したらスライムだった件 第4期",   ← 最初から日本語
  "isNew": true,
  "catchphrase": "譲れない思いを胸に、リムルの次なる戦いが始まる。",
  "rate": 45,
  "updateOfWeek": 6,
  "lastEpisode": "第91話配信中",
  "productLineupCodeList": ["LNPS_SVOD"],          ← 見放題 / ポイントの判別
  "isOriginal": false,
  "exclusive": { "isOnlyOn": false }
}
```

| コード | 意味 |
|---|---|
| `LNPS_SVOD` | **見放題** |
| `LNPS_VOD` | ポイント（レンタル・購入） |

新規入荷カテゴリの実測構成比は 洋画 28:2、アニメ 24:6 で、大半が見放題。
**「見放題が終わる」と「レンタルなら残る」を書き分けられる**ので、
`leaving` / `ended` の区別（[README](../README.md)）と同じ規律をU-NEXTでも守れる。

### 2.5 作品ページで取れるフィールド

`https://video.unext.jp/title/{SID}` に `TitleStage` オブジェクトがあり、**日付が入っている**。

```json
{
  "titleName": "劇場版 名探偵コナン 100万ドルの五稜星（みちしるべ）",
  "publicStartDate": "2026-03-27T15:00:00.000Z",
  "displayPublicEndDate": "2026年8月31日 23:59まで配信",   ← ★
  "productLineupCodeList": ["LNPS_SVOD"],
  "productionYear": "2024",
  "country": "",
  "mainGenreName": "アニメ",
  "seriesName": "名探偵コナン",
  "story": "…あらすじ…",
  "copyright": "…"
}
```

**見放題（`LNPS_SVOD`）の作品にも終了日が入る**ことを3件で確認した
（名探偵コナン劇場版2本・恐竜探険隊ボーンフリー が 2026年8月31日 23:59 見放題終了）。
ポイント作品だけの情報ではない。

> `displayPublicEndDate` は **表示用の文字列**で ISO 日付ではない。
> `datetime.ts` に渡す前にパースする層が要る。書式が変わると静かに壊れるので、
> パースできなかったものは記事に出さない（捏造しない）方針にすること。

### 2.6 取得手段 — ヘッドレスブラウザを使う

**U-NEXT は検索エンジンのUAにだけサーバー側で中身を描画する。** 実測:

| User-Agent | `isBot` | 作品データ |
|---|---|---|
| Chrome | false | **0件**（空の器だけ） |
| curl / 空 / 自称ボット | false | **0件** |
| Googlebot | true | 30件 |
| bingbot | true | 30件 |

つまり **UAを変えるだけの軽い取得はできない。** 選択肢は2つ。

| 方法 | 評価 |
|---|---|
| **ヘッドレスブラウザ（Playwright等）で普通に開く** | ✅ **これを採る。** ただのブラウザなので身分を偽らない。robots.txt も守れる |
| Googlebot を名乗る | ❌ **採らない。** 検索エンジンだと偽ることになる。ブロックされたら終わりでもある |

> **調査中の実測には Googlebot のUAを使った**（合計20リクエスト程度）。
> 事実確認のための最小限で、本番の取得方式としては採らない。

GraphQL を直接叩く道は塞がれている。実測:

```
POST https://cc.unext.jp/
→ 403 {"code":"QUERY_NOT_IN_SAFELIST",
       "message":"The operation body was not found in the persisted query safelist"}
```

アプリが送る問い合わせだけを通す仕組み（persisted query safelist）なので、
こちらで組み立てた問い合わせは通らない。**ブラウザで開くのが唯一の道。**

### 2.7 コスト

| | |
|---|---|
| 追加の課金 | **なし**（APIキー不要・無料枠という概念がない） |
| 依存 | Playwright + Chromium（CIで `npx playwright install chromium`） |
| 1周のリクエスト数 | 40〜60（新着のみ）／ 終了予定を作るなら作品ページ分が追加 |

## 3. Hulu — 技術的には取れるが、規約で不可

### 3.1 利用規約が自動アクセスを明示的に禁止している

[Hulu利用規約](https://www.hulu.jp/static/legal/terms/) 第3条(3):

> 「ロボット」、「スパイダー」又は「オフラインリーダー」を含む自動化された手段によって
> Hulu見放題サービス（本コンテンツを含みます）にアクセスすること

検索エンジンの一般的なインデックス作成だけが例外として認められている。
**当サイトの収集はこの例外に当たらない。**

### 3.2 robots.txt も一般のクローラを締め出している

```
User-agent: *
Allow: /browse
Disallow: /
```

作品ページ（`https://www.hulu.jp/{slug}`）も新着ページ（`/features/…`）も
`/tiles/genres/…` も、**すべて `*` に対しては禁止**。
`Allow: /` が付くのは Googlebot・bingbot 等の名指しされたクローラだけ。

**規約と robots.txt が同じことを言っている以上、判断の余地はない。**

### 3.3 参考: 技術的には何が取れたか（採らないが記録する）

将来ライセンスを取れた場合や、判断を見直すときのために残す。
**皮肉なことに Hulu のほうが U-NEXT より簡単で、データも整っている。**

- **サイトマップ**: `https://www.hulu.jp/static/sitemaps/sitemap.xml.gz`（5分割・241,683 URL）
  - うち作品スラッグ **14,369件**、人物 70,963件、コミック 152,281件
  - `lastmod` は全件 `1970-01-01` で**使えない**。差分は自前で取る必要がある
- **一覧ページのSSRペイロード**に作品情報が丸ごと入っている（Next.js の RSC）

  ```json
  { "name": "転生したらスライムだった件 第4期…", "slug": "ten-sura",
    "startAt": "2026/07/09 00:00:00", "endAt": "2028/06/30 23:59:59",
    "rental": false, "categoryMetas": ["アニメ","ファンタジー","アドベンチャー"],
    "additionalInfo": { "card_info": { "episode_count": 103, "premiere_year": 2018 } } }
  ```

  **配信開始日と終了日が生の日付で入っている。** U-NEXT のような表示用文字列ではない。
- **公式の新着・終了予定ページが揃っている**
  - 新着: `/features/recentlyadded-anime`, `/features/recently-added-japanese-series`, `/features/recently-added-tv`
  - 配信予定: `/features/comingsoon`
  - **もうすぐ終了予定: `/features/9ba25345-56d6-43de-a0e5-1610a37139a8`** — 50件が `endAt` 付きで並ぶ

**取れるのに取らない。** この結論は技術ではなく規約から来ている。

### 3.4 U-NEXT との差はどこにあるか

|  | U-NEXT | Hulu |
|---|---|---|
| robots.txt | `/browse/` `/title/` を**許可** | `*` には `/browse` 以外**禁止** |
| 規約の自動アクセス条項 | **未確認**（5節） | **明示的に禁止** |

同じ「スクレイピング」でも立場がまったく違う。混ぜて考えないこと。

## 4. U-NEXT に寄せると、いまより何が良くなるか

現行パイプラインの弱点が、そのまま解消する。

| 現行（Streaming Availability API） | U-NEXT |
|---|---|
| タイトルが英語。Wikidata で邦題を引いて**解決率73%**、残りは原題のまま | **最初から邦題**。解決率の概念がなくなる |
| ジャンルは原語と原題から機械推定。**判定できない作品は記事に出さない** | **公式ジャンルがそのまま付いている**。捨てる作品がなくなる |
| 配信終了予定は Netflix と Prime Video の**2社だけ** | 終了日を持っていて、それで並べ替えもできる |
| 無料枠 500req/月。週2回が上限 | 枠の概念がない |
| 「U-NEXTで配信中」と**言えない**ので検索リンク止まり | **作品ごとにアフィリエイトのディープリンクを、裏付け付きで貼れる** |
| 帰属表示が義務（各記事に出典表記） | 提供元表記の義務はない（かわりに規約確認が要る） |

記事タイプの対応:

| 現行 | U-NEXT版 | 素材の取り方 |
|---|---|---|
| `arrivals` | U-NEXT 今月の新規入荷 | 新規入荷作品カテゴリを全ジャンル巡回 |
| `leaving` | U-NEXT もうすぐ見放題終了 | `order=public_end_asc` で並べ、上位の作品ページから終了日を取る |
| `ended` | **不要になる** | 終了日が事前に取れるので、事後まとめを作る理由がなくなる |

**収益面の意味が現行と逆転する。**
いまは「データがある4社のうち金になるのはAmazonだけ」（[AFFILIATE.md 3節](./AFFILIATE.md)）だが、
U-NEXT はデータも単価（1,320円）も揃う。記事の全行がアフィリエイト面になる。

> **ただし [AFFILIATE.md 7節](./AFFILIATE.md#7-運用上の注意) の規律は守ること。**
> 「紹介料の高いサービスを優先して掲載しない」と書いてプライバシーポリシーにも明記した。
> U-NEXT単独のサイトにするなら**それはサイトの主題であって掲載順の操作ではない**、
> という整理が要る。既存記事に U-NEXT を混ぜて優遇するのは別問題で、これはやらない。

| | 内容 |
|---|---|
| ⚠️ **U-NEXT の利用規約** | 2026-08-24 に人力で確認した。**スクレイピング・ロボット・クローラを名指しする条項は無い**（Hulu との決定的な違い）。ただし判断は 5.1 の受け皿条項に移る |
| ⚠️ ASPの規約 | U-NEXT案件の提携条件に、掲載方法の制限がないか（バリューコマース / afb / Link-A） |
| 「新規入荷作品」の窓 | 何日分を保持するカテゴリなのか未検証。週2回の巡回で取りこぼさないかは、2週間ほど回して確かめる |
| `displayPublicEndDate` の書式 | 「2026年8月31日 23:59まで配信」以外の書式があるか未検証（未定・期間未定など） |
| Playwright の導入 | 依存とCI時間が増える。GitHub Actions で Chromium を入れる時間の実測がまだ |
| アクセス頻度 | 週2回・1回50前後を想定。相手のサーバーに対する礼儀としてレート制限を入れる |
| Hulu | ライセンス取得型（TMDB商用 $149/月）以外に道はない。案件として予算が付いたときだけ再検討 |

### 5.1 U-NEXT 利用規約の読み方（2026-08-24）

**スクレイピングを名指しする条項は無かった。** ただし「書いていない＝許可」ではないので、
効いてくる条項を特定しておく。第25条の禁止行為のうち、関係するのは次の5つ。

| 条項 | 効き方 |
|---|---|
| (7) 当社のサーバーに過度の負担を及ぼす行為 | **こちらで制御できる唯一の項目。** レート制限で守る |
| (9) 本来のサービス提供目的とは異なる目的で利用する行為 | 受け皿条項。広く読める |
| (23) 本サービスを利用して第三者に新たなサービスを提供する行為 | **データをAPI・DB・検索機能として再提供すると当たる。記事として書くだけなら当たらない** |
| (25) 営利目的か否かに問わず、**本コンテンツ**を用いて事業を行う行為 | **ここが分岐点**（下記） |
| (26) **本コンテンツ**の二次的著作物やベースとした素材を作成する行為 | 同上 |

**判断は「本コンテンツ」の定義ひとつで決まる。**

- 定義が「本サービスで提供される映像・音声・電子書籍等の**作品**」なら
  → 作品名や配信日といったメタデータは含まれない → (25)(26) は当たらない
- 定義が「本サービス上で提供される**一切の情報**」型なら
  → メタデータも含む → (25) に正面から当たる → **止める**

(24) が「…その他コンテンツの**著作権を侵害する**全ての行為」で締められていることから、
本コンテンツ＝著作物（作品そのもの）を指す読み方のほうが自然だが、**定義条項の確認が要る。**

#### 著作権法のレイヤーは別で、こちらはむしろ有利

規約（契約）とは別に、著作権の問題がある。**取るものを分ければリスクは大きく下がる。**

| | 例 | 扱い |
|---|---|---|
| **事実** | 作品名 / SID / 配信開始日 / 配信終了日 / 見放題かポイントか / 公式ジャンル | 著作物ではない。**取ってよい** |
| **表現** | `catchphrase` / `story`（あらすじ）/ `attractions` / サムネイル画像 | 著作物。**取らない・載せない** |

**この線引きは現行パイプラインの規律と同じもの**（frontmatter は収集データから機械的に組み立て、
本文は LLM に書かせる／日付や出典を LLM に任せない）。新しく我慢するものは何もない。

#### 実装に落とすときの4つの制約

1. **取得するフィールドを事実だけに絞る**（上表）。`catchphrase` / `story` は収集コードで捨てる
2. **レート制限を設計に入れる。** 1リクエストにつき2〜3秒、週2回、1回50前後。
   User-Agent に連絡先を書き、429 / 503 を受けたら即停止する
   — 岡崎市立図書館事件（2010）は規約違反ではなく**負荷**で刑事事件になった実例
3. **データを再提供しない。** 記事とページとして出すだけ。API・DB・作品検索機能は作らない（(23)）
4. **配信終了日は変わる。** 「変更される場合があります」を明記し、断定しない

#### 白黒つけに行くべきか

**U-NEXT に直接問い合わせるのは勧めない。** 聞けば断られやすく、断られた事実が残る。
現実的な順序は **ASP（バリューコマース / afb / Link-A）の提携申請を先に通すこと**で、
申請時にサイトを審査されるため、通れば掲載形態について事実上の承認が得られる。

## 6. 進めるなら（実装の順番）

規約が白だった場合の最短経路。**パイプラインの構造は変えなくてよい。**

1. `pipeline/sources/unext.ts` を足す（`sources/types.ts` の `Work` に合わせて返す）
   — 収集・台帳・差分・通知・執筆はテーマ非依存なので**無改修で動く**
2. `theme-packs/streaming-unext/` を作る（`theme.yaml` にジャンルIDとカテゴリIDの表を持たせる）
3. `data/ledger.json` の重複除外はそのまま流用する
   — **U-NEXT は「いつ入荷したか」を一覧で返さないが、台帳の差分が「前回以降の新着」になる。**
     これは現行の設計がそのまま効く部分で、作り直す必要がない
4. 邦題解決（Wikidata）とジャンル推定は**U-NEXTテーマでは呼ばない**
5. 記事テンプレートは `templates/` に1本足すだけ（[README](../README.md) の手順どおり）

# GraphQL は通らないことの確認
