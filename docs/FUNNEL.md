## 1. 測り方

```bash
npm run analytics                # 直近28日
npm run analytics -- --days 90   # 期間を変える
npm run analytics -- --write     # data/analytics.json に落とす（.gitignore 済み）
```

`pipeline/cli/analytics.ts`。Search Console と GA4 を**1本のファネル**に並べる。
既存の `npm run queries` とは口を分けてある（あちらは記事に焼き込む素材、こちらは判断材料）。

- 認証は `queries.ts` と同じサービスアカウント（`secrets/gsc.json`）
- **GA4 側にも権限が要る** — 管理 → プロパティのアクセス管理 → サービスアカウントを「閲覧者」で追加
- `.env` の `GA4_PROPERTY_ID`（管理 → プロパティの詳細 の数字）

> ★ **Search Console のデータは 2026-08-29 から**しか無い。プロパティの登録がその時期。

## 3. 詰まり① — 面の89%が「終わった」ページになっている

> **この節は 2026-09-06 の「変更前」の記録。** 対処は 7-1（実施済み）。
> **数字を書き換えないこと** — 効果を測るときの基準値になる。

**`site/dist/works/*.html` の `<title>` を全部数えた結果。**

| タイトルの型 | 枚数 | 割合 |
|---|---|---|
| 「◯◯」の見放題配信は**終了しました** | **459** | **89%** |
| 「◯◯」（◯年）は**いつまで見られる？** | 58 | 11% |
| 合計 | 517 | |

さらに、その58枚の終了予定日を見ると:

| 終了予定日 | 枚数 | |
|---|---|---|
| 2026-08-09 〜 09-05 | **30** | **もう過ぎている**。「いつまで見られる？」と書いてあるのに答えが古い |
| 2026-09-06（当日） | 1 | |
| 2026-09-07 〜 09-29 | 27 | まだ有効 |

**517枚のうち、いま「まだ観られる・◯日まで」と言えるのは28枚（5.4%）。**

### 3-1. なぜこれが効くのか

読者が打っている語は「スリザー **配信**」「その女諜報員アレックス **どこで見れる**」——
**「観たい。どこで観られる？」**という意図。

これに対して検索結果に出ている見出しはこう:

```
×  「スリザー」の見放題配信は終了しました
```

**答えではあるが、読者が求めている答えではない。** クリックする理由が無い。

そして踏んだ先も同じことしか書いていない。実際のページ（`/works/5346`）はこうなっている:

| 位置 | 出しているもの |
|---|---|
| h1 | 「スリザー」の見放題配信は終了しました |
| 状態 | Amazon Prime Video で 2026年8月14日に見放題配信が終了しました |
| ボタン | **「Amazon Prime Videoで見る」** ← 直前に「終了した」と書いた相手への導線 |
| 他社 | U-NEXT / Hulu / DMM TV の**検索結果に飛ぶだけ**（あるかどうかは保証しない） |
| CTA | 「見放題での配信は終了していますが、レンタル・購入なら観られる場合があります」 |

**「じゃあ今どこで観られるのか」に、このページは一度も答えていない。**

### 3-2. 順位のせいではない。**タイトルのせい**である

「作品ページのCTRが低いのは順位が低いからでは」を潰すために、**順位帯を揃えて比べた。**

| 順位帯 | 種類 | ページ | 表示 | クリック | CTR |
|---|---|---|---|---|---|
| **4〜10位** | **記事** `/posts/*` | 13 | 233 | 23 | **9.9%** |
| **4〜10位** | **作品ページ** `/works/*` | 87 | 309 | 9 | **2.9%** |
| **4〜10位** | 常設一覧 `/leaving/*` `/arrivals/*` | 4 | 159 | 5 | 3.1% |
| 1〜3位 | 作品ページ | 8 | 13 | 4 | 30.8% |
| 11位以下 | 作品ページ | 40 | 90 | 0 | 0.0% |

**同じ順位帯で、作品ページは記事の 1/3.4 しかクリックされていない。**
順位の差では説明できない。差はタイトルが見せている答えの側にある。

そして 1〜3位に入った作品ページは **CTR 30.8%** を出している（8ページ・母数は小さい）。
**ページの型が悪いのではなく、いま出している答えが悪い。**

### 3-3. 放っておくと比率は悪化する

`expiring`（終了予定）は毎月 `removed`（終了済み）に変わる。
新しい終了予定が入ってこなければ、**「いつまで」ページは自動的に「終了しました」ページになる。**
いま 89% の側は、来月には 92%、その次は 95% になる。

★ **これは記事側の `/refresh` と同じ問題だが、作品ページには同じ仕組みが無い。**
記事は事実がずれたら書き直す運転があるのに、517枚の作品ページには無い。

## 5. 詰まり③ — 外部リンククリックが 3.3%

**ここが目標に対していちばん遠い。**

| | 90日（全ホスト） | 直近8日（本番のみ） |
|---|---|---|
| PV | 288 | 212 |
| 外部リンククリック | **8** | **7** |
| PVに対する率 | **2.8%** | **3.3%** |

内訳は `amazon.co.jp` 5 / `video.unext.jp` 2 / `netflix.com` 1（90日）。
**成果は0件**（[AFFILIATE.md](./AFFILIATE.md) の実績と一致）。

**流入が4倍に増えた直近8日でも、外部クリックは7件。率は動いていない。**
流入が増えれば自然に踏まれる、という形にはなっていない。

### 5-1. 3つの枠が、全部いちばん弱い行き先を指している

作品ページには Amazon への導線が3か所ある（`work` / `cta` / `bar` でIDは分けてある）。
**3つとも行き先が同じで、しかも Amazon の検索結果ページ。**

```
状態ボタン  → amazon.co.jp/s?k=スリザー&i=instant-video&tag=jetbike-work-22
本文CTA     → 同上（tag=jetbike-cta-22）
追従バー    → 同上（tag=jetbike-22）
```

- **見放題が終わった作品**を Amazon で検索させている。読者が探しているのは見放題
- 作品ページ（`/gp/video/detail/…`）ではなく**検索結果**なので、読者があと1回選ぶ必要がある
- 成立しても報酬はビデオのレンタル/購入紹介料。**Prime無料体験 500円/件には繋がらない**

枠を3つに増やしても、**3つとも同じ弱い行き先なら踏まれる数は増えない。** 実測がそう出ている。

### 5-2. U-NEXT の作品別リンクは、提携が通っても成果にならない

ガイドライン【5】が **LP限定**（[AFFILIATE.md 12-1](./AFFILIATE.md)）。
いま作品ページに出ている

```
https://video.unext.jp/freeword?query=スリザー   ← 「U-NEXTで探す」
```

は、提携が通ったあとも**成果が却下される形**。90日で2クリック出ているが、
**この2件は通っていても0円だった。**

★ **提携が通った日に、この形のリンクを増やしてはいけない。**
U-NEXT は単価1,320円で最有力なので、**LPへの導線を別に用意する**のが正しい。

### 5-3. 枠別の実測が取れていない

GA4 の `click` は拡張計測（`outbound: true`）で自動に取れているが、
**どの枠から出たのかは分からない**。Amazon 側でトラッキングIDを分けてあるが、
**成果が0なのでアソシエイトのレポートは何も返さない**（クリック数は成果が出るまで見えない）。

いま `data-affiliate="true"` は付いているので、**枠名を持ったカスタムイベントを1本足せば**
「追従バーは踏まれているのか」「記事末尾のCTAは到達されているのか」が分かる。

参考: **スクロール90%到達は 64件 / 288PV = 22%。**
**ページ下部のCTAは8割の読者に見られていない。**

## 6. 目標までの算数

目標は **1日100人・月3,000人・アフィリエイト収益 月1〜2万円**。

### 6-1. 流入

| | いま | 目標 | 倍率 |
|---|---|---|---|
| 検索クリック（GSC・Googleのみ） | 7.5/日 | 100/日 | **13.3倍** |
| 検索ユーザー（GA4・Yahoo!/Bing含む） | 11.5/日 | 100/日 | **8.7倍** |

以下は GSC 側（13.3倍）で計算する。**厳しいほうで見ておく。**

13.3倍は2つに分解できる。

| 分解 | |
|---|---|
| **CTR** 5.2%（4〜10位）→ 31.3%（1〜3位） | **6.0倍** |
| 残り（表示回数を増やす） | **2.2倍** |

**順位を上げるほうが、面を増やすより効率が良い。**
いま 114ページが 4〜10位に居て、そこに表示の91%がある。
**新しいページを作るより、そのページ群の答えを直すほうが早い。**

### 6-2. 収益

月3,000人 × 1.33 PV/セッション ≒ **月4,000PV**。

| | 必要な数 |
|---|---|
| 月1.5万円（U-NEXT 1,320円/件） | **11.4件** |
| クリック→成果 を 2% とすると（**未検証の仮定**） | **570クリック/月** |
| 月4,000PV に対する必要な外部クリック率 | **14.3%** |
| いまの外部クリック率 | **3.3%** |
| 必要な倍率 | **4.3倍** |

> ★ **「クリック→成果 2%」はこのサイトの実測ではない**（成果が0件なので出しようがない）。
> VOD無料体験の一般的なレンジ（1〜3%）から置いた仮定。
> `npm run afb` が成果を返すようになったら、**まずこの数字を実測に置き換えること。**
> 2% が 1% なら必要なクリックは倍になり、結論（クリック率を上げないと届かない）は強まる。

**流入13倍と、外部クリック率5倍。両方要る。片方だけでは届かない。**

### 6-3. ★ Amazon だけでは目標に届かない（計算で出る）

同じ 570クリック/月 を Amazon（Prime無料体験 500円/件）だけに流した場合、
成果率を 1.5% と置くと **8.6件 = 約4,300円/月**。

同じ570クリックを送ったとき、送り先で月収がこれだけ変わる。

| 送り先 | 単価 | 置いた成果率 | 月4,000PV・外部クリック14.3% のときの月収 |
|---|---|---|---|
| Amazon（Prime無料体験） | 500円 | 1.5% | **約4,300円** |
| U-NEXT（afb） | 1,320円 | 2% | **約1.5万円** |
| DMM TV（afb） | 1,691円 | 2% | 約1.9万円（[5-3 で当面見送りと判断済み](./AFFILIATE.md)） |

> ★ **Amazon だけ成果率を低く置いている**（1.5%）。無料体験の申込みが成果条件なのに、
> 送り先が**ビデオの検索結果**で、そこに「Prime に入る」導線が無いため。
> **どれも未検証の仮定。** 順位は変わらないが、絶対額は実測で置き換えること。

**目標1〜2万円は、U-NEXT の提携が通ることが前提になっている。**
これは営業の問題であって実装の問題ではない。
**通るまでの間に外部クリック率を上げておくこと**が、通った日の収益をそのまま決める。

AdSense を足しても計算は変わらない。月4,000PV × RPM 300〜600円 = **月1,200〜2,400円**。
**主役にはならない**（補助としては入れてよい）。

## 7. 施策（着手順）

**1つずつ出す。** 3-2 の切り分けができたのは順位帯を揃えて比べたからで、
同じ週に複数出すとその比較ができなくなる。

### 7-2. 常設ページの `<title>` を検索語に寄せる

> **✅ 2026-09-06 実施。** 実装は `site/src/lib/evergreen.ts` の `evergreenTitle()`。

```
×  【2026年9月1日時点】Netflixで配信終了予定の作品一覧
○  Netflixで見放題配信が終了する作品一覧【9月1日更新】
```

| 変えたこと | なぜ |
|---|---|
| 日付を**頭から末尾へ** | スマホの検索結果は全角30文字前後で切れる。頭に日付があると、読者が最初に読むのが「2026年9月1日時点」になり、**サービス名も「終了」も押し出される** |
| **「時点」→「更新」** | 9月中旬に「9月1日時点」を見ると古い情報に見える。同じ日付でも「更新」は手入れの新しさを名乗る。左の枠（`evergreenStamp`）が最初から「更新」だったので、そちらへ揃えた |
| 年を落として `【9月1日更新】` | 常設ページの基準日は必ず直近の収集日で、年をまたがない |
| **「見放題」を入れた** | レンタル・購入と区別する言葉が、この一覧のタイトルには無かった（記事タイトルの決まりと同じ理由。`templates/naming.md`） |

**素のタイトルも `evergreen.ts` の1か所に集めた**（`evergreenTitleBase()`）。
以前は `EVERGREEN_PAGES` と `pages/leaving/[service].astro` の**両方**に同じ文字列があり、
片方だけ直すと**同じページがカードと見出しで別の名前を名乗る**状態だった。

実際に出ているタイトル:

#### freeword リンクをどうするか（2026-09-06 の判断）

**問い1: `freeword` リンクを U-NEXT の収益に繋げられるか → 不可能。**

|---|---|---|

#### 問い3: 従来のリンクの位置に afb のポップアップを出すか → **出さない**

理由は4つ。**どれか1つでも十分だが、4つとも当たっている。**

| | |
|---|---|
| **検索順位** | Google は**本文を覆う挿入（intrusive interstitial）を順位で不利に扱う。** いまサイトの生命線は検索流入（9.3人/日）で、そこを削る施策は本末転倒 |
| **AdSense** | 審査中のサイトでインタースティシャルは不利に働く。10節の判断（この枠は AdSense を優先する）と衝突する |
| **JSゼロ方針** | サイトのJSは `WorkSearch` と追従枠のトグルだけに閉じてある（[GROWTH 3-6](./GROWTH.md)）。ポップアップは開閉と再表示抑止の状態管理が要る |
| **afb 側** | リンクコードの改変が許されているのは `rel="sponsored"` までと確認済み（11-3）。包むこと自体は改変ではないが、**誤クリック誘導**と見なされる余地を残す |

**代わりにやったこと（2026-09-06）: 位置を直した。**

`pages/works/[id].astro` の `UnextCta` には
「**『他のサービスで探す』のすぐ後ろに置く**」と注意書きがあるのに、
**実際は間に `AmazonCta` が挟まっていた。** 注意書きどおりの順に直した。

```
変更前   他のサービスで探す → AmazonCta → UnextCta
変更後   他のサービスで探す → UnextCta → AmazonCta
```

**成果にならない `find` のクリックの、すぐ隣に成果になる導線を置く。**
ポップアップで割り込まなくても、**意図が最も高い位置に置けば同じ仕事をする。**
単価も U-NEXT 1,320円 に対して Amazon は数十円（[AFFILIATE 3-0-1](./AFFILIATE.md)）なので、
順番としてもこちらが先。

## 8. 計測の汚れ（2026-09-06 に調べて対処）

### 8-0. やったこと — レポートの側でホスト名を絞った

`npm run analytics` が **GA4 のすべての問い合わせに本番ホストの条件を掛ける**

既定は `GSC_SITE_URL` のホストとその `www` 版。`.env` の `GA4_HOSTS` で上書きできる。

**外した内訳も必ず出す。** 隠すと「外した判断そのもの」が検証できなくなる。

```
  入     20セッション    23PV  エンゲージ  40.0%  www.mihoudairader.com
  外     10セッション    42PV  エンゲージ  60.0%  localhost
  外      8セッション     8PV  エンゲージ   0.0%  mitokou.com
```

### 8-1. `mitokou.com` — 別サイトではなかった

**想定（外れ）**: 別ドメインで同じ測定IDが動いている。測定IDを分ける。

**実際**（2026-09-06 実測）:

| 調べたこと | 結果 |
|---|---|
| DNS | **Cloudflare を指していない**。このサイトを配信していない |
| HTTP | 応答なし |
| GA4 の8セッション | **全部**が「アメリカ・(direct)・着地は `/`・1PV・エンゲージ0%」 |

`mitokou.com` は旧サイト名（観とこう）の候補ドメイン（[DEPLOY.md](../DEPLOY.md) の改名の記録）。
**分けるべき「別サイト」は存在しない。**

**測定IDはHTMLに書いてあるので、誰でも計測エンドポイントに直接送れる。**
送られたヒットは**サイトのJSを一度も実行していない**ので、

- `BaseLayout.astro` の `ga-disable` は効かない（そのコードが走っていない）
- GA4 の内部トラフィック除外も効かない（IPの話ではない）
- GA4 のデータフィルタに**ホスト名の条件は無い**

**つまり GA4 側では止められない。レポートの側で外すしかない。** それが 8-0。

### 8-2. `www.` — すでに301されていた。しかも**本物の読者**だった

```
https://www.mihoudairader.com/leaving/prime-video  → 301 → …/leaving/prime-video
https://www.mihoudairader.com/posts/2026-08-ended  → 301 → …/posts/2026-08-ended
```

| 国 | 日本 |

| 着地 | `/works/2036` `/leaving/prime-video` `/posts/2026-08-ended` など実在ページ |

正しくは 159セッション。`productionHosts()` が `www` 版を既定に含めているのはこのため。

> ★ なぜ 301 されているのに `www` で記録されるのかは**分かっていない**（未検証）。
