# 横断の「いま観られるサービス」表示（設計・保留中）

**シリーズ記事の表に「この作品はいまどこで観られるか」を出す施策。**
2026-09-05 に実現性を調べた。**技術的にも規約的にも可能だが、実装は保留にした。**

保留の理由は 6節。**規約でも工数でもなく、収益とデータの穴が噛み合わないこと。**

- 実装するときの手順 → 5節
- 再検討する条件 → 7節
- 関連: [SOURCES-UNEXT-HULU.md](./SOURCES-UNEXT-HULU.md)（各ソースで何が取れるか）
  / [AFFILIATE.md](./AFFILIATE.md)（提携可否と掲載順の規律）
  / [WORK-PAGES.md](./WORK-PAGES.md)（作品ページの状態表示）

---

## 1. 何をしたいのか

シリーズ記事は「◯◯シリーズ、いつまで観られる？」に答える記事だが、
読者が次に知りたいのは **「じゃあどこで観られる？」**。

いまの答えは記事末尾の**検索リンク**しかない。
「U-NEXTで検索」「Huluで検索」を並べているだけで、
**あるかどうかは読者が自分で確かめる**形になっている。実質は丸投げ。

ここを「Amazon Prime Video と Netflix で見放題」と**裏付き**で書けるようにしたい、
というのがこの施策。読者が観る先を選べることが利益になる。

## 2. 技術的にできること（2026-09-05 実測）

### 2-1. 在庫が取れる。**これは変化ログとは別のもの**

パイプラインが使っているのは `/changes`（変化のログ）で、
だから当サイトは**「配信中」と書けない**という決まりがある
（`site/src/lib/works.ts` 冒頭「絶対に守ること」／`pipeline/core/cross-service.ts`）。

**この禁止は `/changes` の性質から来ていて、APIの限界ではない。**

`/shows/search/filters` と `/shows/{id}` が返す `streamingOptions.jp[]` は
**その時点の在庫そのもの**で、サービスごとに取扱区分とリンクを持っている。

| フィールド | 中身 |
|---|---|
| `service.id` | `prime` `netflix` `disney` `apple` |
| `type` | `subscription`（見放題）/ `addon`（チャンネル）/ `rent` / `buy` |
| `link` | そのサービスの作品ページへの直リンク |
| `expiresOn` / `expiresSoon` | 終了日（**実測では空。2-4**） |

★ **`catalogs` で絞っても、他社の取扱は返ってくる。**
  `catalogs=prime.subscription` で投げたバイオハザードの応答に
  `apple:rent` `apple:buy` が入っていた。
  **1回の問い合わせで横断の在庫が揃う**ということ。

### 2-2. コストは安い。**作品単位ではなくシリーズ単位**

`/shows/search/filters` はキーワードで複数作品をまとめて返す。
バイオハザードは **7件が1リクエスト**（`hasMore: false`）で取れた。

| | 見積もり |
|---|---|
| シリーズ記事1本 | 1〜3リクエスト（大きいシリーズはページング） |
| 公開中のシリーズ記事6本を全更新 | **10リクエット前後** |
| 無料枠 | 500/月（2026-08 の実績 101、2026-09 は5日で29） |

月1回の書き直しに載せるなら枠は問題にならない。

### 2-3. コードの下地はほぼ揃っている

| | 状態 |
|---|---|
| `ApiStreamingOption` の型 | **定義済み**（`service` / `type` / `link` / `expiresOn` / `expiresSoon`） |
| `collectWorks()`（`/shows/search/filters` を叩く） | **実装済み・未使用** |
| `fetchShow()`（1作品を引く。IMDb ID も渡せる） | **実装済み** |
| `toWork()` | ⚠️ **`streamingOptions` をリンク1本だけ拾って捨てている**（`streaming-availability.ts`） |

**足りないのは実質この最後の1点だけ。**

### 2-4. 「いつまで」は増えない

バイオハザード6作すべてで `expiresOn` は空だった。
終了日は引き続き `/changes` の `expiring` 頼みで、**それが取れるのは Netflix と Prime Video だけ**。

つまりこの施策が増やすのは **「どこで観られるか」だけ**で、
シリーズ記事の本来の問い（「いつまで」）の答えは1件も増えない。

## 3. カバーできない範囲

### 3-1. サービスごと

| サービス | 在庫が取れるか |
|---|---|
| Netflix / Amazon Prime Video / Disney+ / Apple TV+ | ✅ APIから取れる |
| **U-NEXT** | ❌ **APIの日本カタログに存在しない**（2026-08-24 再確認）。自前台帳を使うしかない → 3-2 |
| Hulu / DMM TV | ❌ データが無い。検索リンクのまま |

### 3-2. ★ U-NEXT の台帳は「観測したものだけ」で、カタログではない

**この施策のいちばん大きな穴。**

`data/unext-titles.json` は収集で歩いた範囲（新規入荷ページ＋終了予定ページ）しか持たない。
**U-NEXTの全カタログではない。**

2026-09-05 時点の実測:

| | |
|---|---|
| 台帳の作品数 | **1,902件**（U-NEXTの実カタログは桁がいくつも違う） |
| 終了日あり / 開始日あり | 795 / 1,163 |
| 「バイオハザード」 | **0件** |
| 「ミッション:インポッシブル」 | **0件** |
| 「ハリー・ポッター」 | **1件**（ベイキング番組のみ。本編7作は無い） |
| 「名探偵コナン」 | 32件（終了予定として拾ったぶん） |

**台帳に無いことは「U-NEXTに無い」を意味しない。「まだ観測していない」だけ。**

横断表示にU-NEXTを混ぜると、ここが**偽の不在**になって出る。
読者は「U-NEXTには無いのか」と読むが、実際にはあるかもしれない。
**単価が最も高いサービス（1,320円）で、いちばん質の悪い誤情報を出す**ことになる。

> ★ 出さなければ嘘にはならないが、**それなら横断表示の値打ちが半減する。**
>   4社ぶんだけ出して、収益になる1社が空欄というのは読者にとっても中途半端。

## 4. 規約・運用の条件

**規約上できないことは無い。** ただし守る条件が4つある。

### 4-1. ★ `addon` を見放題と書かない（いちばん事故りやすい）

`type` には `subscription` と `addon` が**同じ作品に併存する**。
実測でバイオハザードの各作に `prime:subscription` と `prime:addon` の両方が付いていた。
`addon` は Prime Video チャンネル（**別料金**）。

混同すると「別料金の作品を見放題と書く」ことになり、
性質としては U-NEXT ガイドライン【4】の誤認訴求と同じ。

> **`type === 'subscription'` だけを見放題として扱うこと。** ここは実装の必須条件。
> 2026-09-05 にバイオハザードのシリーズ記事で「すべてが見放題」が
> `check:unext` に止められた事故と、同じ種類の間違い。

### 4-2. 「配信中」と書けるようになるが、根拠と時点を明示する

現行の禁止（`works.ts`「絶対に守ること」）は
**変化ログを根拠に在庫を断定するな**という趣旨なので、
在庫レスポンスを根拠にするなら射程外になる。

- **取得時点を明記する**（既存の「◯月◯日時点」と同じ作法）。在庫は日々変わる
- U-NEXT・Hulu・DMM TV への断定禁止は**そのまま残る**（データが無い／別の規律）

### 4-3. ★ 掲載順は機械的に固定する

[AFFILIATE.md 7節](./AFFILIATE.md) で
**「紹介料の高いサービスを優先して掲載しない」**と決め、
プライバシーポリシーにも明記した。横断表示はこの規律に正面から触れる。

**Amazon を上に置く実装にした時点で、明記した方針に反する。**
並び順はデータ由来の機械的な順（サービスキーの定義順など）に固定すること。

### 4-4. 帰属表示を落とさない

APIは各記事への出典表記が義務（[SOURCES-UNEXT-HULU.md 4節](./SOURCES-UNEXT-HULU.md) の比較表）。
既存の固定文言でカバーされているので、**表示を足しても文言は必ず残す。**

## 5. 実装するときの手順

保留を解いたときのために、順番だけ残す。**上から順に、1つずつ確かめながら。**

1. **`toWork()` で `streamingOptions` を保持する**
   `Work.meta` に `{ service, type, link }[]` を持たせる。
   `type === 'subscription'` の絞り込みは**保持のときではなく使うときに**行う
   （`rent`/`buy` は将来アフィリエイトの導線になりうるので捨てない）

2. **取得の口を1つ作る**
   `collectWorks()` をシリーズ記事の主題（`--match`）で叩く CLI。
   **書き直し（`/refresh`）のときだけ走らせる。** 毎ビルドで叩かない

3. **`series.ts` の表に「視聴可能サービス」列を足す**
   - `subscription` のみ
   - 順序固定（4-3）
   - 取得時点を記事に明記（4-2）
   - **U-NEXT は入れない**（3-2。入れるなら 7-1 が先）

4. **品質ゲートを足す**
   `addon` が「見放題」として本文に出ていないかの検査（4-1）

★ **`/changes` の収集は変えないこと。** 終了日はそちらでしか取れない（2-4）。
  この施策は**別の口を1つ増やす**話で、既存の収集を置き換える話ではない。

## 6. 保留の理由（2026-09-05）

**規約でも工数でもない。収益とデータの穴が噛み合わないこと。**

### 6-1. 在庫が取れる4社のうち、収益になるのは1社だけ

[AFFILIATE.md 3節](./AFFILIATE.md) の実測より:

| サービス | 在庫 | 提携 |
|---|---|---|
| Amazon Prime Video | ✅ | ✅ Amazonアソシエイト |
| Netflix | ✅ | ❌ **公式プログラムが存在しない** |
| Disney+ | ✅ | 🔶 招待制 |
| Apple TV+ | ✅ | 🔶 招待制 |
| **U-NEXT**（単価 1,320円で最有力） | ❌ **3-2 の穴** | afb で提携交渉中 |

**在庫が取れるサービスと、収益になるサービスが、ほとんど重なっていない。**
横断表示を作り込むほど、**収益にならない導線を厚くする**ことになる。

### 6-2. 読者の利益は本物だが、いま出せる形では半端

「どこで観られるか」を裏付きで出せるのは読者にとって明確な前進で、
検索リンクへの丸投げより良い。**それは疑いない。**

ただし、いま出せるのは
**「4社ぶんの在庫」＋「U-NEXTは空欄」＋「Hulu・DMM TVは検索リンクのまま」**
という形。読者から見て「結局どこで観られるのか」が1画面で閉じない。

### 6-3. 「いつまで」は1件も増えない（2-4）

シリーズ記事の本来の問いに対しては、この施策は何も足さない。

## 7. 再検討する条件

**どれか1つでも変われば、判断は変わる。**

### 7-1. ★ U-NEXT の台帳がカタログに近づいたとき（いちばん効く）

いまの台帳は「新規入荷」と「終了予定」を歩いた副産物でしかない（3-2）。
**作品名から引ける形**になれば、3-2 の穴と 6-1 の収益の穴が**同時に埋まる。**

考えられる道:

- **作品名での検索**（`video.unext.jp` のフリーワード検索）を、
  シリーズ記事の主題ぶんだけ叩いて台帳に足す。
  **既存の巡回とは別の口**で、件数も限られる（記事1本あたり数十件）
- ★ ただし [SOURCES-UNEXT-HULU.md 5節](./SOURCES-UNEXT-HULU.md) の規律がそのままかかる。
  `min_interval_ms` を下げない。負荷の議論（岡崎市立図書館事件）は
  規約より重い問題として扱うこと

> **これが本命。** U-NEXT は在庫も単価も揃う唯一のサービスで、
> ここが埋まればこの施策は「読者の利益」と「収益」が初めて同じ方向を向く。

### 7-2. Disney+ か Apple TV+ の提携が通ったとき

在庫が取れる4社のうち収益になるのが2社に増える。6-1 の計算が変わる。

### 7-3. `expiresOn` が返るようになったとき

2-4 が解消し、**Disney+ と Apple TV+ の終了日**が初めて手に入る。
そうなればシリーズ記事の本来の問い（「いつまで」）にも効くので、
この施策は「あれば嬉しい表示」から「記事の中身そのもの」に変わる。

## 8. この調査で分かった、すぐ使える事実

**保留とは別に、記録しておく価値のあるもの。**

- `streamingOptions` は `catalogs` で絞られない（2-1）。
  **1リクエストで横断の在庫が取れる**のは、他の用途にも使える
- `collectWorks()` と `fetchShow()` は実装済みで未使用（2-3）。
  ランキング記事など、在庫を前提にした記事タイプを作るときの土台になる
- `type` に `addon` が混ざる（4-1）。
  **これは今後どの機能で在庫を使うときも効く注意**で、この施策に限らない
