## 2. 対処

### 2-1. 🔴 配信が再開した作品のページが 404 になっていた — `works.ts`

**原因:** 作品ページを出す条件の「終了日を言える」を、**いまの状態だけ**で判定していた。
一度終了して**同じサービスで配信が再開した**作品は、状態が「配信開始」に戻った時点で条件から外れ、
**ページごと消えていた。**

| 作品 | できごと | Search Console | 本番（直す前） |
|---|---|---|---|
| `/works/1942` 新感染 | Prime Video 8/3 終了 → 9/2 再開 | **登録済み** | **404** |
| `/works/5460157` 運の悪い日 | Prime Video 8/14 終了 → 9/11 再開 | **登録済み** | **404** |
| `/works/3222` 青春ブタ野郎はバニーガール先輩の夢を見ない | Prime Video 8/13 終了 → 9/11 再開 | **登録済み** | **404** |
| `/works/3931` 力道妖精キム・ボクジュ | Prime Video 8/14 終了 → 9/11 再開 | **登録済み** | **404** |
| `/works/4813920` JunとJun | Prime Video 8/14 終了 → 9/11 再開 | 未認識 | 404 |

どれも Google が最後に巡回したのは消える前で、**次の巡回で 404 の行に入るところだった。**

**直し方:** 「終了日を言える」を**履歴でも見る**ようにした（`isWorkPagePublishable()`）。
過去に終了・終了予定を1度でも観測した作品は、配信が再開してもページを残す。

- 増えるのは**この5枚だけ**（ビルドで 673 → 678 を確認。消えたページは0）
- 再開した作品のページには「8/3 に終了 → 9/2 に再開」の**配信の記録**が出る。
  「いつまで観られる？」の答えが変わった作品なので、**このサイトで一番中身のあるページになる**

> ★ **消えたページを 301 で逃がす方法は採らなかった。** 行き先に正しい候補が無い（作品の代わりになるページは無い）うえ、
> 再開した作品はまさに検索される作品で、ページがあるほうが読者の答えになる。

### 2-2. 🟡 CSS・JS に noindex ヘッダー — `public/_headers`

```
/_astro/*.css
  X-Robots-Tag: noindex
/_astro/*.js
  X-Robots-Tag: noindex
```

- **いま本番にある CSS・JS は、Google にまだ URL として認識されていない**（URL 検査で5件とも「認識されていません」）
- 「クロール済み - インデックス未登録」の**特定できなかった3件は、過去のビルドの CSS・JS の可能性が高い**（推定）。
  Astro はビルドのたびにファイル名のハッシュが変わるので、古い名前は検査の対象リストに入らない
- ヘッダーを付けると、今後 Google が CSS・JS を取りに来ても「**noindex タグによって除外**」（意図どおりの行）に入る
- **描画には影響しない。** `robots.txt` の Disallow とは別物（あちらは描画を壊す。**やらないこと**）
- 画像（`/_astro/*.webp`）には付けていない
- `wrangler pages dev` で確認済み: CSS・JS にだけ `x-robots-tag: noindex` が付き、画像・HTML・RSS には付かない

**本番に出したあとの確認:**

```bash
curl -sI https://mihoudairader.com/_astro/<いまのCSSのファイル名>.css | grep -i x-robots-tag
# → x-robots-tag: noindex
```

### 2-3. 🟡 404 の正体は Cloudflare のメールアドレス難読化 — `public/robots.txt`

`/contact` の `mailto:` リンクを、**Cloudflare が配信のときに** `/cdn-cgi/l/email-protection#…` へ書き換えている
（Scrape Shield の Email Address Obfuscation。`site/dist/contact.html` には `mailto:` のまま入っていて、本番の HTML だけが違う）。
人のブラウザではスクリプトがアドレスに戻すが、**Googlebot はリンクを辿って 404 を受け取る。**

**直し方:** `robots.txt` に `Disallow: /cdn-cgi/l/` を足した。

| 方法 | 404 | アドレスの収集対策 | 採否 |
|---|---|---|---|
| **`robots.txt` で `/cdn-cgi/l/` だけ止める** | 出なくなる | **残る** | ✅ 採用 |
| Cloudflare の画面で難読化を切る | 出なくなる | **消える**（個人の Gmail が HTML にそのまま出る） | 採らない |
| `<!--email_off-->` で `/contact` だけ除外 | 出なくなる | **消える** | 採らない |

- ★ **`/cdn-cgi/` 全体は止めない。** `/cdn-cgi/scripts/…/email-decode.min.js`（アドレスを表示に戻すスクリプト）も止まり、
  Google がページを描画するときに読めなくなる
- Search Console の行は、再クロールされないので**時間をかけて消えるか、「robots.txt によりブロックされました」に移る**。どちらも意図どおり
- 独自ドメインのメール転送に替えて**フォームにする**なら、この行は要らなくなる（`pages/contact.astro` の注意書き）

### 2-4. やらないと決めたこと

| | 理由 |
|---|---|
| **RSS に noindex を付ける** | フィードが未登録なのは正常。Google Discover の「フォロー」がフィードを読むため、影響を確かめないまま付けない |
| **人物ページの閾値（作品5本）を上げる** | 索引対象53枚のうち37枚が登録済み。薄いと判断されたのは3枚だけ。**重要度が低いので今は触らない**（3節） |
| **`/404` の canonical を外す** | `/404` は 200 で返るが noindex。外から見つかる経路が無い |

## 5. AdSense 審査との関係

**Search Console の「未登録」の件数そのものは審査の基準ではない**（一般論。AdSense が見るのはサイトの中身とポリシー）。
審査に効くのは次のもの。

| | 状態 |
|---|---|
| **読者が 404 を踏まない** | ✅ 2-1 で、登録済みページの 404 を4枚ぶん防いだ |
| 薄いページを索引に入れない | ✅ 人物ページの noindex（AFFILIATE 10-3）が効いている |
| 記事の量（目安30本） | ✅ **32本**（AFFILIATE 10-4 の「19本」から到達） |
| 追従バーを止める | ⬜ **申請の前に** `FOLLOW_BAR_ENABLED = false`（AFFILIATE 10-5。いまは `true`） |
| **画像の権利の書き方** | 🔴 **見直しが要る。** AFFILIATE 10-1 の「画像の権利処理 ✅ 提供元から再ホストの許諾」は、API 規約の現行版と合わない（[PARTNERSHIPS.md 3-1](./PARTNERSHIPS.md) の🔴）。AdSense のポリシーは著作権のあるコンテンツの扱いを見るので、**申請前に決着させること** |

  （`{ inspectionUrl, siteUrl: GSC_SITE_URL, languageCode: 'ja' }`）

## 7. 2026-09-23 の急落（Google の表示が約9割消えた）

調査日: 2026-09-26 ／ 元データ: Search Console（日別・時間別、`dataState: 'all'`）、GA4（`dateHour` × `sessionSource`）、URL 検査 API 81件

### 7-1. 何が起きたか

**2026-09-23 17時（JST）を境に、Google 検索の表示が 1日 約220 → 約40 になった。** GSC の時間別（01:00 PT）と GA4 の時間別（google/organic の最後のまとまった流入が 16時台）が同じ1時間を指す。Bing・ChatGPT・直接は横ばい。9/25 に表示が残っていたのは `/posts/harry-potter` の1本だけ。

### 7-2. 原因ではなかったもの

| 疑い | 否定した根拠 |
|---|---|
| 記事テンプレの変更（9/19 22:05 に記事35本を書き直し） | **新版を Google が一度もクロールしていないページも同率で消えた**（`/leaving/netflix` は最終クロール 9/14 で −97%。書き直し後にクロール済みの記事は −100%、未クロールの作品ページは −97%）。作品ページと `/leaving` はそもそもテンプレの対象外 |
| デプロイの事故 | 崖の時刻に出たのは bot のデータ更新だけ。コードの最終デプロイは 9/22 16:08 |
| 索引落ち・canonical・robots | 81件中78件が「送信して登録されました」。残る3件は新しい記事で未登録なだけ。**順位が下がったのではなく表示が消えた** |
| 手動による対策・セキュリティ・削除 | 運用者が Search Console の画面で確認し、すべて問題なし（9/26） |
| 連休明け | 9/19〜23 はシルバーウィークで増えていたが、休み明けに9割は落ちない |

**→ アルゴリズムによるサイト単位の評価。** 「September 2026 spam update」は公式には 9/24 09:15 PT に始まり2週間（〜10/8ごろ）。揺れは 9/22 から報告されていた。崖は公式開始より32時間早いので、アップデートそのものとは断定できない。回復は Google 公式で「数か月かかることがある」。
