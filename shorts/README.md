# ショート動画の台本

`/article` で記事を1本書くと、**同じ素材からショート動画の台本のたたき台**が
ここに1本できる。ファイルは `<記事のスラッグ>.md`。

```
shorts/
├ README.md                      このファイル
├ 2026-10-leaving-netflix.md     台本（手で直す。git で管理する）
└ frames/                        カット画像（作り直せるので git に入れない）
   └ 2026-10-leaving-netflix/
      ├ 01.png … 1080 × 1920
      └ 02.png
```

**たたき台です。** そのまま撮るためのものではなく、
30秒の骨組みと、法的に問題のない材料をそろえた状態で渡すためのもの。

---

## 1. 台本を直す

`<スラッグ>.md` の **`## カット` の表**だけを直せばよい。
他の節（概要欄・チェックリスト）は自動で組み立てられている。

| 列 | 中身 | 目安 |
| --- | --- | --- |
| **ナレーション** | 読み上げる文。これが尺を決める | 1カット **35字**まで |
| **テロップ** | 画面に大きく出る文字。作品名かまとまりの正体 | **20字**まで |
| **補足** | 日付とサービス名。小さいバッジになる | **16字**まで |

- 行を足す・消す・並べ替えてよい。**`#` の番号は飾りで、画像は上から順に作られる**
- ナレーションをテロップに書き写さない。同じ文が耳と目に二重に来ると、どちらも入らない
- **最後のカットは「詳細は概要欄にて。」で終える。** 毎回同じ終わり方にすることで、
  視聴者が概要欄を見る動作を覚える

### 30秒に収まっているか

```powershell
cd C:\Users\grate\brog\site
npm run shorts
```

いま書いてある文から数え直して、カット数・字数・推定秒数が出る。
超えていれば `!` が付く。

```
  2026-10-leaving-netflix  6カット / 読み上げ 151字 / 推定 27.2秒
! 2026-10-leaving-prime    7カット / 読み上げ 205字 / 推定 36.6秒  ← 30秒を超えています
```

> **秒数は 6字/秒 での目安。** ラテン文字は字数と読みの長さが一致しない
> （「Netflix」は7字だが読みは8音、「Amazon Prime Video」は17字で11音）。
> 最後は必ず実際に読み上げて確かめること。

## 2. カット画像を作る

```powershell
cd C:\Users\grate\brog\site
npm run shorts                      全部
npm run shorts -- --slug 2026-10-leaving-netflix   1本だけ
npm run shorts -- --guides          安全領域のガイドを重ねる
```

`shorts/frames/<スラッグ>/01.png` … に 1080×1920 の PNG が並ぶ。
**台本を直したら作り直す。** 古い連番は毎回消してから作るので、
カットを減らしても末尾が残らない。

### `--guides` は何のためにあるか

YouTube ショートの再生画面は、**下部にタイトルとチャンネル名、右側にボタン列**が重なる。
そこに文字を置くと本番で読めない。`--guides` を付けると、
その余白が赤く塗られた画像が出るので、位置合わせに使える。
**確認したらガイド無しで作り直すこと**（ガイドは画像に焼き込まれる）。

### 見た目を変える

`site/scripts/make-shorts.mjs` の `buildSvg()` を直す。

| 変えたいもの | 場所 |
| --- | --- |
| 配色 | `COLOR` |
| 安全領域 | `SAFE` |
| 文字の大きさ | `fitLines('bold', cut.caption, 108, 56, …)` の数字 |
| 読み上げ速度の見積り | `CHARS_PER_SECOND`（`pipeline/core/short.ts` と揃えること） |

## 3. 動画にする

カット画像とナレーションを動画編集ソフトで組む。ここは手作業。

- **声**: 合成音声を使う場合、**キャラクターごとに利用規約とクレジット表記の義務が違う**。
  使うものを決めたら、その規約を必ず確認すること
- **BGM**: YouTube オーディオライブラリが最も安全（YouTube 内での利用に限れば条件が明確）。
  外部のフリー素材を使う場合は**商用利用可**かを確認する。
  このチャンネルは広告・アフィリエイトの導線を持つので商用扱いになる
- **概要欄**: 台本の `## 概要欄` の中身をそのまま貼る

---

## 使ってよい素材・使ってはいけない素材

| | 動画で使えるか |
| --- | --- |
| 記事の事実データ（作品名・日付・サービス名） | **使える。** 事実に著作権はない |
| `shorts/frames/` のカット画像 | **使える。** 自前生成で第三者の権利が絡まない |
| `site/public/cards/` の記事カード画像 | **使える。** 同上 |
| サイトのロゴ・配色 | **使える** |
| **作品ポスター**（`site/public/sections/posters/`） | **使えない**（下記） |
| 作品のあらすじ原文 | 使えない。表現は著作物 |
| 各社ロゴ（Netflix 等） | 使えない。商標＋ブランドガイドライン。**サービス名はテキストで書く** |

### なぜポスターだけ使えないのか

サイトの記事にはAPIが返す作品ポスターを載せているが、**動画には使えない。**

1. **このリポジトリは「契約を終えたら画像を全部消す」前提で組んである**
   （`docs/APPEARANCE.md` 11節）。公開した動画は同じようには消せない
2. 提供元から得た許諾は「**自分のドメインから再ホストしてよい**」であって、
   第三者プラットフォームへの動画素材としての投稿は含まれない
3. YouTube へのアップロードは、YouTube に対する再許諾可能なライセンスの付与を意味する。
   **再ホストの許可しか持っていない画像について、それは出せない**

### 概要欄で必ず守ること

- **出典の行を消さない。** 配信情報の帰属表示は利用規約上の義務で、
  **YouTube は記事とは別の配布先**。概要欄に無いと義務を果たしたことにならない
- **アフィリエイトリンクを貼るなら、先頭に「PR」を置く。**
  景品表示法（2023-10-01 施行のステマ規制）が分かりやすい位置での明記を求めている。
  記事側の扱いは `docs/AFFILIATE.md` 5-5 と同じ

## 台本が付く記事・付かない記事

| 記事タイプ | 台本 | 理由 |
| --- | --- | --- |
| `leaving`（見放題終了予定） | **付く** | 締切があるのでショートに最も向く |
| `arrivals`（見放題配信開始） | **付く** | まとまりが強い月は成立する |
| `ended`（見放題終了済み） | **付かない** | 「もう観られない」を30秒で誤解なく伝える型が無い |

`ended` に台本を付けたくなったら、`theme-packs/streaming-jp/article-types/ended.ts` に
`buildShortPrompt` を実装すればそれだけで付く。CLI もスラッシュコマンドも触らなくてよい。

台本の構成・尺・禁止事項を変えたいときは
`theme-packs/streaming-jp/templates/short-script.md` を直す。全台本の型が変わる。
