# 常設ページの画像置き場

置くと**3か所すべてに同時に反映される**。

| 出る場所 | 大きさ |
|---|---|
| 右の追従枠のカード | 48×48 |
| 記事一覧に並ぶカード | 72×72 |
| 常設ページの**見出し（h1）の直上** | 本文幅・16:7 で切り抜き |

## ファイル名がそのまま対応先になる

拡張子は `.png` / `.jpg` / `.jpeg` / `.webp` のいずれか。

| ファイル名 | 出るカード |
|---|---|
| `netflix.png` | Netflix の「配信終了予定」と「新着配信」の2枚 |
| `prime-video.png` | Amazon Prime Video の2枚 |
| `disney-plus.png` | Disney+ の「新着配信」 |

**キーは `src/lib/events-data.ts` のサービスキーと同じ。** サービスを増やしたら
同じキーのファイルを置けば自動で拾われる（コード変更は不要）。

> 1つの画像が「終了予定」と「新着」の両方のカードに使われる。
> 区別はカード内のカテゴリバッジ（色付き）が担当するので、
> **画像はサービスを表すものだけでよい。**

## 仕様

- **正方形と横長の両方に切り抜かれる。** 小さい方は正方形（`object-fit: cover`）、
  見出し上は 16:7 の横長。**中央に主題がある画像**にすると両方で成立する
- **元画像は 1200×1200px 前後**を推奨。見出し上は本文幅（736px）まで拡大されるため、
  小さすぎるとそこでぼやける。ビルド時に各サイズへ縮小・WebP変換される
- 角丸はCSS側で付ける。画像に丸みを焼き込まない

## 画像が無くてもよい

| 場所 | 画像が無いとき |
|---|---|
| カード（追従枠・一覧） | **カテゴリ色のタイル**にサービス名の頭文字。高さは変わらないので並びは崩れない |
| 見出しの直上 | **何も描かない**。大きな面なので空の枠を出すと見た目が破綻するため |

1つずつ用意していけばよく、全部揃うまで待つ必要はない。

## ライセンスに注意

**各サービスの公式ロゴをそのまま使うと商標の問題になりうる。**
当サイトは広告収入を得ているため、ロゴの使用が各社のブランドガイドラインの
範囲を超える可能性がある。自作のアイコン、または利用条件を確認した素材を使うこと。
判断に迷うなら**頭文字のまま**にしておくのが安全（それで成立する設計にしてある）。

## 個別記事の画像は別系統

記事カードと記事ページの画像は frontmatter の `heroImage`（`public/` からの絶対パス）。
**いまは未設定**で、カテゴリ色のタイルが出る。
ポスター再ホストの可否が確定したら、パイプラインが紹介作品1件のポスターを入れる想定
（[HANDOVER.md](../../../docs/HANDOVER.md) の「返答待ち」）。

> 生成物の `/cards/<スラッグ>.jpg` は**使わない**。
> 記事タイトルを焼き込んだSNS共有用の画像なので、見出しの上に置くとタイトルが二重に出る。
