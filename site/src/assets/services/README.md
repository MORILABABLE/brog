# 常設ページの画像置き場

置くと**カード3か所に同時に反映される**。**どれも正方形の切り抜き**（`object-fit: cover`）。

| 出る場所 | 大きさ |
|---|---|
| トップの横スクロールの棚（`TopCalendar.astro`） | 132×132 |
| 記事一覧に並ぶカード（`EvergreenCard.astro`） | 72×72 |
| **左**の枠のカード（`CalendarCards.astro` / `LeftRail.astro`） | 60×60 |

> ★ **常設ページの見出しの直上（`LeadImage.astro`）には、もう出していない**（2026-09-07）。
> 汎用の絵（再生記号）が本文幅の帯を占めるわりに読者に渡すものが無く、
> カレンダーと表を画面の外へ押し下げていたため。
> **カードとしては上の2か所で使い続けている。** 部品（`LeadImage.astro`）も残してある。
> 戻し方は `site/src/pages/leaving/[service].astro` の h1 の直前に書いてある。

> 小さい2つは `Thumb.astro` が描く。**表示サイズの2倍**を書き出すので、
> 高精細画面でもぼやけない（48pxの枠には96pxの画像が入る）。
> 右の追従枠に出る絵は別系統（記事の `heroImage`）でここは関係しない。

## ファイル名がそのまま対応先になる

拡張子は `.png` / `.jpg` / `.jpeg` / `.webp` のいずれか。

| ファイル名 | 出るカード | いまの状態 |
|---|---|---|
| `netflix.png` | Netflix の「配信終了予定」と「新着配信」の2枚 | **あり**（2026-09-20・生成） |
| `prime-video.png` | Amazon Prime Video の2枚 | **あり**（2026-09-20・生成） |
| `disney-plus.png` | Disney+ の「新着配信」 | **あり**（2026-09-20・生成） |

> ★ **同じキーで拡張子違いを2つ置かないこと。** `serviceImage()` は
> `/<キー>\.(png|jpg|jpeg|webp)$` に最初に当たったものを返すので、
> `netflix.png` と `netflix.jpg` が並ぶと**どちらが出るか決まらない。**
> 差し替えるときは古いほうを消す（2026-09-20 に `.jpg` 3枚を消して `.png` へ移した）。
| `guide.*` | **左の枠の1ブロック目**「当サイトの運営方針および活用について」 | 無し（仮の汎用画像 `public/guide-thumb.svg`） |

> `guide` だけはサービスではなく**固定ページのカード**（/guide）。
> 置かなくても壊れない。置くまでは図形だけの仮画像（`site/public/guide-thumb.svg`）が出る。
> 差し替えるときの条件は下の「仕様」と同じ（中央に主題がある横長の絵）。

**キーは `src/lib/events-data.ts` のサービスキーと同じ。** サービスを増やしたら
同じキーのファイルを置けば自動で拾われる（コード変更は不要）。

> 1つの画像が「終了予定」と「新着」の両方のカードに使われる。
> 区別はカード内のカテゴリバッジ（色付き）が担当するので、
> **画像はサービスを表すものだけでよい。**

## 仕様

- **元画像は 1200×1200 の正方形**（2026-09-20〜）。出る3か所はどれも正方形の
  切り抜きなので、正方形で作れば**切り抜きが起きない＝描いたものがそのまま出る**。
  ビルド時に各サイズへ縮小・WebP変換される

  > ★ **横長で作らないこと。** 16:9 を正方形に切ると中央の 56% しか残らない。
  > いまの絵は7列の升目なので、**左右の列が落ちて「NETFLIX」の N と X が消える。**
  >
  > 以前ここには「1600×900 前後の横長を推奨」と書いてあった。これは
  > 見出し直上の帯（`LeadImage.astro`・16:7）に出していたころの条件で、
  > **その用途は 2026-09-07 に外した**（下の「3:2 の絵が欠ける」の節も同じ前提）。
  > 帯を戻すなら、そのとき改めて横長に作り直すこと。
- **中央に主題を置く。** 正方形どうしなら切り抜きは起きないが、
  将来また別の比率で使うときに効く
- **いちばん小さいのは 60px。** 1200px で見て成立していても、60px では
  細い線と小さい字は消える。**実寸に縮めて確かめること**（下の「確かめ方」）
- 角丸はCSS側で付ける。画像に丸みを焼き込まない

## 作り直し方と、確かめ方

```bash
cd site && node scripts/service-cards.mjs      # 3枚を描き直す
```

ビルドには**含まれない**手動スクリプト。出力は生成物だが、ここは `astro:assets` が読む
**入力**なので（`public/` に出す `cards/` や `thumbs/` とは性格が違う）**git に入れる。**

絵柄・文字・色を変えるときは `scripts/service-cards.mjs` の `SERVICES` を直す。
直したら**実寸に縮めて確かめること。** 1200px で見て成立していても、60px では別物になる:

```bash
cd site && node -e "
const sharp = require('sharp');
for (const k of ['netflix','prime-video','disney-plus'])
  for (const s of [60,72,132])
    sharp('src/assets/services/'+k+'.png').resize(s,s)
      .resize(s*4,s*4,{kernel:'nearest'})   // 情報を足さずに拡大する
      .toFile('/tmp/'+k+'-'+s+'.png');
"
```

`kernel:'nearest'` で引き伸ばすのは、**60px の時点で残っている情報だけを見るため。**
既定の補間で拡大すると、無い階調が足されて実際より読めるように見える。

> ★ **このフォルダに置いた画像は、どのページも使っていなくても `dist/` に出る。**
>   `lib/images.ts` の `import.meta.glob` が `eager` なので、全部が束ねられる。
>   **作業用のスクリーンショットや下書きを置いたままにしないこと**
>   （公開URLとして誰でも開ける形で残る）。置き場は各自の作業フォルダにする。

## 画像が無くてもよい

| 場所 | 画像が無いとき |
|---|---|
| カード（左の枠・一覧） | **カテゴリ色のタイル**にサービス名の頭文字。高さは変わらないので並びは崩れない |
| 見出しの直上 | **何も描かない**。大きな面なので空の枠を出すと見た目が破綻するため |

1つずつ用意していけばよく、全部揃うまで待つ必要はない。

## ライセンスに注意

**各サービスの公式ロゴをそのまま使うと商標の問題になりうる。**
当サイトは広告収入を得ているため、ロゴの使用が各社のブランドガイドラインの
範囲を超える可能性がある。自作のアイコン、または利用条件を確認した素材を使うこと。
判断に迷うなら**頭文字のまま**にしておくのが安全（それで成立する設計にしてある）。

> いま置いてある3枚は `scripts/service-cards.mjs` が描く**カレンダーの升目**で、
> 升目に並べた英字がサービス名を名乗る。**第三者の画像は1枚も使っていない**
> （升目は図形、字は同梱フォント＝SIL OFL）。許諾も出典表記も期限も無い。
>
> ★ **ロゴは使っていない。** 出ているのは各社の名前を**素の書体で組んだ文字**で、
>   公式のロゴタイプ（Netflix の専用書体など）ではない。サービスを指すために
>   名前を普通の字で書くのは、商標そのものの使用とは別の話。
>   **公式ロゴの画像を持ってこないこと**——ここが以前からの線で、変えていない。
> ★ 色は 赤／青／**深緑**（2026-09-20・運用者の指定）。
>   Disney+ に公式の青を当てるとブランド色に寄りすぎるので、**色では寄せていない。**
>   以前ここに置いていた抽象画で Disney+ だけモノクロにしていたのと同じ判断。

### ★ 配信カレンダーの画面をスクリーンショットして使わないこと（2026-09-20 に検討して見送り）

升目に並んでいるのは**作品のポスター**で、これは Third-Party Content として
**提供元も許諾を出せない**（`docs/PARTNERSHIPS.md` 3-1）。さらに、

- カードの絵は `og:image` にもなる。**X・LINE・Slack 側にコピーが残る**ので、
  あとからサイトの画像を消しても回収できない。ページ内のポスターは
  消せばその場で消えるが、**こちらは撤退できない**
- 装飾として貼るので「引用」（著作権法32条）の主従関係が立たない
- AdSense の著作権ポリシーは「適法な引用か」ではなく
  「**権利のある画像を主役にしていないか**」で見る

だから**升目の構造だけを自分で描いている。**

### 3:2 の絵をそのまま置くと、見出し上で主題が欠ける（2026-09-06 に踏んだ）

> **いまは効かない話。** 見出し直上の帯（`LeadImage.astro`）は 2026-09-07 に外し、
> 画像も正方形へ移した（2026-09-20）ので、16:7 の切り抜きはどこにも無い。
> **帯を戻すときだけ読むこと。** 以下は当時の記録。

`disney-plus.jpg` の元絵は **1248×832（3:2）** だった。置いた結果、
見出し上（16:7）で**三角形の上下の頂点が切れ、他の2枚より絵が大きく見えた。**
原因は2つあり、どちらも「16:9 ではない」ことから来ている。

| | 16:9（1680×944） | 3:2（1248×832） |
|---|---|---|
| 16:7 に切り抜いたとき残る高さ | 77.9% | **65.6%**（＝主題が欠けやすい） |
| 本文幅736pxで表示するときの縮小率 | 0.438 | **0.590**（＝主題が1.35倍大きく見える） |

**幅が狭い絵ほど、同じ736pxに引き伸ばすぶん中身が大きく出る。** 縦の切り落としも増える。

直し方は**絵を縮めるのではなく、左右に足して 16:9 にする**こと。
中身の大きさは他の2枚と揃い、縦の切り落としも同じ割合になる。

```bash
cd site && node -e "
const sharp = require('sharp');
const W = 1680, H = 944, src = 'src/assets/services/<キー>.jpg';
sharp(src).metadata().then(m => sharp(src).extend({
  left: Math.round((W - m.width) / 2), right: W - m.width - Math.round((W - m.width) / 2),
  top: Math.round((H - m.height) / 2), bottom: H - m.height - Math.round((H - m.height) / 2),
  extendWith: 'copy',
}).jpeg({ quality: 90, mozjpeg: true }).toFile(src + '.new'));
"
```

`extendWith: 'copy'`（端の色をそのまま伸ばす）を使うのは、**継ぎ目が出ないから**。
`make-og.mjs` と同じ「ぼかした自分自身を継ぎ足す」方式も試したが、
継ぎ足しの明るさが元絵の端とわずかに違い、**縦の線として見えた**。
横方向の光の筋でできた絵なら、端を伸ばすほうが自然につながる。
（`mirror` も継ぎ目は出ないが、右側の模様が左右対称に折り返して不自然だった。）

> **いちばんよいのは、最初から 1600×900 前後の 16:9 で書き出すこと。**
> 上の継ぎ足しは、手元に 16:9 の元絵が無いときの後処理。

## 個別記事の画像は別系統

記事カードと記事ページの画像は frontmatter の `heroImage`（`public/` からの絶対パス）。
**いまは未設定**で、カテゴリ色のタイルが出る。
**`npm run sections -- --write` が自動で入れる**（2026-08-25〜）。
記事タイトルと一致する作品のポスターが選ばれ、無ければ記事に最初に出てくる作品になる。
手で別のパスを書けば、その記事は自動処理の対象から外れる。
→ [APPEARANCE.md の12節](../../../docs/APPEARANCE.md#12-記事のヘッダー画像frontmatter-の-heroimage)

> **ここ（常設ページのサービス画像）は自動化していない。**
> 作品のポスターはサービスを表さないので、置くと意味が変わる。
> 頭文字のタイルのままでも成立する設計にしてある。

> 生成物の `/cards/<スラッグ>.jpg` は**使わない**。
> 記事タイトルを焼き込んだSNS共有用の画像なので、見出しの上に置くとタイトルが二重に出る。
