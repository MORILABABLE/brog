## ファイル名がそのまま対応先になる

拡張子は `.png` / `.jpg` / `.jpeg` / `.webp` のいずれか。

| ファイル名 | 出るカード | いまの状態 |
|---|---|---|
| `netflix.jpg` | Netflix の「配信終了予定」と「新着配信」の2枚 | **あり**（2026-08-28） |
| `prime-video.jpg` | Amazon Prime Video の2枚 | **あり**（2026-08-28） |
| `disney-plus.jpg` | Disney+ の「新着配信」 | **あり**（2026-09-06） |
| `guide.*` | **左の枠の1ブロック目**「当サイトの運営方針および活用について」 | 無し（仮の汎用画像 `public/guide-thumb.svg`） |

> `guide` だけはサービスではなく**固定ページのカード**（/guide）。
> 置かなくても壊れない。置くまでは図形だけの仮画像（`site/public/guide-thumb.svg`）が出る。
> 差し替えるときの条件は下の「仕様」と同じ（中央に主題がある横長の絵）。

**キーは `src/lib/events-data.ts` のサービスキーと同じ。** サービスを増やしたら
同じキーのファイルを置けば自動で拾われる（コード変更は不要）。

> 1つの画像が「終了予定」と「新着」の両方のカードに使われる。
> 区別はカード内のカテゴリバッジ（色付き）が担当するので、
> **画像はサービスを表すものだけでよい。**

## 仕様

- **正方形と横長の両方に切り抜かれる。** 小さい方は正方形（`object-fit: cover`）、
  見出し上は 16:7 の横長。どちらも中央を残す切り抜きなので、
  **中央に主題がある画像**にすると両方で成立する（これが唯一の必須条件）
- **元画像は 1600×900px 前後の横長**を推奨。
  いちばん大きく出るのが見出し上（本文幅736px・16:7）なので、
  そこを縮小だけで賄える幅があればよい。ビルド時に各サイズへ縮小・WebP変換される

  > 以前ここには「1200×1200 の正方形」と書いてあったが、
  > 実際に採用した2枚は 1680×944（16:9）で、こちらのほうが素直だった。
  > 正方形の絵は見出し上で上下を大きく落とすことになる。
  > **16:9 から 16:7 への切り抜きは上下を1割ずつ落とすだけ**で済む。
- 角丸はCSS側で付ける。画像に丸みを焼き込まない

## 画像が無くてもよい

| 場所 | 画像が無いとき |
|---|---|
| カード（左の枠・一覧） | **カテゴリ色のタイル**にサービス名の頭文字。高さは変わらないので並びは崩れない |
| 見出しの直上 | **何も描かない**。大きな面なので空の枠を出すと見た目が破綻するため |

1つずつ用意していけばよく、全部揃うまで待つ必要はない。

## ライセンスに注意

**各サービスの公式ロゴをそのまま使うと商標の問題になりうる。**
当サイトは広告収入を得ているため、ロゴの使用が各社のブランドガイドラインの
範囲を超える可能性がある。自作のアイコン、または利用条件を確認した素材を使うこと。
判断に迷うなら**頭文字のまま**にしておくのが安全（それで成立する設計にしてある）。

> いま置いてある3枚（`netflix.jpg` / `prime-video.jpg` / `disney-plus.jpg`）は
> **生成した抽象画**で、ロゴ・商標・文字・人物をいずれも含んでいない。
> 各社を連想させるのは**色と再生ボタンのモチーフだけ**にしてある
> （赤＝Netflix、青＋ゴールド＝Prime Video）。次を足すときもこの線を守ること。
>
> ★ `disney-plus.jpg` だけ**モノクロ**（暗い地に白い入れ子の三角形）。
>   Disney+ の青を当てると公式のブランド色に寄りすぎるため、色では寄せていない。
>   **3枚並んだときに1枚だけ無彩色**になるが、これは意図した状態。

### ★ 3:2 の絵をそのまま置くと、見出し上で主題が欠ける（2026-09-06 に踏んだ）

`disney-plus.jpg` の元絵は **1248×832（3:2）** だった。置いた結果、
見出し上（16:7）で**三角形の上下の頂点が切れ、他の2枚より絵が大きく見えた。**
原因は2つあり、どちらも「16:9 ではない」ことから来ている。

| | 16:9（1680×944） | 3:2（1248×832） |
|---|---|---|
| 16:7 に切り抜いたとき残る高さ | 77.9% | **65.6%**（＝主題が欠けやすい） |
| 本文幅736pxで表示するときの縮小率 | 0.438 | **0.590**（＝主題が1.35倍大きく見える） |

**幅が狭い絵ほど、同じ736pxに引き伸ばすぶん中身が大きく出る。** 縦の切り落としも増える。

直し方は**絵を縮めるのではなく、左右に足して 16:9 にする**こと。
中身の大きさは他の2枚と揃い、縦の切り落としも同じ割合になる。

```bash
cd site && node -e "
const sharp = require('sharp');
const W = 1680, H = 944, src = 'src/assets/services/<キー>.jpg';
sharp(src).metadata().then(m => sharp(src).extend({
  left: Math.round((W - m.width) / 2), right: W - m.width - Math.round((W - m.width) / 2),
  top: Math.round((H - m.height) / 2), bottom: H - m.height - Math.round((H - m.height) / 2),
  extendWith: 'copy',
}).jpeg({ quality: 90, mozjpeg: true }).toFile(src + '.new'));
"
```

`extendWith: 'copy'`（端の色をそのまま伸ばす）を使うのは、**継ぎ目が出ないから**。
`make-og.mjs` と同じ「ぼかした自分自身を継ぎ足す」方式も試したが、
継ぎ足しの明るさが元絵の端とわずかに違い、**縦の線として見えた**。
横方向の光の筋でできた絵なら、端を伸ばすほうが自然につながる。
（`mirror` も継ぎ目は出ないが、右側の模様が左右対称に折り返して不自然だった。）

> **いちばんよいのは、最初から 1600×900 前後の 16:9 で書き出すこと。**
> 上の継ぎ足しは、手元に 16:9 の元絵が無いときの後処理。

## 個別記事の画像は別系統

記事カードと記事ページの画像は frontmatter の `heroImage`（`public/` からの絶対パス）。
**いまは未設定**で、カテゴリ色のタイルが出る。
**`npm run sections -- --write` が自動で入れる**（2026-08-25〜）。
記事タイトルと一致する作品のポスターが選ばれ、無ければ記事に最初に出てくる作品になる。
手で別のパスを書けば、その記事は自動処理の対象から外れる。
→ [APPEARANCE.md の12節](../../../docs/APPEARANCE.md#12-記事のヘッダー画像frontmatter-の-heroimage)

> **ここ（常設ページのサービス画像）は自動化していない。**
> 作品のポスターはサービスを表さないので、置くと意味が変わる。
> 頭文字のタイルのままでも成立する設計にしてある。

> 生成物の `/cards/<スラッグ>.jpg` は**使わない**。
> 記事タイトルを焼き込んだSNS共有用の画像なので、見出しの上に置くとタイトルが二重に出る。
