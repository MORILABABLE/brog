# 記事テンプレート: 見放題配信開始（サービス別・月内更新）

このファイルを編集すれば、サービス別の配信開始記事の構成が変わる。
コードを触る必要はない。

- **記事の骨格（節の数・表の割り方）→ `writing.md` 0節**（全記事タイプ共通）
- 毎月そのまま使う文言 → `fixed-phrases.md`（`arrivals-service-` で始まるキー）
- **軸とタイトルの決まり → `naming.md`**（全記事タイプ共通）
- **文章の書き方の決まり → `writing.md`**（全記事タイプ共通）
- ジャンル別の配信開始記事 → `arrivals.md`
- 配信終了記事 → `leaving.md` / `ended.md`

## 軸とタイトル

**この記事の軸は「サービス1社」。他社を混ぜない。**
タイトルの形と更新版の扱いは `naming.md` にある。この記事の動詞句は `見放題配信が始まった`。

> 【2026年8月】Netflixで見放題配信が始まった作品199本｜エドワード・ヤン3作

★ **`｜` のあとに中心作を必ず1つ入れる**（2026-09-19）。
  新テンプレではリードから作品名が消えたので、**作品名が出るのはタイトルと見出しだけ**。
  ここに出す作品は、小段落1で解説する中心作から選ぶ。

## 記事の目的

**1つのサービスで、その月に見放題入りした作品を1本のURLで追い続ける。**

配信は月末までに何度も追加される。月初に書いた記事は月半ばには古くなるが、
記事を1本ずつ増やすと同じ検索語を自分同士で奪い合う。
そこで**同じURLを月内に何度も書き直す。** 記事が増えるのではなく、記事が育つ。

**読者が知りたいのは2つ。**

1. このサービスで、今月新しく何が観られるようになったのか
2. 前に見たときから何が増えたのか

### ジャンル別の配信開始記事（`arrivals.md`）との違い

**同じ作品が両方に出るが、切り口が違うので競合しない。**

| | ジャンル別（`arrivals`） | サービス別（この記事） |
| --- | --- | --- |
| 分け方 | アニメ / 洋画・海外ドラマ / 邦画・国内ドラマ | サービス1社 |
| サービス | 複数社を横断 | 1社だけ |
| 更新 | その月に1回 | **月内に何度も** |
| 読者 | 「アニメで何か観たい」 | 「プライムビデオで何が増えた？」 |

### ★ ジャンルを節の束ね方に使ってよい（2026-09-18 変更）

**もとは「この記事の中でジャンルの話をしない」だった。件数を前提にした決まりで、
いまの件数には合っていない。**

- **少ない月**（20〜40本）にジャンルで割ると、各節が3〜10本に痩せて
  ジャンル別記事（`arrivals.md`）の劣化版になる。だから禁じていた
- **多い月**は事情が逆になる。U-NEXT の2026年9月は268本で、
  新作起点・制作会社起点・シリーズ起点のどれにも入らない作品が大半を占める。
  このとき**読者が知っている束はジャンルしか残らない**

| その月の件数 | ジャンルの扱い |
| --- | --- |
| 概ね60本未満 | 使わない。新作・制作会社・シリーズで束ねる |
| **60本以上** | **他のまとまりが尽きたところで使ってよい** |

★ **もともと `writing.md` 10節と食い違っていた。** あちらは全記事タイプ共通で、
  制作会社を見出しに立てられないときは「**ジャンル・国・年代など読者が知っている束に替える**」
  と書いてある。同じプロンプトに両方が入っていたので、ここを合わせた。

★ **変わったのは節の束ね方だけで、軸はサービス1社のまま。**

- **タイトルにジャンルを名乗らない。** 名乗ると軸が2つになる（`naming.md`）
- ジャンル別記事の代わりにしない。**あちらの値打ちはサービスを横断すること**で、
  この記事がジャンルで節を切っても横断はしない

## 版（初回と更新回）

> **前の版の本文が付いている回は、作品ごとの解説を引き継ぐ。**
> 更新のたびに書き直すと、調べて書いた説明が別の文章に入れ替わって内容が痩せる。
> 決まりは `naming.md`「前の版の本文は引き継ぐ」（全記事タイプ共通）。

**この記事には2つの版がある。素材にどちらかが明示される。**

| | 初回 | 更新回 |
| --- | --- | --- |
| いつ | その月・そのサービスで初めて書くとき | 2回目以降 |
| タイトル | `naming.md` の初回の形 | `naming.md` の更新版の形 |
| リード | `arrivals-service-lead-first-sentence` | `arrivals-service-update-lead-first-sentence` |
| **小段落1** | その月の主要なまとまりから中心作2〜3作 | **今回追加された作品**から中心作2〜3作 |
| 前回までの分 | — | 落とさない。**小段落2の表**に一緒に並べる |

★ **節は増えない。** 更新回でも `##` は2つ＋まとめのまま（`writing.md` 0節）。
  今回追加された分は**小段落1の見出しに持たせる**。

> ★ **初回に「更新」と書かない。** 読者にとって「更新」は
> 「前に読んだものが変わった」という意味で、初回に付けると嘘になる。
> 素材が初回だと言っているのに更新回の形で書いたら、それは誤りとして検査で止まる。

## 「新たに追加」と書いてよい条件（最重要）

**素材には作品ごとに2つの日付が入る。混同すると誤情報になる。**

| 素材の項目 | 意味 |
| --- | --- |
| `配信開始日` | そのサービスで実際に見放題になった日 |
| `把握した日` | 当サイトがその作品を収集した日 |

この2つはずれる。**取りこぼしを後から拾うと、古い作品が今回の素材に現れる。**

| 状況 | 書いてよい言い方 | 書いてはいけない言い方 |
| --- | --- | --- |
| 配信開始日が前回の更新より**後** | 「新たに見放題配信が始まりました」 | — |
| 配信開始日が前回の更新より**前** | 「今回新たに確認されました」<br>「8月3日から見放題の対象になっています」 | 「新たに配信が始まりました」<br>「今回追加されました」 |

**素材には「前回の更新以降に配信開始」か「今回新たに確認」かが1件ずつ明示される。
そのラベルに従うこと。自分で日付を突き合わせて判断しない。**

> ★ ここを外すと「8月3日に始まった作品」を「8月26日に新たに追加」と書くことになる。
> 読者は配信開始日を見て記事を疑う。**この記事でいちばん壊れやすいのはここ。**

## 構成

**全体の骨格は `writing.md` 0節にある。** ここにあるのは、この記事タイプ固有の中身。

```
リード        arrivals-service-lead-first-sentence をそのまま（1組）
## 小段落1    中心の2〜3作    表 → 解説（最大1,000字）
## 小段落2    残りの全件      表 → 軽い言及（0〜2文）
## まとめ     100〜200字
```

### 1. リード

**`fixed-phrases.md` の文言をそのまま使う。**
初回は `arrivals-service-lead-first-sentence`、
更新回は `arrivals-service-update-lead-first-sentence`。**文型は変えない。**

**2段落目を書かない。** タイトルがすでに中心作を名乗っているので、
ここで作品名を挙げると同じ名前を2回読ませることになる（`writing.md` 0節）。

★ 以前あった「この版で伝わってほしい作品名を挙げる2段落目」と `arrivals-lead-closer` は
  **2026-09-19 に廃止した。**

### 2. 小段落1 — 中心の2〜3作

**更新回では「今回追加された作品」から、初回ではその月の主要な作品から選ぶ。**

| 版 | 小段落1の中身 |
| --- | --- |
| 初回 | その月の主要なまとまりから中心作2〜3作 |
| 更新回 | **今回追加された作品**から中心作2〜3作（★印が付いている） |

更新回で前回までに載っていた作品は落とさず、**小段落2の表に全件残す。**

★ **節は増えない。** 更新回でも `##` は2つ＋まとめのまま（`writing.md` 0節）。
  旧テンプレにあった「今回追加された作品」「今月のここまでの注目作」の2節は、
  **小段落1と小段落2に畳んだ**（2026-09-19）。

#### まとまりの見つけ方（この優先順で探す）

1. **新作起点** — シリーズの新作が動いている作品の過去作が入った
2. **制作会社起点** — 同じ制作会社の作品が複数入った（素材に「制作」として与えられる）
3. **シリーズ起点** — 同一シリーズの複数作が入った
4. **ジャンル** — 上のどれも尽きたときだけ（下の「ジャンルを節の束ね方に使ってよい」）

**日付をまたいでよい。** 日付で切ると、まとまりが見えなくなる。

#### 節の作り方（この順序を必ず守る）

```
## 「◯◯」シリーズ◯作が見放題配信開始

| 配信開始日 | 作品 | 出演者 | サービス |
| --- | --- | --- | --- |
| …… | …… | …… | …… |

（ここから作品の解説）
```

**必ず「見出し → 表 → 解説」の順にする。** 導入文を挟まない。

- 表の列は **配信開始日・作品・出演者・サービス** の4列で固定する（下の「表について」）
- **この表に載せるのは解説する2〜3作だけ。** 残りは小段落2の表
- **見出しを `## ○月○日：` で始めない**（2026-09-19 に変更）。
  節はまとまりで割るので、日付は表の列が持つ

#### ★ 解説は2〜3作・最大1,000字（2026-09-19・運用者の指定）

- 選ぶ基準は **①本数が多い ②名前が通っている** の2つ
- **4作以上を解説しない。** どうしても外せない作品は小段落2で1〜2文触れる
- **字数を守るために調べる深さを落とさない**（`writing.md` 11節）

**節の最後は作品の解説で終える。** 促し文句も助言も置かない。
ただし体言止め・尻すぼみにはせず、です・ます調の文で閉じる。

### 2-5. 「どこで観られるか」は表が答える

在庫台帳に載っている作品では、**サイトが表の各行の下に1行足す**
（`site/plugins/rehype-availability.ts`）。記事側は何も書かなくてよい。
決まりは `leaving.md` の 2-5 と同じ。

★ **「他のサービスで探す」の節は作らない**（2026-09-19 に廃止）。
  同じ行き先が表の行ごとに出ているので、末尾にもう一度並べる意味がない
  （`writing.md` 0節）。「配信中」とは絶対に書かない。

### 3. 小段落2 — 残りの全件

**小段落1で解説しなかった作品を、1つの表に漏れなく載せる。**

```
## そのほかに配信開始した◯本

| 配信開始日 | 作品 | 出演者 | サービス |
| --- | --- | --- | --- |
| …… | …… | …… | …… |

（特筆すべき1〜2作だけを1〜2文。無ければ表だけでよい）
```

**この記事タイプの中心的な約束は網羅。** その月の全件をここに載せる
（ジャンル判定が要らないので、1本でその月を漏れなく扱えるのがこの記事の値打ち）。

- **表が主役。** 表の下は0〜2文で足りる（`writing.md` 7節）
- **作品名を並べただけの段落を作らない**（`writing.md` 7節）
- **小段落1に出した作品をここにもう一度出さない**

★ 旧テンプレの「その他の注目作」「全作品リスト」は、**この節が兼ねる**（2026-09-19 に統合）。

★ **表の直下に配信カレンダーへのリンクがサイト側で入る。** 本文には書かない。

### 4. まとめ（100〜200字）

その月に増えた作品を1〜2点に絞って再提示する。
読者がここだけ読んでも要点が分かる状態にする。

「目玉」「注目」のような比喩は使わず、**「見放題配信が始まりました」と言い切る**。
**評価上位◯本のような順位付けは書かない。**

## 表について

**表の列は4列で固定する。1サービスの記事でもサービス列を省かない。**

サイトはビルド時に表の作品名をリンクに変える。そのとき
**行のサービス列を読んで送り先を決めている**（`site/src/lib/work-links.ts`）。
列を省くと、複数サービスにある作品の行が別のサービスの作品ページへ飛ぶ。

同じ理由で、**作品名のセルには作品名だけを書く。**
括弧書きの補足や記号を足すと、台帳と一致せずリンクが付かなくなる。

> 表の各行の画像も、リンクも、ビルド時に自動で入る。記事に書くことは何も無い。

## どれくらい書くか

**解説するのは中心の2〜3作だけ**（2026-09-19 に 12〜15作品から変更）。
全作品に1文ずつ付けると、どれも印象に残らないまま読み飛ばされる。

| 版 | 小段落1で解説する作品 |
| --- | --- |
| 初回 | その月の主要なまとまりから2〜3作 |
| 更新回 | **今回追加された作品**から2〜3作 |

- 残りは小段落2の表で網羅する（表からは1本も落とさない）
- **絞る基準は知名度。** 評価スコアは同じくらいの知名度の作品を比べるときの決め手にしか使わない
- **絞るのは本数であって、調べる深さではない**（`writing.md` 11節）

## 文体

`arrivals.md` と同じ。要点だけ再掲する。

- です・ます調
- **記号は全角に統一する。** `！` `？` `（）` を半角で書かない
  （作品名に含まれる半角記号は正式表記なのでそのまま使う）
- 誇張しない。「衝撃」「必見」「神作」等の煽り文句は使わない
- **評価スコアは記事に出さない**（表からも外した。下の「評価の列は置かない」）
- **急かさない。** 配信開始記事には締切が無い。
  「ぜひ観ましょう」「見逃せません」は使わない
  （「〜してみましょう」程度の穏やかな誘いは構わない。`writing.md` 1節）
- **編集部のおすすめを書かない。** 「まず1本選ぶなら」「この日から観るなら」も書かない
- 「配信開始」ではなく **「見放題配信開始」** を基本語にする（購入・レンタルと区別するため）

### この記事だけの言い回し

- サービス名は**記事を通して同じ表記**にする（`Amazon Prime Video`）。
  「プライムビデオ」「アマプラ」と揺らさない
- 前の版に触れてよいが、**前の版の本数を書かない。**
  「前回は162本でした」は、読者が前の版を見ていない限り意味を持たない
- **他サービスとの比較を書かない。** この記事は1サービスの話に徹する

## データの外にあることを書くとき

`arrivals.md` と同じ。

### 書いてよい

- 素材に与えられた制作会社（Wikidata で裏付けたもの）
- 広く知られたシリーズの継続性（「シリーズの新作が続いています」）
- 原作の存在、実写化されていることなど、広く知られた事実

### 書いてはいけない

- **新作の放送開始日・公開日・シーズン番号などの具体的な日付や数字**
- **あらすじ・登場人物・筋書きをデータ無しに書くこと**
- 確度が低いと自分で感じたこと。**迷ったら書かない**

## 絶対に守ること

- **「新たに配信が始まった」と書いてよいのは、素材がそう明示した作品だけ**（上の表）
- **初回の版に「更新」と書かない**
- **邦題が確認できていない作品は原題のまま書く。** 推測で日本語タイトルを作らない
- **あらすじが与えられていない作品の内容を書かない**
- **人名は素材に出ているものだけを書く。素材に無ければ人名に触れない。**
  素材の人名は `npm run enrich` が Wikidata から**日本語表記で**引いたもの。
  引けなかった作品には人名の行が無い。**英語やローマ字で補ってはいけない。**
  あらすじの英文に人名が出てきても、**地の文に写さない**
- **出演者の並び順に意味を持たせない。** Wikidata 由来で**主演順ではない**。
  「主演は」「1番手は」と書かず、「◯◯や◯◯が出演しています」と並べるだけにする
- 与えられた配信開始日以外の日付を書かない
- 与えられていない作品を追加しない
- **配信開始済みと配信開始予定を混ぜない**
- **小段落2の表からは1本も落とさない**
- `fixed-phrases.md` の文言は一字一句そのまま使う
- 記事の末尾に配信情報の提供元表記を必ず入れる

#### ★ 「評価」の列は置かない（2026-09-08 変更）

**評価スコアは記事のどこにも出さない。** 表にも地の文にも書かない。
読者が表で知りたいのは「いつ」「どこで」「誰が出ているか」で、
**100点満点の数字はその判断に使われていない。**
その1列を、読者が実際に探している**出演者**に置き換えた（2026-09-08・運用者の指定）。

★ **素材からは無くなっていない。** 評価は引き続き素材に入っていて、
  **表の行を並べる順番を決める目安**として使う。記事に出さないだけ。

#### ★ 「出演者」の列は主演＋助演の2名まで（2026-09-08 追加）

**網羅しない。** 素材の `出演` の行から、主演と助演を1名ずつ選ぶ。

| | 書き方 |
| --- | --- |
| 実写 | `佐藤健、蒼井優` のように**2名まで** |
| **アニメ** | **`キャラ名（CV.声優）`** の形にする |
| 素材に `出演` の行が無い | **`—`**。推測で埋めない（U-NEXT の作品に多い） |

★ **素材の `出演` は並び順が主演順ではない。** どちらが主演か分からない作品では、
  代表として2名を挙げるだけにして「主演」と書かない。
★ 表の下に「出演者」の箇条書きを置くのは**主題が1つの記事（`series` / `special`）だけ**。
  月次記事は作品がばらばらなので、主演をまとめて名乗れない（`writing.md` 6節）。
