# 記事テンプレート: 特報

このファイルを編集すれば、全ての特報記事の構成が変わる。コードを触る必要はない。

- 毎月そのまま使う文言 → `fixed-phrases.md`（`special-` で始まるキー）
- **軸とタイトルの決まり → `naming.md`**（全記事タイプ共通）
- **文章の書き方の決まり → `writing.md`**（全記事タイプ共通）
- 月次のまとめ記事 → `leaving.md` / `ended.md` / `arrivals.md` / `arrivals-service.md`

## 軸とタイトル

**この記事の軸は「主題1つ」。** 作品・シリーズ・出来事など、人が指定した主題を扱う。
主題の記事なので**サービスを横断してよい**し、1社の話ならその社名をタイトルに出してよい。

動詞句は `--kind` で決まる。

| `--kind` | 動詞句 | 記事の性格 |
| --- | --- | --- |
| `new` | `見放題配信開始` | 観られるようになった。**急かさない** |
| `expiring` | `見放題配信終了予定` | これから終わる。締切がある |
| `removed` | `見放題配信終了` | **もう観られない**。次の一手だけを渡す |

> 【2026年9月】Netflixで「007」シリーズ5作が見放題配信終了予定｜9月30日まで
> 【2026年8月】スタジオジブリ作品が見放題配信開始｜Netflixほかで21作

### ★ 問いを置くのは `removed` だけ（2026-09-10 に整理）

`--kind removed`（**もう観られない**）のときだけ、主題の直後に `はどこで見れる？` を置く。
**`expiring` には置かない。** その記事の作品はまだ観られるうえ、
行き先は**表の在庫の行がもう答えている**（下の「どこで見れるか」の項）。

| `--kind` | タイトル | 例 |
| --- | --- | --- |
| `expiring` | 問いを置かない | 【2026年9月】ワーナー系アニメの見放題配信終了予定の作品32本｜U-NEXTでアドベンチャー・タイム全10期 |
| `removed` | `{主題}はどこで見れる？` | 【2026年9月】「007」シリーズはどこで見れる？見放題配信終了 |

★ 2026-09-10 に `expiring` にも足して、同じ日に戻した。**問いかけが過剰になる**
  （運用者の判断。`naming.md`「終わった記事は問いから入る」に経緯がある）。

## 月次のまとめ記事と何が違うか

**月次記事は「その月に何があったか」、特報は「この主題に何が起きたか」。**

| | 月次記事 | 特報 |
| --- | --- | --- |
| 軸 | サービス／ジャンル | **主題** |
| いつ書くか | 毎月・決まった形で | **人が決めたときだけ** |
| 範囲 | その月の全件 | **主題に当たる作品だけ** |
| 網羅性 | 表からは1本も落とさない | 同じ（渡された素材は全件載せる） |

**「今月の配信終了作品一覧」のような書き方をしない。** それは月次記事の仕事で、
同じことを2本書くと同じ検索語を自分同士で奪い合う。
（素材の側でも、絞り込み（`--match` / `--from` / `--to`）を1つも渡さないと
生成が止まるようにしてある。）
特報が答えるのは「**その主題が、どこで、いつまで（いつから）観られるのか**」だけ。

**主題から離れない。** 与えられた作品の話に徹する。
「ほかにもこんな作品が終了します」と広げない。

## 構成

**全体の骨格は `writing.md` 0節にある。** ここにあるのは、この記事タイプ固有の中身。

```
リード        --kind で決まる固定文言をそのまま（1組）
## 小段落1    中心の2〜3作    表 → 解説（最大1,000字）
## 小段落2    残りの全件      表 → 軽い言及（0〜2文）
## まとめ     100〜200字
```

### 1. リード

**`fixed-phrases.md` の文言をそのまま使う**（`--kind` で決まる）。
主題・サービス名・基準日・本数だけが差し替わる。**文型は変えない。**

**2段落目を書かない。** タイトルがすでに中心作を名乗っているので、
ここで作品名を挙げると同じ名前を2回読ませることになる（`writing.md` 0節）。

★ 以前あった「主題の中で名前の通った作品を挙げる2段落目」とリードの締めの固定文言は
  **2026-09-19 に廃止した。**

★ **終了日の内訳を書かない**（「◯◯だけが9月26日、残る27本は9月30日です」）。
  本文に影響しない数字で、日付は表の列が持っている（`writing.md` 11節）。
  リードが固定文言だけになったので書く場所は無いが、**まとめでも同じ。**

### 2. 小段落1 — 中心の2〜3作（この記事の中心）

主題の中で**名前の通った2〜3作**を選び、そこに調べた事実を集中させる。

```
## 「◯◯」シリーズ◯作が終了予定

| 終了日 | 作品 | 出演者 | サービス |
| --- | --- | --- | --- |
| …… | …… | …… | …… |

**出演者**

- 佐藤健（実写5作すべてに主演）

（ここから作品の解説）
```

**必ず「見出し → 表 → 解説」の順にする。** 導入文を挟まない。

- 表の列は **日付・作品・出演者・サービス** の4列で固定する
- **この表に載せるのは解説する2〜3作だけ。** 残りは小段落2の表
- **見出しを日付で始めない。** 節はまとまりで割るので、日付は表の列が持つ

#### 表の直後の「出演者」の箇条書き

**主題が1つの記事なので、読者がいちばん知りたいのは「誰が演じているのか」の1点。**
サイトがこの箇条書きを小さな枠にたたむので、**文章にせず、短く書く**。

- アニメは**キャラ名（CV.声優）**の形で書く
- **記事に1回だけ。小段落1の表の下にだけ**置く
- **主演と書けるのは、素材のリサーチに「主演・◯◯」のような記述がある作品だけ。**
  確かめられない記事では、**この箇条書きごと置かない**

#### ★ 解説は2〜3作・最大1,000字（2026-09-19・運用者の指定）

- 選ぶ基準は **①本数が多い ②名前が通っている** の2つ
- **4作以上を解説しない。** どうしても外せない作品は小段落2で1〜2文触れる
- **見出しの「」に入れた作品を、その節の中心作にする。**
  見出しに出して本文で触れない形にしない
- **絞るのは本数で、調べる深さではない。** 中心作は下調べを取り切り
  （項目なしは `npm run research -- --force` で取り直す）、1本に事実を2〜4文使って
  ファンが読んでも納得する水準で書く（`writing.md` 11節「絞るのは本数」）

■ なぜ絞るのか

**節ごとに同じ密度で解説を続けると、読者が最後まで持たない。**

> サービス全体の終了記事のはずが、タイトルではコナンに触れるのみ。
> コナンに触れる段落で終了のはずが他作品も解説するので、
> 読者は疲れを感じる構成になってしまっている。

6つの節すべてに表と解説を並べた版で出た指摘（2026-09-10）。
**読者が読むのは、自分が探していたまとまりの1つだけ。**

★ **表を薄くするのではない。** 全作品が表に載っている状態は変えない
  （抜けがあるとこの記事は用を成さない）。**変えるのは解説の配分だけ。**

#### ★ 「どこで見れるか」は表が答える。文章で書かない（2026-09-10）

在庫台帳（`data/availability.json`）に載っている作品では、
**サイトが表の各行の下に1行足す**
（`site/plugins/rehype-availability.ts`）。記事側は何も書かなくてよい。

    | 終了日  | 作品                        | 出演者 | サービス |
    | 9月30日 | アドベンチャー・タイム シーズン1 | —      | U-NEXT   |
    | [配信中]  ● Netflix   × Amazon Prime Video   △ Apple TV+  |  ← サイトが足す行

- **頭のラベルは枠付きで、文字も色もサイトが決める。** 文字にも色にも触れない
- **その行のサービスも含めて4社ぶん出る**（2026-09-15 変更）。印は在庫台帳のままで、
  終了予定の行は終了日まで ●、終了済みの行は自動で △ か × に落ちる
- **行も列も自分で書き足さない。** 表は4列のまま書く
- **在庫を段落で説明しない。** 同じ事実が表と文章の2か所になり、
  書き直すたびに片方だけ古くなる（docs/FUNNEL.md 5-3）
- まとめでは**表を指すだけ**にする

★ **「他のサービスで探す」の節は作らない**（2026-09-19 に廃止）。
  同じ行き先が表の行ごとに出ているので、末尾にもう一度並べる意味がない
  （`writing.md` 0節）。「配信中」とは絶対に書かない
  （他社の配信状況データを持っていない）。

★ 在庫は `npm run availability` が取る。**`--emit` のあとに実行して、もう一度 `--emit`**。
  取れなかった作品は行が出ないだけで、**「どこにも無い」と書いてはいけない。**

### 3. 小段落2 — 残りの全件

**小段落1で解説しなかった作品を、1つの表に漏れなく載せる。**

```
## そのほかの◯本

| 終了日 | 作品 | 出演者 | サービス |
| --- | --- | --- | --- |
| …… | …… | …… | …… |

（特筆すべき1〜2作だけを1〜2文。無ければ表だけでよい）
```

- **渡された作品を1本残らず、どちらかの表に載せる**
- **表が主役。** 表の下は0〜2文で足りる（`writing.md` 7節）
- **作品名を並べただけの段落を作らない**（2026-09-10 追加・`writing.md` 7節）
- **小段落1に出した作品をここにもう一度出さない**

★ 旧テンプレの「対象作品リスト（全件）」は、**この節が兼ねる**（2026-09-19 に統合）。

★ **表の直下に配信カレンダーへのリンクがサイト側で入る。** 本文には書かない。

### 4. まとめ（100〜200字）

主題について、読者が次に取れる行動を1〜2点で示して終える。
`--kind removed` では「他で探せます」、それ以外では日付を添えて締める。

## 文体

月次記事と同じ。要点だけ再掲する。

- です・ます調
- **記号は全角に統一する。** `！` `？` `（）` を半角で書かない
  （作品名に含まれる半角記号は正式表記なのでそのまま使う）
- 誇張しない。「衝撃」「必見」「神作」等の煽り文句は使わない
- **評価スコアは記事に出さない**（表からも外した。下の「評価の列は置かない」）
- 「配信開始」ではなく **「見放題配信開始」**（購入・レンタルと区別するため）
- サービス名は**記事を通して同じ表記**にする。略称に言い換えない

### `--kind` ごとの締め方

| `--kind` | 節の締め | 禁止 |
| --- | --- | --- |
| `new` / `upcoming` | 作品の紹介か、穏やかな誘い（「〜してみましょう」） | 「ぜひ観ましょう」「見逃せません」などの煽り。編集部のおすすめ |
| `expiring` | 「〜しましょう」など視聴を促す形 | 視聴の命令。終了を過去形で書くこと |
| `removed` | 「〜で探せます」など次の一手 | **「お見逃しなく」「今のうちに」「配信中です」（公開が止まる）** |

## 版（初回と更新版）

> **前の版の本文が付いている回は、作品ごとの解説を引き継ぐ。**
> 更新のたびに書き直すと、調べて書いた説明が別の文章に入れ替わって内容が痩せる。
> 決まりは `naming.md`「前の版の本文は引き継ぐ」（全記事タイプ共通）。

**同じ `--slug` で書き直せば更新版になる。** URLも被リンクもそのまま残る。

- 更新版はタイトルの本数の直後に `【{月}月{日}日更新】` を置く（`naming.md`）
- 初回に「更新」と書かない。前の版が無いので嘘になる
- **節は増えない。** 更新版でも `##` は2つ＋まとめのまま（`writing.md` 0節）
- リードは初回と同じ固定文言を使う。
  **特報は「その月に何が増えたか」を追う記事ではない**ので、
  月次記事のような更新版専用の文言は用意していない。
  基準日（`{基準日}時点`）が入れ替わることで、いつ時点の情報かは伝わる

## 絶対に守ること

- **主題から離れない。** 与えられていない作品を追加しない
- **渡された作品は、小段落1か小段落2のどちらかの表に全件載せる**
- **「特報」という単語を記事に書かない。** タイトル・説明文・本文・見出しのどこにも出さない。
  これは**この仕組みの内側で記事タイプを呼び分けるための名前**であって、読者には意味がない
  （読者が探しているのは「◯◯が終わる」であって「特報」ではない）。
  「速報」「緊急」など、同じ役割の言い換えも同じ理由で書かない
- **`--kind removed` で「まだ観られる」と読ませない**（公開が止まる）
- **U-NEXT を含む記事で「観られなくなる」と断定しない。**
  ポイント（レンタル・購入）で残る作品がある。「見放題での配信が終了します」と書く
- **邦題が確認できていない作品は原題のまま書く。** 推測で日本語タイトルを作らない
- **あらすじが与えられていない作品の内容を書かない**
- **人名は素材に出ているものだけを書く。** 素材に無ければ人名に触れない。
  あらすじの英文に人名が出てきても、地の文に写さない
- 与えられた日付以外の日付を書かない
- `fixed-phrases.md` の文言は一字一句そのまま使う
- 記事の末尾に配信情報の提供元表記を必ず入れる。
  **素材が複数の出どころにまたがる月は、その全部を入れる**

#### ★ 「評価」の列は置かない（2026-09-08 変更）

**評価スコアは記事のどこにも出さない。** 表にも地の文にも書かない。
読者が表で知りたいのは「いつ」「どこで」「誰が出ているか」で、
**100点満点の数字はその判断に使われていない。**
その1列を、読者が実際に探している**出演者**に置き換えた（2026-09-08・運用者の指定）。

★ **素材からは無くなっていない。** 評価は引き続き素材に入っていて、
  **表の行を並べる順番を決める目安**として使う。記事に出さないだけ。

#### ★ 「出演者」の列は主演＋助演の2名まで（2026-09-08 追加）

**網羅しない。** 素材の `出演` の行から、主演と助演を1名ずつ選ぶ。

| | 書き方 |
| --- | --- |
| 実写 | `佐藤健、蒼井優` のように**2名まで** |
| **アニメ** | **`キャラ名（CV.声優）`** の形にする |
| 素材に `出演` の行が無い | **`—`**。推測で埋めない（U-NEXT の作品に多い） |

★ **素材の `出演` は並び順が主演順ではない。** どちらが主演か分からない作品では、
  代表として2名を挙げるだけにして「主演」と書かない。
★ 表の下に「出演者」の箇条書きを置くのは**主題が1つの記事（`series` / `special`）だけ**。
  月次記事は作品がばらばらなので、主演をまとめて名乗れない（`writing.md` 6節）。
