# 記事テンプレート: 配信終了済み

このファイルを編集すれば、全ての「配信終了済み」記事の構成が変わる。
コードを触る必要はない。

- 毎月そのまま使う文言 → `fixed-phrases.md`（`ended-` で始まるキー）
- **軸とタイトルの決まり → `naming.md`**（全記事タイプ共通）

## 軸とタイトル

**この記事の軸は「サービス1社」。他社を混ぜない。**
タイトルの形と更新版の扱いは `naming.md` にある。この記事の動詞句は `見放題配信が終了した`。

> 【2026年8月】Disney+で見放題配信が終了した作品76本まとめ
> 【2026年9月】Disney+で見放題配信が終了した作品48本｜名探偵コナン劇場版22作と評決のとき

★ **`どこで見れる？` をタイトルに入れない**（2026-09-10）。
  行き先は**表の在庫の行がもう答えている**（下の 2-5）。タイトルでも同じことを聞くと過剰になる。
  問いを置くのは主題軸の「終了済み」だけ（`naming.md`「終わった記事は問いから入る」）。

★ **いちばん大きいまとまりは `｜` のあとに置く。** 本文の主語にはするが、
  **記事の名乗りはあくまで「その月・そのサービスで終了した全◯本」。**
  まとまりを先頭に出すと、48本を扱う記事が22本の記事に見える（2026-09-10・運用者の指摘）。

★ **「他のサービスで探す」の節は横断ではない。** 軸を1社に保ったまま行き先を出しているだけで、
この記事ではその節が中心。「サービスを混ぜない」を理由に削らないこと。

## 版（初回と更新版）

> **前の版の本文が付いている回は、作品ごとの解説を引き継ぐ。**
> 更新のたびに書き直すと、調べて書いた説明が別の文章に入れ替わって内容が痩せる。
> 決まりは `naming.md`「前の版の本文は引き継ぐ」（全記事タイプ共通）。

**同じ月・同じサービスの記事は1本しか作らない。2回目からは書き直す。**
素材にどちらの版かが明示される。

| | 初回 | 更新版 |
| --- | --- | --- |
| タイトル | `naming.md` の初回の形 | `naming.md` の更新版の形 |
| リードの1文目 | `ended-lead-first-sentence` | `ended-update-lead-first-sentence` |
| 記事の中心 | その月に終了した作品の全体 | **今回新たに終了が確認された作品** |
| 前回までの分 | — | 落とさない。同じ表に一緒に並べる |

更新版では、リードの直後に今回確認された分（素材に ★ が付いた作品）を置く。
**前の版の本数は書かない。** 初回に「更新」と書かない（前の版が無いので嘘になる）。

## この記事が存在する理由

**API が「配信終了予定」を返さないサービスがあるため。**

Netflix と Amazon Prime Video は終了予定日が取れるので、`leaving.md`（配信終了予定）の
記事で**終了前に**知らせられる。しかし Disney+ ではそれが取れず、
終了したという事実が後から分かるだけになる。

黙って落とすと、そのサービスの終了情報が読者に一切届かない。
だから**終了後でも届ける**。ただし価値の出し方は配信終了予定の記事とまったく違う。

## 記事の目的

**読者が「観そびれた作品を、他のサービスで探せる」ようにする。**

この記事を読む人は、すでに観る機会を逃している。
急かしても、おすすめしても、その人は作品を観られない。
**唯一渡せる価値は「まだどこかで観られるかもしれない」という次の一手**である。

**読者が知りたいのは2つだけ。**

1. 何が終了したのか（自分が観そびれたものが含まれるか）
2. それを今から観る方法はあるのか

## 絶対に守ること（この記事タイプの生命線）

**もう観られない作品を「観られる」と読ませたら、この記事は読者を裏切る。**

次の表現は**一切使ってはいけない**。品質チェックで公開が止まる。

| 禁止 | 理由 |
| --- | --- |
| お見逃しなく／見逃せません | もう見逃した後である |
| 今のうちに／まだ間に合います | 間に合っていない |
| 観ておきましょう／チェックしておきましょう | 観る手段が無い |
| 配信中です／視聴できます | 終了した事実と矛盾する |

**U-NEXT・Hulu・DMM TV について「配信中」と書かない。**
当サイトはこれらの配信状況データを持っていない。書けるのは検索リンクまで。

> 悪い例: 「U-NEXTで配信中なので今すぐ観られます」
> 良い例: 「U-NEXTなどでの取り扱いは、以下のリンクから確認できます」

**終了日はデータにあるものだけを書く。** 推測して補わない。

## 構成

### 1. リード（2段落）

1段落目は `fixed-phrases.md` の `ended-lead-first-sentence` をそのまま置く。

2段落目では、終了した作品のうち**知名度の高いものを、まとまりの大きい順に**、
作品名・シリーズ名を「」で囲んで挙げる。
段落の最後は `ended-lead-closer` をそのまま置いて締める。

★ **終了日順に並べ直さない**（2026-09-10 に変更）。読者が探しているのは作品であって
  日付ではない。**いちばん大きいまとまりを最初に出す。**
  「9月2日に◯本、9月3日に◯本、9月4日に◯本」という日付の刻みは、
  **書き手の観測を読者に読ませているだけ**で、読む理由にならない。

**記事の作り方の解説は書かない。** 読者の関心は作品であって、記事の構造ではない。

### 2. シリーズ・主題ごとのまとまり

**節はシリーズ・主題で割る。終了日で割らない**（2026-09-10 に変更。下の理由）。

#### まとまりの見つけ方（この優先順で探す）

1. **シリーズ起点** — 同一シリーズの複数作が終了した
2. **制作会社起点** — 同じ制作会社の作品が複数終了した（素材に「制作」として与えられる）
3. **ジャンル・国起点** — 韓国ドラマ、ドキュメンタリーなど、まとまって外れた束
4. 上のどれでもなければ、終了日でまとめる

**1〜3は日付をまたいでよい。** これがこの節でいちばん大事な決まり。

#### ★ 時系列で節を割らない（2026-09-10・運用者の指摘）

**同じシリーズが日付をまたいでいても、1つの節にまとめる。**

前の版の Disney+ 記事は「名探偵コナン」劇場版22作が9月2日・3日・4日に分かれて
終了したのを、**日付どおり3つの節に割っていた。**

> コナン記事は、時系列順にまとめるという点を重視しすぎており、
> コナンを3段落に分けており読みにくいです。
> → 段落を作品シリーズごとに分ける〇　時系列でまとめるはNG

■ なぜ日付で割ってはいけないのか

- **読者は日付で探していない。** 探しているのは作品とシリーズで、
  「9月3日に何が終わったか」を知りたい人はいない
- **同じ解説が3回に割れる。** シリーズの説明を節ごとに繰り返すか、
  どこか1つに寄せて他を痩せさせるかの二択になり、どちらも読みにくい
- **まとまりが見えなくなる。** 22作が同じシリーズだという、この記事でいちばん
  大きい事実が、3つに割れた時点で読者に伝わらない

■ 日付はどこへ行くのか

**表の「終了日」列が持つ。** 節がまたいでいれば、行ごとに実際の終了日を書く。
**日付は行の属性であって、節の見出しではない。**

★ 同じ決まりが `arrivals.md`（配信開始）にもある。
  「分かれて入ったなら、1つの節にまとめる。日付で切ると、まとまりが見えなくなる」。
  終了側だけ日付優先で残っていたのを、ここで揃えた。

#### 節の作り方（この順序を必ず守る）

```
## 「◯◯」シリーズ◯作が終了

（表：終了日 / 作品 / 出演者 / サービス の4列で固定）

（解説の段落）
```

**見出しの直後に導入文を挟まない。** いきなり表を置く。
読者はまず一覧を掴みたい。文章はその後でいい。

#### ★ 解説を厚く書く節は2つまで。残りは表と短いまとめ（2026-09-10・運用者の指定）

**本数が多く、名前の通ったまとまりを2つ選んで、その2つだけを解説する。**
残りは**1つの節にまとめて、表と数文のまとめ**で終える。

```
## （厚い節1）「◯◯」シリーズ◯作が終了     ← 表 ＋ 解説2〜3段落
## （厚い節2）◯◯制作の◯作が終了           ← 表 ＋ 解説2〜3段落
## そのほかに終了した◯本                    ← 表 ＋ まとめ3〜5文
```

- 厚い節を選ぶ基準は **①本数が多い ②名前が通っている** の2つ
- まとまりの作り方は上と同じ（**シリーズ・制作会社・監督**などの繋がり）
- **3つ目を厚く書かない。** どうしても外せない作品は「そのほか」の節で1〜2文触れる
- 「そのほか」の節も**表には全件載せる**。落とすのは解説であって作品ではない

■ なぜ2つで止めるのか

**節ごとに同じ密度で解説を続けると、読者が最後まで持たない。**

> サービス全体の終了記事のはずが、タイトルではコナンに触れるのみ。
> コナンに触れる段落で終了のはずが他作品も解説するので、
> 読者は疲れを感じる構成になってしまっている。

6つの節すべてに表と解説を並べた版で出た指摘（2026-09-10）。
**読者が読むのは、自分が探していたまとまりの1つか2つだけ。**
残りは「自分の観そびれたものが入っているか」を表で確かめられればよく、
そこに同じ厚さの文章を置いても読まれないまま記事が長くなる。

★ **表を薄くするのではない。** 全作品が表に載っている状態は変えない
  （抜けがあるとこの記事は用を成さない）。**変えるのは解説の配分だけ。**

#### 見出しは「何が」で始める。「いつ」で始めない

> 悪い例: `## 9月4日：「名探偵コナン」劇場版12作が終了`（日付が主語になっている）
> 悪い例: `## 8月14日：アニメ作品が終了`（何が終わったのか分からない）
> 良い例: `## 「名探偵コナン」劇場版22作が終了`
> 良い例: `## リージェンシー・エンタープライズ制作の7作が終了`

★ **見出しに `はどこで見れる？` を並べない**（2026-09-10）。
  見出しは**その節に何があるか**を示す場所で、問いを並べると
  **どの節も同じ顔になって目次として区別が付かない。**

#### 解説では評価スコアに触れない

**評価は記事のどこにも出さない**（表からも外した。下の「評価の列は置かない」）。

#### 各まとまりの最終段落は「探す」で締める

配信終了予定の記事は「観ましょう」で締めるが、**この記事はそれができない。**
代わりに次の一手を示して締める。

> 「配信終了後も、他のサービスでの取り扱いを確認できます。」
> 「シリーズをまとめて観たい場合は、以下の検索リンクから探してみましょう。」

### 2-5. ★ 「どこで見れるか」は表が答える。文章で書かない（2026-09-10 追加）

在庫台帳（`data/availability.json`）に載っている作品では、
**サイトが表の各行の下に1行足す**
（`site/plugins/rehype-availability.ts`）。記事側は何も書かなくてよい。

    | 終了日 | 作品                        | 出演者 | サービス |
    | 9月4日 | 名探偵コナン 時計じかけの摩天楼 | —      | Disney+  |
    | [配信中]  ● Netflix   × Amazon Prime Video   △ Apple TV+  |  ← サイトが足す行

- **頭のラベルは枠付きで、文字も色もサイトが決める**
  （○があれば「配信中」＝青／△だけなら「有料で配信中」＝黄／×だけなら「取り扱いなし」＝赤）。
  **文字にも色にも触れない。** 本文で言い換えるのも禁止
- **その行のサービス（上の例なら Disney+）はサイト側が外す。**
  「終わった行に、そこで観られると出す」ことにならないようにするため
- **行も列も自分で書き足さない。** 表は4列のまま書く
- **「◯月◯日時点」も書かなくてよい。** 表の凡例が持っている
- **在庫を段落で説明しない。** 同じ事実が表と文章の2か所になり、
  書き直すたびに片方だけ古くなる。**答えは表に置いたほうが届く**
  （実測でスクロール90%到達は22%。docs/FUNNEL.md 5-3）
- まとめでは**表を指すだけ**にする（「上の表のとおりです」）

★ 在庫は `npm run availability` が取る。**`--emit` のあとに実行して、もう一度 `--emit`**。
  取れなかった作品は行が出ないだけで、**「どこにも無い」と書いてはいけない。**

### 3. 全終了作品リスト

その月に終了した作品を**漏れなく全件**、表で並べる。
列は「終了日 / 作品 / 出演者 / サービス」。

読者は自分が観そびれた作品を探しに来る。抜けがあると用を成さない。

★ **構成2ですべての作品が表に出ているなら、この節は省く**（2026-09-10 追加）。
  節をシリーズ・主題で割るようにしたことで、**全作品がどこかの節の表に載る月**が出てきた。
  そのとき全件リストを足すと、

  - 同じ48行を読者が2回たどることになる
  - **表の下の在庫の行も2回出る**（構成2-5。48行が96行に膨らむ）

  ので、**全件が本文の表に出ていることだけを確かめて省く。**
  1作でも漏れているなら省かない（抜けがあると、この記事は用を成さない）。

### 4. 他のサービスで探す

冒頭に `fixed-phrases.md` の `other-services-intro` をそのまま置く。
そのうえで、主要な作品について検索リンクを並べる。

**この節がこの記事の中心である。** 配信終了予定の記事では補足だが、
こちらでは読者に渡せる唯一の実用情報になる。省略も短縮もしない。

### 5. まとめ（100〜200字）

その月に終了した作品を振り返り、他サービスで探す導線をもう一度示して閉じる。
**次の月も終了情報を追う旨を書いてよい**が、煽らない。

記事の末尾に `fixed-phrases.md` の `attribution` をそのまま置く。

## 文体

- 常体ではなく敬体（です・ます）
- 1作品あたり1〜2文。踏み込んだ作品解説はここでは書かない
- 記号は全角に統一する（！ ？ （ ） を半角で書かない）
  ただし作品名に含まれる半角記号は正式表記なのでそのまま使う
- **終了は過去形で書く。** 「終了します」ではなく「終了しました」
- 煽らない。読者はすでに機会を逃しており、急かす理由が無い

#### ★ 「評価」の列は置かない（2026-09-08 変更）

**評価スコアは記事のどこにも出さない。** 表にも地の文にも書かない。
読者が表で知りたいのは「いつ」「どこで」「誰が出ているか」で、
**100点満点の数字はその判断に使われていない。**
その1列を、読者が実際に探している**出演者**に置き換えた（2026-09-08・運用者の指定）。

★ **素材からは無くなっていない。** 評価は引き続き素材に入っていて、
  **表の行を並べる順番を決める目安**として使う。記事に出さないだけ。

#### ★ 「出演者」の列は主演＋助演の2名まで（2026-09-08 追加）

**網羅しない。** 素材の `出演` の行から、主演と助演を1名ずつ選ぶ。

| | 書き方 |
| --- | --- |
| 実写 | `佐藤健、蒼井優` のように**2名まで** |
| **アニメ** | **`キャラ名（CV.声優）`** の形にする |
| 素材に `出演` の行が無い | **`—`**。推測で埋めない（U-NEXT の作品に多い） |

★ **素材の `出演` は並び順が主演順ではない。** どちらが主演か分からない作品では、
  代表として2名を挙げるだけにして「主演」と書かない。
★ 表の下に「出演者」の箇条書きを置くのは**主題が1つの記事（`series` / `special`）だけ**。
  月次記事は作品がばらばらなので、主演をまとめて名乗れない（`writing.md` 6節）。
