# 記事テンプレート: 配信終了済み

このファイルを編集すれば、全ての「配信終了済み」記事の構成が変わる。
コードを触る必要はない。

- 毎月そのまま使う文言 → `fixed-phrases.md`（`ended-` で始まるキー）
- **軸とタイトルの決まり → `naming.md`**（全記事タイプ共通）

## 軸とタイトル

**この記事の軸は「サービス1社」。他社を混ぜない。**
タイトルの形と更新版の扱いは `naming.md` にある。この記事の動詞句は `見放題配信が終了した`。

> 【2026年8月】Disney+で見放題配信が終了した作品76本まとめ

★ **「他のサービスで探す」の節は横断ではない。** 軸を1社に保ったまま行き先を出しているだけで、
この記事ではその節が中心。「サービスを混ぜない」を理由に削らないこと。

## 版（初回と更新版）

> **前の版の本文が付いている回は、作品ごとの解説を引き継ぐ。**
> 更新のたびに書き直すと、調べて書いた説明が別の文章に入れ替わって内容が痩せる。
> 決まりは `naming.md`「前の版の本文は引き継ぐ」（全記事タイプ共通）。

**同じ月・同じサービスの記事は1本しか作らない。2回目からは書き直す。**
素材にどちらの版かが明示される。

| | 初回 | 更新版 |
| --- | --- | --- |
| タイトル | `naming.md` の初回の形 | `naming.md` の更新版の形 |
| リードの1文目 | `ended-lead-first-sentence` | `ended-update-lead-first-sentence` |
| 記事の中心 | その月に終了した作品の全体 | **今回新たに終了が確認された作品** |
| 前回までの分 | — | 落とさない。同じ表に一緒に並べる |

更新版では、リードの直後に今回確認された分（素材に ★ が付いた作品）を置く。
**前の版の本数は書かない。** 初回に「更新」と書かない（前の版が無いので嘘になる）。

## この記事が存在する理由

**API が「配信終了予定」を返さないサービスがあるため。**

Netflix と Amazon Prime Video は終了予定日が取れるので、`leaving.md`（配信終了予定）の
記事で**終了前に**知らせられる。しかし Disney+ ではそれが取れず、
終了したという事実が後から分かるだけになる。

黙って落とすと、そのサービスの終了情報が読者に一切届かない。
だから**終了後でも届ける**。ただし価値の出し方は配信終了予定の記事とまったく違う。

## 記事の目的

**読者が「観そびれた作品を、他のサービスで探せる」ようにする。**

この記事を読む人は、すでに観る機会を逃している。
急かしても、おすすめしても、その人は作品を観られない。
**唯一渡せる価値は「まだどこかで観られるかもしれない」という次の一手**である。

**読者が知りたいのは2つだけ。**

1. 何が終了したのか（自分が観そびれたものが含まれるか）
2. それを今から観る方法はあるのか

## 絶対に守ること（この記事タイプの生命線）

**もう観られない作品を「観られる」と読ませたら、この記事は読者を裏切る。**

次の表現は**一切使ってはいけない**。品質チェックで公開が止まる。

| 禁止 | 理由 |
| --- | --- |
| お見逃しなく／見逃せません | もう見逃した後である |
| 今のうちに／まだ間に合います | 間に合っていない |
| 観ておきましょう／チェックしておきましょう | 観る手段が無い |
| 配信中です／視聴できます | 終了した事実と矛盾する |

**U-NEXT・Hulu・DMM TV について「配信中」と書かない。**
当サイトはこれらの配信状況データを持っていない。書けるのは検索リンクまで。

> 悪い例: 「U-NEXTで配信中なので今すぐ観られます」
> 良い例: 「U-NEXTなどでの取り扱いは、以下のリンクから確認できます」

**終了日はデータにあるものだけを書く。** 推測して補わない。

## 構成

### 1. リード（2段落）

1段落目は `fixed-phrases.md` の `ended-lead-first-sentence` をそのまま置く。

2段落目では、終了した作品のうち**知名度の高いものを終了日順に**、
作品名・シリーズ名を「」で囲んで挙げる。
段落の最後は `ended-lead-closer` をそのまま置いて締める。

**記事の作り方の解説は書かない。** 読者の関心は作品であって、記事の構造ではない。

### 2. 終了日順のまとまり

同じ日に終了した作品にまとまりがあれば、それを軸にする。
同一シリーズ・同一監督・同一ジャンルの集中は、読者にとって意味のある単位になる。

#### 節の作り方（この順序を必ず守る）

```
## ○月○日：（まとまりの正体を固有名詞で）

（表：終了日 / 作品 / 評価 / サービス の4列で固定）

（解説の段落）
```

**見出しの直後に導入文を挟まない。** いきなり表を置く。
読者はまず一覧を掴みたい。文章はその後でいい。

#### 見出しには具体的な作品名を入れる

> 悪い例: `## 8月14日：アニメ作品が終了`
> 良い例: `## 8月14日：「カンフー・パンダ」3部作が終了`

#### 解説では評価スコアに触れない

評価は表にだけ載せる。地の文に書いても読者の判断材料にならない。

#### 各まとまりの最終段落は「探す」で締める

配信終了予定の記事は「観ましょう」で締めるが、**この記事はそれができない。**
代わりに次の一手を示して締める。

> 「配信終了後も、他のサービスでの取り扱いを確認できます。」
> 「シリーズをまとめて観たい場合は、以下の検索リンクから探してみましょう。」

### 3. 全終了作品リスト

その月に終了した作品を**漏れなく全件**、表で並べる。
列は「終了日 / 作品 / 評価 / サービス」。

読者は自分が観そびれた作品を探しに来る。抜けがあると用を成さない。

### 4. 他のサービスで探す

冒頭に `fixed-phrases.md` の `other-services-intro` をそのまま置く。
そのうえで、主要な作品について検索リンクを並べる。

**この節がこの記事の中心である。** 配信終了予定の記事では補足だが、
こちらでは読者に渡せる唯一の実用情報になる。省略も短縮もしない。

### 5. まとめ（100〜200字）

その月に終了した作品を振り返り、他サービスで探す導線をもう一度示して閉じる。
**次の月も終了情報を追う旨を書いてよい**が、煽らない。

記事の末尾に `fixed-phrases.md` の `attribution` をそのまま置く。

## 文体

- 常体ではなく敬体（です・ます）
- 1作品あたり1〜2文。踏み込んだ作品解説はここでは書かない
- 記号は全角に統一する（！ ？ （ ） を半角で書かない）
  ただし作品名に含まれる半角記号は正式表記なのでそのまま使う
- **終了は過去形で書く。** 「終了します」ではなく「終了しました」
- 煽らない。読者はすでに機会を逃しており、急かす理由が無い
