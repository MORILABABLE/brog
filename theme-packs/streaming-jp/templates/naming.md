# 記事の軸とタイトル

**全記事タイプに共通の決まり。** 構成と文体は記事タイプごとのテンプレートにある。

- 見放題配信開始（サービス別）→ `arrivals-service.md`
- 見放題配信開始（ジャンル別）→ `arrivals.md`
- 見放題終了予定 → `leaving.md`
- 見放題終了済み → `ended.md`
- 特報（そのつど出す）→ `special.md`
- **シリーズ（保存版・月を名乗らない）→ `series.md`**

決めた理由と実測は [docs/ARTICLE-RULES.md](../../../docs/ARTICLE-RULES.md)。

## 記事は軸を1本だけ名乗る

**軸 ＝ その記事が誰のために何を切り取ったか。** 記事は必ず1つだけ名乗る。

| 軸 | 読者 | 記事に入れてよいサービス |
| --- | --- | --- |
| **サービス軸** | 「Netflixで何が終わる？」と探している人 | **1社だけ** |
| **ジャンル軸** | 「アニメがどこで観られる？」と探している人 | **横断してよい** |
| **主題軸**（特報） | 「あの作品がどこで観られる？」と探している人 | **横断してよい** |

読者はサービスごとの最新情報を求めて来る。**複数サービスを1本にまとめた記事は作らない。**
横断してよいのは「どこで観られるか」を知りたい読者に向けた記事、
つまり**ジャンル軸と主題軸だけ**。

### 記事タイプごとの軸

| 記事タイプ | 軸 |
| --- | --- |
| 見放題配信開始（サービス別） | サービス |
| 見放題配信開始（ジャンル別） | ジャンル |
| **見放題終了予定** | **サービス（これだけ）** |
| **見放題終了済み** | **サービス（これだけ）** |
| 特報（`special`） | 主題 |
| **シリーズ（`series`）** | **主題** |

★ **配信終了の記事はサービス別だけ。ジャンル別の終了記事は作らない。**
読者は「Netflixで何が終わるのか」を探しに来る。ジャンルで束ねると、
どのサービスの話なのかが読者側で分解できなくなる。

### U-NEXT

**ジャンル軸の記事以外で、U-NEXT を他社と混ぜない。**

U-NEXT の作品には作品ポスターが付かない（自前収集のため。`site/src/lib/work-links.ts`）。
表の行はジャンル別の汎用画像になる。**それでよい。**

> ★ 画像を揃えるために配信API側のポスターをU-NEXTの行に流用してはいけない。
> ポスターの再ホスト許諾は配信APIのカタログに対するもので、U-NEXT はその範囲外。
> 見た目の問題を、許諾の問題にすり替えることになる。

### 「他のサービスで探す」節は横断ではない

記事末尾の検索リンクは、軸を1社に保ったまま行き先を出しているだけ。
**この節を「横断だから」と削らないこと。** 終了済み記事ではこの節が記事の中心。

## タイトル

### 形

**先頭は初回も更新版も同じ。** 更新の日付は**本数の直後**に置く。

    【{年}年{月}月】{軸句}{動詞句}{本数}本{更新}｜{見どころ}

| 部品 | 中身 |
| --- | --- |
| `{軸句}` | サービス軸なら `Netflixで`。ジャンル軸なら**書かない**（ジャンルは本数の前に付く） |
| `{動詞句}` | 記事タイプごとに固定（下の表） |
| `{本数}本` | ジャンル軸では `見放題配信が始まった洋画・海外ドラマ58本` のようにジャンル名＋本数 |
| `{更新}` | 初回は**空**。更新版は `【{月}月{日}日更新】` |

> 初回（サービス軸）　【2026年9月】Netflixで見放題配信が終了予定の作品36本｜007シリーズ5作と五等分の花嫁
> 更新版（サービス軸）【2026年9月】Netflixで見放題配信が終了予定の作品42本【9月12日更新】｜踊る大捜査線が終了
> 初回（ジャンル軸）　【2026年8月】見放題配信が始まった洋画・海外ドラマ58本｜ボーン・アイデンティティーとSISU

**期間と軸が先頭に来ること。** 読者は検索結果の一覧で、
「いつの」「どこの」情報かだけを見て開くかどうかを決める。

> ★ **更新版でも先頭を 【9月12日更新】 にしない。**
> 先頭が更新日だと、**どのカテゴリ・どの月の記事なのかが頭から消える。**
> 更新したことは大事だが、それは記事を開くかどうかを決めたあとの情報。
> 更新日は本数の直後・`｜` より前に置く。

### 配信開始「予定」だけ先頭が違う

**【】の中で動詞まで名乗る。** 本文側の動詞句は書かない（同じことを2回書かない）。

    【{年}年{月}月配信開始】{サービス}の見放題{ジャンル}{本数}本｜{見どころ}

> 【2026年9月配信開始】Amazon Prime Videoの見放題アニメ10本｜ゆるキャン△3期
> 【2026年9月】Netflixで見放題配信が終了予定の作品36本｜007シリーズ5作と五等分の花嫁

同じ月に「開始」と「終了」の記事が並ぶ。読者が検索結果で見るのは**先頭の数文字**なので、
そこで開始と終了を取り違えさせない。

★ **「見放題」を落とさないこと。** 動詞句の検査を外したぶん、
  購入・レンタルと区別する言葉がここにしか残らない（品質ゲートが見ている）。

### シリーズ記事だけ期間を名乗らない

**【保存版】で始める。年月を1文字も書かない。**

    【保存版】{主題}の{動詞句}作品{本数}本{更新}｜{見どころ}

> 【保存版】「名探偵コナン」劇場版シリーズの見放題配信が終了予定の作品61本｜ベイカー街の亡霊と純黒の悪夢
> 【保存版】「007」シリーズの見放題配信が終了予定の作品5本【9月12日更新】｜スカイフォールも終了

**この記事タイプだけ、URLにもタイトルにも月が入らない。**
他の記事が「その月に何が起きたか」を書くのに対して、シリーズ記事は
「いま全作がどうなっているか」を書き、**配信状況が変わるたびに同じURLを書き直す**。
月を名乗ると、書き直しても翌月には古い記事に見える（docs/KEYWORDS.md 案1）。

★ **本数は「作品の数」。同じ作品が複数のサービスにあっても1と数える。**
  シリーズ記事は横断してよいので、同じ映画が2社に入ることがある。
  素材はサービスごとに1件ずつ持っているが、**表では1行にまとめる**決まりなので、
  素材の件数を名乗ると**読者が表で数えられる行数と合わない。**

      素材 6件（実写5作＋『最後の騎士王』が2社ぶん）／表 5行
      ○ 作品5本   ✕ 作品6本

  **ズレを本文で説明しない。**「件数が6本になっているのは〜」という断り書きは、
  運営の都合であって読者の用ではない。**統合した数を名乗り、ズレを作らない**
  （2026-08-31 の添削）。数は記事タイプ側が自動で出す（`series.ts` の `workCount()`）。

★ **日付を1つも書かない。品質ゲートが止める。**
  先頭の【2026年9月】だけでなく、**見どころ（`｜` のあと）の「8月31日まで」も書かない。**
  終了日は書き直すたびに入れ替わるので、日付をタイトルに入れると
  **次に書き直すまでのあいだ、タイトルだけが嘘になる。**
  終了日は本文の表に出す。見どころには固有名詞を置く。
  例外は 【9月12日更新】 の更新日だけ（版の印なので）。

★ 動詞句は素材から決まる（下の表）。人が選ぶフラグは無い。

### 動詞句は記事タイプごとに固定する

| 記事タイプ | 動詞句 |
| --- | --- |
| 見放題配信開始（サービス別・ジャンル別） | `見放題配信が始まった` |
| 見放題終了予定（サービス別） | `見放題配信が終了予定の` |
| 見放題終了済み（サービス別） | `見放題配信が終了した` |
| **シリーズ（保存版）** | **下の3つ。素材から決まる** |

シリーズ記事の動詞句は、素材の状態を上から順に見て決まる（`article-types/series.ts` の `stanceOf()`）。

| 素材の状態 | 動詞句 | 記事のカテゴリ |
| --- | --- | --- |
| 終了予定が1本でもある | `見放題配信が終了予定の` | 配信終了予定 |
| 終了予定は無いが、**見放題に復帰した作品**がある | `見放題配信が再開した` | **新着配信** |
| どちらも無い（全部終わっている） | `見放題配信が終了した` | 配信終了済み |

★ **3つを行き来する。** 終了した作品が別のサービスで見放題に戻ることが実際にある
  （1か月の観測で4件。docs/KEYWORDS.md 3-1）。戻ったら「再開した」に変わり、
  次の終了日が付けばまた「終了予定の」に戻る。**人が選ぶフラグは無い。**

「見放題配信開始の」「見放題終了する」「配信終了する」と言い換えない。
**「配信」ではなく「見放題配信」**（購入・レンタルと区別するため）。

### 軸の書き方

| 軸 | 書き方 | 使える値 |
| --- | --- | --- |
| サービス | 正式表記そのまま | `Netflix` `Amazon Prime Video` `U-NEXT` `Disney+` `Apple TV+` |
| ジャンル | ジャンルの呼び方そのまま | `アニメ` `洋画・海外ドラマ` `邦画・国内ドラマ` |

**略称を使わない**（アマプラ／プライムビデオ／ネトフリ／ディズニープラス／ユーネクスト）。
本文のサービス名表記とも揃える。

### 作ってはいけないタイトル

| ✕ | なぜ |
| --- | --- |
| `見放題配信が始まった作品まとめ` | 軸が無い。いつの・どこの話か分からない |
| `【2026年9月】見放題配信が終了する作品まとめ` | 期間はあるが軸が無い |
| `【2026年8月】Netflix・Prime Videoで配信終了する作品32本まとめ` | 軸が2つ（サービス横断） |
| `【2026年8月】U-NEXTとNetflixのアニメ…` | ジャンル記事にサービス名を出している |
| `8月に見放題配信が始まったアニメ34本` | 【】の期間表記が無い・年が無い |
| `【8月26日更新】見放題配信が始まった邦画・国内ドラマ60本` | 更新日を先頭に置いている。対象月も消えている |
| `【2026年8月】見放題配信が始まった邦画60本｜告白と来る【8月26日更新】` | 更新日が `｜` より後ろ |

### 見どころ（`｜` のあと）

その記事でいちばん名前の通った作品・シリーズを**固有名詞で**2つまで。

- **タイトル全体で60字以内。** 更新版は【】が長くなるぶん、`｜` 以降を10〜15字に抑える
- 評価スコア・順位（「評価上位5本」）を書かない
- 「衝撃」「必見」「神作」などの煽りを書かない
- **挙げるだけの価値がある固有名詞が無い月は、`｜` ごと省いてよい**
  （`【2026年8月】Disney+で見放題配信が終了した作品76本まとめ` の形）。
  無理に埋めて知名度の低い作品を先頭に出すより、省いたほうがよい

#### ★ 更新版の見どころに「追加は」と書かない（終了記事）

更新版で増えたのは**「終わる作品」であって、観られる作品ではない。**
それを「追加は◯◯」と書くと、**◯◯が見放題に入ったという逆の意味に読める。**
検索結果には動詞句（`終了予定の`）と見どころしか並ばないので、
読者はこの2つだけで開くかどうかを決める。

| 記事タイプ | ✕ | ○ |
| --- | --- | --- |
| 見放題終了予定・終了済み | `｜追加はハリー・ポッター7作` | **`｜ハリー・ポッター7作が終了`** |
| 見放題配信開始 | — | `｜追加は踊る大捜査線`（こちらは「増えた＝観られる」で一致する） |

「追加は」が使えるのは**配信開始の記事だけ**。終了記事では、
新しく判明したぶんを名乗りたいなら **`◯◯が終了`／`◯◯も終了`** の形にする。

## 同じ月に2本目を作らない（更新版）

**同じ月・同じ軸の記事はすでにある。それを書き直す。**

記事を1本ずつ増やすと同じ検索語を自分同士で奪い合う。**記事が増えるのではなく、記事が育つ。**
スラッグが同じなら同じファイルを上書きするので、URLも被リンクもそのまま残る。

| | 初回 | 更新版 |
| --- | --- | --- |
| タイトル | `【{年}年{月}月】…{本数}本｜…` | `…{本数}本【{月}月{日}日更新】｜…`（**先頭は同じ**） |
| リードの1文目 | 初回用の固定文言 | **更新版用の固定文言** |
| 記事の中心 | その月の全体 | **前回の版以降に増えた/判明した分** |
| 前回までの分 | — | 落とさない。同じ表に一緒に並べる |

> ★ **初回に「更新」と書かない。** 読者にとって「更新」は「前に読んだものが変わった」という意味で、
> 初回に付けると嘘になる。素材が初回だと言っているのに更新版の形で書いたら検査で止まる。

素材には**どちらの版か**と、**どれが今回の分か**が明示される。
**自分で日付を突き合わせて判断しないこと。** 配信開始日・終了日と、
当サイトがそれを把握した日はずれる。取りこぼしを後から拾うと古い作品が今回の素材に現れるので、
それを「新たに始まった」と書けば誤情報になる。
記事タイプごとの言い分けは各テンプレートにある。

### 前の版の本文は引き継ぐ（2026-09-02 追加）

**同じスラッグの記事がすでにあるとき**、プロンプトの冒頭に
**「★ この記事には前の版があります」** の節が付き、
**いま公開されている本文がまるごと入っている**。全記事タイプ共通で、

> **あらすじも、一度調べた作品の特徴も、書き直す必要はない。**
> **いまの状態で読んでも違和感が出ないところだけを直して、記事を遷移させる。**

**作品ごとの解説はそのまま引き継ぐ。** その段落は `npm run research` で調べた事実で
書いてあり、同じ材料からもう一度書いても良くはならない。
**別の文章になって、内容が静かに痩せるだけ。**
「言い回しを整える」ためだけに手を入れないこと。

手を入れるのは2つだけ。

1. **事実が変わったせいで嘘になっている箇所**（動詞句・固定文言・状態の列・日付）
2. **今回はじめて素材に入った作品**（素材の ★ 印）。ここだけ新しく書き足す

★ **構成までは前の版に固定しない。** 月次記事の更新版は
  「今回新たに判明した分」の節が増えるなど、**版によって構成そのものが変わる。**
  この決まりが言っているのは「**文章を引き継ぐ**」ことで、形を固定することではない。
  どういう形にするかは各テンプレートの「版（初回と更新版）」／
  `series.md` の「書き直し（状態が変わったとき）」にある。

★ **この節が無い回は初回。** 前の版が無いので、引き継ぐものも無い。
  **渡されていないものを残そうとしないこと。**
