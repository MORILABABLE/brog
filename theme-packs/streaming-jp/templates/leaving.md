# 記事テンプレート: 配信終了

このファイルを編集すれば、全ての配信終了記事の構成が変わる。
コードを触る必要はない。

- 毎月そのまま使う文言 → `fixed-phrases.md`
- **軸とタイトルの決まり → `naming.md`**（全記事タイプ共通）
- 実際に書けている記事の例 → `examples/leaving-excerpt.md`

## 軸とタイトル

**この記事の軸は「サービス1社」。他社を混ぜない。**
タイトルの形と更新版の扱いは `naming.md` にある。この記事の動詞句は `見放題配信が終了予定の`。

> 【2026年9月】Netflixで見放題配信が終了予定の作品36本｜007シリーズ5作と五等分の花嫁

## 記事の目的

読者が「観ようと思っていた作品を見逃さない」ようにする。
新作紹介はどこでも読めるが、いつ観られなくなるかを追っている媒体は少ない。そこが価値。

**読者が知りたいのは2つだけ。**

1. 今月どの作品が見放題終了するのか
2. その作品・シリーズはどういうものなのか

**記事の作り方の解説を書かない。** 読者の関心は作品であって、記事の構造ではない。

> 悪い例: 「今月は終了日が特定の日に固まっているのが特徴です」
> 　　　　「単に評価の高い順に観るより、この『かたまり』を意識した方が満足度は高くなるはずです」
> どちらも記事の編集方針の話。作品の話に置き換える。

作品紹介は**簡潔に分かりやすく**。1作品あたり1〜2文で足りる。
踏み込んだ作品解説は別ページで扱うので、ここで長く書かない。

## 版（初回と更新版）

> **前の版の本文が付いている回は、作品ごとの解説を引き継ぐ。**
> 更新のたびに書き直すと、調べて書いた説明が別の文章に入れ替わって内容が痩せる。
> 決まりは `naming.md`「前の版の本文は引き継ぐ」（全記事タイプ共通）。

**同じ月・同じサービスの記事は1本しか作らない。2回目からは書き直す。**
終了予定は月の途中で新しく判明する。記事を増やすと同じ検索語を自分同士で奪い合うので、
**記事が増えるのではなく、記事が育つ**形にしてある。素材にどちらの版かが明示される。

| | 初回 | 更新版 |
| --- | --- | --- |
| いつ | その月・そのサービスで初めて書くとき | 2回目以降 |
| タイトル | `naming.md` の初回の形 | `naming.md` の更新版の形 |
| リードの1文目 | `leaving-lead-first-sentence` | `leaving-update-lead-first-sentence` |
| 記事の中心 | その月に終了する作品の全体 | **今回新たに判明した終了予定** |
| 前回までの分 | — | 落とさない。同じ表に一緒に並べる |

更新版では、**リードの直後に「今回新たに判明した終了予定」の節を置く。**
対象は素材に `★今回新たに判明した終了予定` と付いた作品だけ。

- **前の版の本数を書かない。** 読者が前の版を見ているとは限らない
- 素材に ★ が付いた作品が無ければ、この節は作らない

#### ★ 全件を1枚の表にしない。`###` のまとまりに割る

この節に**平の大きな表を1枚置いてはいけない。**
そのあと構成2で同じ作品をもう一度まとめて出すことになり、
**読者は同じ行を2回も3回もたどる羽目になる**（2026-09-01 の添削）。

`##` の直下は**まとめの2〜3文だけ**にして、そのあとを `###` の小段落に割る。
今回の分の解説は**すべてこの節の中で終わらせる。**

```
## 今回新たに判明した終了予定27本

（何が増えたのかを2〜3文。表は置かない）

### 「ハリー・ポッター」7作と「ファンタスティック・ビースト」3作

| 終了日 | 作品 | 出演者 | サービス |
| --- | --- | --- | --- |
| …… | …… | …… | …… |

（解説）

### 「ジュラシック・パーク」シリーズ5作

（同じく 見出し → 表 → 解説）

### そのほかに判明した◯本

（まとまりを作れなかった残りを1つの表にまとめ、1作1〜2文で）
```

- **小段落の作り方は構成2と同じ**（見出し → 表 → 解説の順、まとまりの固有名詞で始める見出し）
- **同じ作品を2つの表に出さない。** ここで出した作品は、構成2でもう一度表にしない。
  構成2が扱うのは**前の版から載っていた作品**だけになる
- **`###` の見出しを `◯月◯日：` で始めない**（2026-09-10 に変更）。
  節はシリーズ・主題で割るので、日付は表の列が持つ（構成2「時系列で節を割らない」）
- まとまりに入らなかった作品は捨てず、最後の `###` にまとめて全部載せる

> ★ **画像は日付が無くても入る。** `site/scripts/make-sections.mjs` は
> 日付見出しが1つも無い記事では**見出しの形を問わずに節を拾い直す**（`anyHeading`）。
> 「全終了作品リスト」「他のサービスで探す」「まとめ」は名前で外してあるので、
> 一覧の節に絵が二重に入ることもない（同ファイルの `NO_IMAGE_HEADING`）。

> ★ **初回に「更新」と書かない。** 読者にとって「更新」は
> 「前に読んだものが変わった」という意味で、初回に付けると嘘になる。検査が error で止める。

★ **同じ日に2回 `--apply` すると「今回判明した分」が0件になる。**
  ★ は**公開済みの記事本文との差**で決まる。1回目を適用した時点で基準が今日の版に移るので、
  書き直しのために2回目を回すと「今回新たに判明した終了予定が0件」になり、
  リードの固定文言まで0本に変わる。

      git checkout HEAD -- site/src/content/posts/<スラッグ>.md   # 読者が見ていた版に戻す
      npm run write -- --type leaving --service <サービス> --emit  # ここで件数が戻る
      npm run write -- --apply

  **直すのは記事であって、基準ではない。** 0件のまま書くと、
  27本増えたことが読者に伝わらない記事になる（2026-09-01 の添削）。

## 構成

### 1. リード（2段落）

**1文目は `fixed-phrases.md` の `leaving-lead-first-sentence` をそのまま使う。**
月・サービス名・基準日・本数だけを差し替える。文型は変えない。

2段落目は、今月の目玉を**具体的な作品名で**示す。

**ねらいは、読者を本文の最後まで連れていくこと。**
ここで具体的な作品名を見せられないと、読者は表だけ眺めて離脱する。

- 知名度のあるシリーズ・作品を、**終了日の早い順**に挙げる
- 「有名作・話題作が見放題終了する」ことが伝わるように書く
- 作品名・シリーズ名は「」で囲む
- 抽象的な傾向の説明にしない（前述の「悪い例」）

> 例: 今月は8月14日に「カンフー・パンダ」シリーズ、8月15日以降に「タイタニック」や
> 「THE 有頂天ホテル」「オーメン」シリーズと、往年の話題作や名作の多くが見放題終了します。

**目立つシリーズが無い月**は、次の優先順で挙げる作品を選ぶ。

1. 有名作・人気作（広く知られている作品）
2. 近年に続編・新作が公開された作品（今も関心が続いている）
3. それでも決まらなければ評価の高い順

**段落の最後に `leaving-lead-closer` をそのまま置く。** 言い換えない。

### 2. シリーズ・主題ごとのまとまり（最重要・独自性の核）

**終了する作品を眺めて、意味のあるまとまりを見つけること。**
これがこの記事の価値そのもの。**節はシリーズ・主題で割る。終了日で割らない**
（2026-09-10 に変更。下の理由）。

#### まとまりの見つけ方（この優先順で探す）

1. **シリーズ起点** — 同一シリーズの複数作が終了する
2. **制作会社起点** — 同じ制作会社の作品が複数終了する（素材に「制作」として与えられる）
3. **ジャンル・国起点** — 同じ国・同じジャンルの作品が集中している
4. 上のどれでもなければ、終了日でまとめる

**1〜3は日付をまたいでよい。** これがこの節でいちばん大事な決まり。
まとまりが見つからない月は無理に作らない。その場合は終了日でまとめてよい。

★ **なぜ終了するのかを書かない。** 「まとめてライセンスされたものが同時に期限を
  迎えた」は素材のどこにも無い推測（`writing.md` 2節）。**まとまりは節の割り方の
  根拠であって、記事に書く内容ではない。**「同じ制作会社の作品です」までは事実。

#### ★ 時系列で節を割らない（2026-09-10・運用者の指摘）

**同じシリーズが日付をまたいでいても、1つの節にまとめる。**

- **読者は日付で探していない。** 探しているのは作品とシリーズで、
  「9月20日に何が終わるか」を知りたい人はいない
- **同じ解説が複数の節に割れる。** シリーズの説明を節ごとに繰り返すか、
  どこか1つに寄せて他を痩せさせるかの二択になり、どちらも読みにくい
- **まとまりが見えなくなる。** 「同じシリーズが何作も終わる」という、
  この記事でいちばん大きい事実が、割れた時点で読者に伝わらない

**日付は表の「終了日」列が持つ。** 節がまたいでいれば、行ごとに実際の終了日を書く。
**日付は行の属性であって、節の見出しではない。**

★ 同じ決まりが `arrivals.md`（配信開始）と `ended.md`（終了済み）にもある。

#### 節の作り方（この順序を必ず守る）

```
## 「◯◯」シリーズ◯作が終了予定

| 終了日 | 作品 | 出演者 | サービス |
| --- | --- | --- | --- |
| …… | …… | …… | …… |

（ここから作品の解説。最後は視聴を促す形で締める）
```

**必ず「見出し → 表 → 解説」の順にする。**
見出しの直後は表で、導入文（「◯作品が終了します」）を挟まない。
読者はまず何がいつ終わるのかを一覧で把握し、そのうえで解説を読む。

- 表の列は **終了日・作品・出演者・サービス** の4列で固定する
- 日付をまたぐまとまりでは、行ごとに実際の終了日を書く

#### ★ 解説を厚く書く節は2つまで。残りは表と短いまとめ（2026-09-10・運用者の指定）

**本数が多く、名前の通ったまとまりを2つ選んで、その2つだけを解説する。**
残りは**1つの節にまとめて、表と数文のまとめ**で終える。

```
## （厚い節1）「◯◯」シリーズ◯作が終了     ← 表 ＋ 解説2〜3段落
## （厚い節2）◯◯制作の◯作が終了           ← 表 ＋ 解説2〜3段落
## そのほかに終了した◯本                    ← 表 ＋ まとめ3〜5文
```

- 厚い節を選ぶ基準は **①本数が多い ②名前が通っている** の2つ
- まとまりの作り方は上と同じ（**シリーズ・制作会社・監督**などの繋がり）
- **3つ目を厚く書かない。** どうしても外せない作品は「そのほか」の節で1〜2文触れる
- 「そのほか」の節も**表には全件載せる**。落とすのは解説であって作品ではない

■ なぜ2つで止めるのか

**節ごとに同じ密度で解説を続けると、読者が最後まで持たない。**

> サービス全体の終了記事のはずが、タイトルではコナンに触れるのみ。
> コナンに触れる段落で終了のはずが他作品も解説するので、
> 読者は疲れを感じる構成になってしまっている。

6つの節すべてに表と解説を並べた版で出た指摘（2026-09-10）。
**読者が読むのは、自分が探していたまとまりの1つか2つだけ。**
残りは「自分の観そびれたものが入っているか」を表で確かめられればよく、
そこに同じ厚さの文章を置いても読まれないまま記事が長くなる。

★ **表を薄くするのではない。** 全作品が表に載っている状態は変えない
  （抜けがあるとこの記事は用を成さない）。**変えるのは解説の配分だけ。**

#### 見出しは「何が」で始める。「いつ」で始めない

> 悪い: `## 8月14日：ふたつのまとまりが重なる日`（何が終わるのか分からない）
> 悪い: `## 9月20日：アニメ5作が終了`（日付が主語で、何かも分からない）
> 良い: `## 「カンフー・パンダ」シリーズ3作が終了予定`
> 良い: `## 京都アニメーション制作の6作が9月末で終了予定`

★ **見出しにもタイトルにも `どこで見れる？` を置かない**（2026-09-10）。
  行き先は**表の在庫の行がもう答えている**（下の 2-5）。
  問いを並べると、目次として読んだときにどの節も同じ顔になる
  （`naming.md`「終わった記事は問いから入る」）。

### 2-5. ★ 「終了後どこで観られるか」は表が答える。文章で書かない（2026-09-10 追加）

在庫台帳（`data/availability.json`）に載っている作品では、
**サイトが表の各行の下に1行足す**
（`site/plugins/rehype-availability.ts`）。記事側は何も書かなくてよい。

    | 終了日  | 作品                      | 出演者 | サービス |
    | 9月30日 | ハリー・ポッターと賢者の石 | —      | Netflix  |
    | [配信中]  ● Amazon Prime Video   × Disney+   △ Apple TV+  |  ← サイトが足す行

- **頭のラベルは枠付きで、文字も色もサイトが決める**
  （○があれば「配信中」＝青／△だけなら「有料で配信中」＝黄／×だけなら「取り扱いなし」＝赤）。
  **文字にも色にも触れない。** 本文で言い換えるのも禁止
- **その行のサービス（上の例なら Netflix）はサイト側が外す。**
  「終わる行に、そこで観られると出す」ことにならないようにするため
- **行も列も自分で書き足さない。** 表は4列のまま書く
- **在庫を段落で説明しない。** 同じ事実が表と文章の2か所になり、
  書き直すたびに片方だけ古くなる（実測でスクロール90%到達は22%。docs/FUNNEL.md 5-3）
- まとめでは**表を指すだけ**にする（「上の表のとおりです」）

★ 在庫は `npm run availability` が取る。**`--emit` のあとに実行して、もう一度 `--emit`**。
  取れなかった作品は行が出ないだけで、**「どこにも無い」と書いてはいけない。**

#### 解説では評価スコアに触れない

**評価は表にだけ載せる。地の文には書かない。**
読者が探しているのは「終わる前に観ておきたい作品」であって、その日の最高得点ではない。

> 悪い: 「この日の最高評価は『タイタニック』で80です」
> 悪い: 「今月配信終了する中では最も評価が高い作品です」

「なぜ今まとめて観る価値があるのか」と、どれから観るべきかの助言を書く。

#### 各まとまりの最終段落は、視聴を促す形で締める

このパートの段落は**原則として行動を促す形で終える**。
体言止め・尻すぼみで終わらせない。

| 書かない | こう書く |
| --- | --- |
| 8月14日が期限になります。 | 夏休みの残りでまとめて観ておきましょう。 |
| 配信で気軽に観られる機会は多くありません。 | 気軽に観られる機会は多くないため、チェックしておきましょう。 |
| 興味があればこの機会に。 | この機会にぜひ観ましょう。 |
| 〜が終了します。 | 〜が終了します。こちらも名作揃いのため見逃せません。 |

**例外**: 段落そのものが「どれから観るべきか」の助言になっている場合は、
促し文句で締めなくてよい（`examples/leaving-excerpt.md` の抜粋2がこの形）。
品質チェックはこの場合も警告を出すが、内容が助言になっていれば無視してよい。

### 3. その他の注目作

まとまりに入らなかった作品のうち、評価が高いものや知名度のあるものを
終了日順にグループ化して紹介する。1作品1〜2文。

ここは事実の列挙でよく、構成2のような締めの一文は要らない。

### 4. 全終了作品リスト

終了日・作品名・評価・サービスの4列の表。漏れなく全件。

★ **全件の表はここ1か所だけ。記事の後ろに置く。**
  更新版でも同じで、**先に個別のまとまり、最後に全件**の順を崩さない。
  全件の表を前に出すと、読者は目当ての作品を探すのに長い表を読まされ、
  そのあと同じ行を解説側でもう一度たどることになる。
  この順序が崩れるのは決まって更新版なので、書き直すときほど確かめる
  （2026-09-01 の添削）。

### 5. 他のサービスで探す

冒頭に `fixed-phrases.md` の `other-services-intro` をそのまま置き、検索リンクを並べる。
「配信中」とは絶対に書かない。

### 6. まとめ（100〜200字）

今月の山場を1〜2点に絞って再提示する。
読者がここだけ読んでも今月の要点が分かる状態にする。
**評価上位◯本のような順位付けは書かない**（評価は表で見られる）。

「山場」「見どころ」のような比喩は使わず、**「見放題終了予定です」と言い切る**。
最後は「お見逃しがないように」など、リードと同じく視聴を促す形で締める。

## 文体

- です・ます調
- **記号は全角に統一する。** `！` `？` `（）` を半角で書かない
- 誇張しない。「衝撃」「必見」「神作」等の煽り文句は使わない
- **評価スコアは記事に出さない**（表からも外した。下の「評価の列は置かない」）
- 作品への主観的な評価は書いてよいが、断定は避ける
- 価値のある作品には「名作」「往年の話題作」といった語を素直に添えてよい
- 「配信終了」ではなく **「見放題終了」** を基本語にする（購入・レンタルは残るため）

## 絶対に守ること

- **邦題が確認できていない作品は原題のまま書く。** 推測で日本語タイトルを作らない
- 与えられた終了日以外の日付を書かない
- 与えられていない作品を追加しない
- `fixed-phrases.md` の文言は一字一句そのまま使う
- 記事の末尾に配信情報の提供元表記を必ず入れる

#### ★ 「評価」の列は置かない（2026-09-08 変更）

**評価スコアは記事のどこにも出さない。** 表にも地の文にも書かない。
読者が表で知りたいのは「いつ」「どこで」「誰が出ているか」で、
**100点満点の数字はその判断に使われていない。**
その1列を、読者が実際に探している**出演者**に置き換えた（2026-09-08・運用者の指定）。

★ **素材からは無くなっていない。** 評価は引き続き素材に入っていて、
  **表の行を並べる順番を決める目安**として使う。記事に出さないだけ。

#### ★ 「出演者」の列は主演＋助演の2名まで（2026-09-08 追加）

**網羅しない。** 素材の `出演` の行から、主演と助演を1名ずつ選ぶ。

| | 書き方 |
| --- | --- |
| 実写 | `佐藤健、蒼井優` のように**2名まで** |

  代表として2名を挙げるだけにして「主演」と書かない。
★ 表の下に「出演者」の箇条書きを置くのは**主題が1つの記事（`series` / `special`）だけ**。
  月次記事は作品がばらばらなので、主演をまとめて名乗れない（`writing.md` 6節）。
