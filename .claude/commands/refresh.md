description: 事実と食い違った公開済み記事（見放題終了予定→終了など）をまとめて書き直す
argument-hint: "[スラッグ] 例: conan-movies。省略すると急ぐ順に全部"
---

**公開済みの記事のうち、いまのデータと食い違っているものを書き直す。**
LLM APIは使わず、このセッションで書く（`/article` と同じ経路・課金なし）。

> **これは書き下ろしではない。**「終了予定だった作品が終了済みになった」ように
> **事実のほうが変わった記事**を、変わった箇所だけ直す作業。
> 何を差し替えて何を残すかは `data/draft/prompt.md` に埋め込まれて渡される。
> このファイルの記述と食い違ったら prompt.md に従う。

引数: `$ARGUMENTS`（対象のスラッグ。省略可）

## 手順

### 0. 最初に pull する

```
git pull
```

収集は GitHub Actions が `origin/main` にコミットする。手元が古いまま判定すると、
**終了日が過ぎたことに気づけない**（`--refresh` は収集済みイベントを見て決める）。

### 1. 何が書き直しどきかを見る

```
npm run write -- --refresh
```

「記事 / 素材件数 / 理由 / 書き直すコマンド」が急ぐ順に出る。

```
  conan-movies          61  見放題終了予定 → 見放題終了 / 期日切れ61件
  ultraman              12  見放題終了予定 → 見放題終了 / 期日切れ9件
```

理由は3つあり、**上ほど急ぐ**。

| 理由 | 意味 |
|---|---|
| `見放題終了予定 → 見放題終了` | 記事が名乗るカテゴリが事実と違う。**タイトルの動詞句・リードの固定文言・バッジがまとめて食い違っている**（読者に嘘を見せている状態） |
| `期日切れ◯件` | 記事を書いたあとに終了日が過ぎた作品がある。表の「状態」の列が事実と違う |
| `未掲載◯件` | その記事の本文に出ていない素材がある（あとから増えたぶん） |

#### 「他社に生きている観測が残っている作品」が出ていたら、必ずユーザーに伝える

一覧の下に、書き直しの表とは**別枠で**こう出ることがある。

```
  他社に生きている観測が残っている作品 2件
  ------------------------------------------------------------------------
  conan-movies        名探偵コナン ベイカー街の亡霊
      Netflixで終了 / Amazon Prime Videoで配信開始を観測したまま
```

**公開中の記事が「終了しました」と書いている作品が、他社では生きている観測のまま**という意味。
シリーズ記事が `ended` に切り替わる判定は**その記事が選んだ素材だけ**を見ていて、
他社での配信開始は素材に入らない。記事が誤りになりうる唯一の形。

- **書き直しても直らない。** `--refresh --emit` の対象ではない
- **「他社で配信中」と書かせない。** 当サイトが持っているのは変化の観測であって在庫ではない
  （Disney+ と Apple TV+ は終了予定を返さず、終了の観測も遅れて出る）
- やることは**ユーザーに伝えて、実際の配信状況を確かめてもらう**こと。
  黙って読み飛ばさない

- **1本も出なければそこで終了。** 「書き直しどきの記事はありません」と伝えて終わる
- 何も出ないのに書き直したい記事がある場合、控えに入っていない可能性がある（下の「控えに無い記事」）
- 引数でスラッグを渡されていれば、その1本だけを扱う

### 2. 1本書き出す

```
npm run write -- --refresh --emit                     いちばん急ぐ1本
npm run write -- --refresh --emit --slug conan-movies 指定した1本
```

**下書きの置き場は1本ぶんしかない。** まとめて書き出すことはできないので、
1本ずつ「書き出す → 書く → 適用する」を回す。残り本数は毎回出力の最後に出る。

### 3. prompt.md を読んで、**変わった箇所だけ**直す

`data/draft/prompt.md` の先頭に **「★ これは書き直しです」** の節があり、
そこに**いま公開されている本文がまるごと入っている**。それを土台にする。

> **あらすじも、一度調べた作品の特徴も、書き直す必要はない。**
> **「見放題が終了した状態」で読んでも違和感が出ないところだけを直して、記事を遷移させる。**

段落ごとに「この文は、いまの状態で読んでもおかしくないか」だけを見る。
おかしくなければ**触らない**。「言い回しを整える」だけの書き換えもしない。

| 差し替える | そのまま残す |
| --- | --- |
| タイトルの動詞句（`見放題配信が終了予定の` → `見放題配信が終了した`） | タイトル先頭の `【保存版】` |
| タイトルの本数と `【{月}月{日}日更新】` | 見どころ（`｜` の後ろ。事実として誤りでなければ） |
| リードの1文目（固定文言が入れ替わる） | リード2段落目のシリーズの説明 |
| 節の見出し（`終了する◯本` → `終了した◯本`） | 節の解説（調べた事実で書いた段落） |
| 表の「状態」の列 | **表の行そのもの**（前の版の作品を落とさない） |
| 行動を促す言い回し | 「他のサービスで探す」「まとめ」 |

★ **解説の段落を書き直さない。** `npm run research` で調べた事実で書いてある。
  同じ材料からもう一度書くと**別の文章になって、内容が静かに痩せる。**

★ **生成のあとで手を入れた一文を消さない。** 他社との相互参照など
  （`docs/EDITING.md`「他社の話を1文だけ足すとき」）。事実として誤りでなければ残す。

★ **全作品が終了済みになった回は、行動を促す言い回しを1つ残らず消す。**
  「お見逃しなく」「今のうちに」「観ておきましょう」「配信中です」。
  品質ゲートが行ごとに見て止める。

書いた内容は `data/draft/response.md` に保存する。形式は `/article` と同じ。

```
TITLE: （30〜60文字）
DESCRIPTION: （60〜120文字・1行）
---BODY---
（Markdown本文。見出しは ## から）
```

### 4. 検証して書き出す

```
npm run write -- --apply
```

品質ゲートで弾かれたら `data/draft/response.md` を直して再実行する。
`--apply` は書き直し前のフラグ（`--topic` / `--slug` / `--match`）を自動で復元する。

### 5. 画像を入れ直す（**書き直したら必ず**）

```
cd site && npm run sections -- --write
```

**`--apply` は frontmatter を組み立て直すので、`heroImage:` が一度消える。**
飛ばすと記事一覧・右の枠・追従枠のタイル画像が空になる。
何度実行しても結果は同じなので、忘れたと思ったら実行してよい。

### 6. 残りを繰り返す

`--refresh --emit` の出力の最後に「このあと書き直しどきの記事があと◯本」と出る。
0本になるまで 2〜5 を繰り返す。

### 7. サイトのビルドを確認（最後に1回）

```
cd site && npm run build
```

カテゴリが `leaving` → `ended` に移った記事は、**一覧の並びとバッジが変わる**。
frontmatter のスキーマ検証もここで走る。

## 控えに無い記事

判定に使うのは**記事の控え**（`data/articles.json`）。記事を書き出すたびに
「どの指示で作ったか」が記録されるが、2026-09-02 より前の記事は入っていない。
`--refresh` に出てこない記事があれば、一度だけ手で登録する。

```
npm run write -- --register --type series --slug <スラッグ> --topic "<主題>" --match "<正規表現>"
```

**`--topic` と `--match` は人が決めた値で、記事のどこにも残っていない。**
登録のあとに出る素材件数が記事の本数と合っているかを必ず確かめる（0件なら `--match` が違う）。

> ★ **コマンドは1行で書くこと。** 行末の `\` は PowerShell では次の行に続かず、
> 2行目以降のフラグが落ちたまま実行される。

## 報告

- 書き直した記事（スラッグ）と、**何が変わったか**（カテゴリの移動・状態の列・本数）
- **前の版から残した箇所と、変えた箇所**（解説を書き直していないこと）
- 品質ゲートで警告が出た場合はその内容と、直したか直さなかったかの理由
- `heroImage` が frontmatter に戻っているか（手順5）
- まだ残っている書き直しどきの記事があれば、その本数

コミットとpushは**勝手に行わない**。ユーザーの判断を仰ぐ。
