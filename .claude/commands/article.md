収集済みデータから記事を1本書く。**LLM APIは使わず、このセッションで執筆する**（課金の節約が目的）。

## 手順

### 1. プロンプトを書き出す

```
npm run write -- --emit${ARGUMENTS:+ --type $ARGUMENTS}
```

素材が0件なら「先に `npm run collect` を実行してください」と伝えて終了する。

### 2. 指示と素材を読む

`data/draft/prompt.md` を読む。以下が入っている。

- 記事の構成・文体・禁止事項（テーマパックのテンプレート）
- 出力形式の指定
- 素材データ（作品名・終了日・サービス・評価・ジャンル・あらすじ・検索リンク）

### 3. 記事を書く

**`data/draft/response.md` に保存する。** 形式は厳密に守る。

```
TITLE: （30〜60文字）
DESCRIPTION: （60〜120文字・1行）
---BODY---
（Markdown本文。見出しは ## から）
```

frontmatter は書かない。日付・出典・カテゴリはパイプラインが機械的に組み立てる。

**執筆時に必ず守ること**（品質ゲートで機械的に検査される）:

- 本文は**2,000字以上**（空白を除いた実質文字数）
- **「★邦題が未確認」と書かれた作品は、与えられた原題をそのまま使う。**
  日本語タイトルを推測して書かない
- 与えられた終了日**以外の日付を書かない**。与えられていない作品を追加しない
- prompt.md の「今月そのまま使う固定文言」を**一字一句そのまま**使う
  （リードの1文目・リードの締め・「他のサービスで探す」の冒頭・末尾の提供元表記）
- U-NEXT / Hulu / DMM TV について「配信中」と**断定しない**（配信状況のデータを持っていない）

**警告として指摘される**（公開は止まらないが、直せるなら直す）:

- 日付ごとの `##` セクションの最終段落が「〜しましょう」等で終わっていない
  （ただし段落自体が「どれから観るべきか」の助言になっていれば、そのままでよい）
- 半角の `!` `?` `(` `)` が混ざっている。記号は全角に統一する

**この記事の価値の核**は、終了日を見比べて**意味のあるまとまりを見つける**こと。
同一監督・同一シリーズ・同一ジャンルが同じ日に集中していれば、それを記事の軸にする。
まとまりが無い月は無理に作らず、有名作・人気作や近年に続編が出た作品を優先して並べる。

リードの2段落目と `##` 見出しには、**具体的な作品名・シリーズ名を入れる**。
記事の構造の説明（「終了日が特定の日に固まっているのが特徴です」等）は書かない。

### 4. 検証して書き出す

```
npm run write -- --apply
```

品質ゲートで弾かれたら、指摘された箇所を `data/draft/response.md` で直して再実行する。

### 5. サイトのビルドを確認

```
cd site && npm run build
```

frontmatter のスキーマ検証もここで走る。通ればサイトに反映できる状態。

## 報告

- 記事タイトルと本文の文字数
- 見つけた「まとまり」（この記事の独自性がどこにあるか）
- 品質ゲートで警告が出た場合はその内容

生成した記事のコミットとpushは**勝手に行わない**。ユーザーの判断を仰ぐ。
